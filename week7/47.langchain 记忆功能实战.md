# 47. LangChain 记忆功能实战

Day 46 讲了记忆如何进入上下文：何时检索、如何过滤、放在哪、以什么形式，以及注入失败的常见原因。本节用 **LangChain** 把“记忆”落到代码里：先了解**内置 Memory 类型**（Buffer、BufferWindow、Summary 等），再**基于对话构造简单的个性化记忆**（如用户偏好）并在后续轮次中使用。

目标：

1. **认识 LangChain 的几种 Memory**：各自存什么、何时用、和 Day 44 的短期/长期记忆如何对应。
2. **动手跑通一个带“用户偏好”的多轮对话**：从用户话里抽取偏好、写入“记忆”、在下一轮的 System 或 Context 里注入，让回复体现个性化。

环境要求：`langchain-core`、`langchain-openai`（或其它兼容的 Chat 模型）、`python-dotenv`。项目 `pyproject.toml` 已包含这些依赖。**LangChain 1.0+** 推荐用 **LangGraph** 管理对话状态；本节为兼容 1.0+ 且不依赖已弃用的 `langchain_community.memory`，采用与 Day 41 一致的**手动消息列表 + 时间窗口**实现对话历史，概念上等价于 BufferWindow。

## 一、LangChain 中的“记忆”概念（Buffer、BufferWindow、Summary）

在 LangChain 里，**Memory** 曾指在多次调用之间保存和加载“历史信息”的组件；链在每次调用前从 Memory **加载**变量（如对话历史），拼进 prompt，调用后再**保存**本轮。**LangChain 1.0+** 中，传统的 `ConversationBufferMemory`、`ConversationBufferWindowMemory`、`ConversationSummaryMemory` 等仍在 `langchain_community.memory` 中保留，但官方推荐新项目使用 **LangGraph** 的 state + checkpointer 管理短期/长期记忆。下面用**概念表**说明几种类型，实战代码则用**手动列表 + 窗口**实现，与 Day 41 一致、无需 `langchain_community`。

### 1. Buffer：全量缓冲

- **含义**：把**所有**历史轮次的 Human/AI 消息都存下来，不丢、不截断。
- **特点**：实现简单、信息最全；但对话一长就会占满 Context 或超 token 上限。
- **适用**：轮数很少的短对话；或你在链外自己做裁剪/摘要时，用列表保存全量再按需截取。

### 2. BufferWindow：滑动窗口（本节实现方式）

- **含义**：只保留**最近 K 轮**对话（每轮一条 Human + 一条 AI），更早的自动丢弃。
- **特点**：与 Day 38、41 的“时间窗口”一致；token 受控，适合多数多轮场景。
- **实现**：用列表保存 `HumanMessage` / `AIMessage`，每轮追加；拼 Context 时取 `history[-(2*k):]` 即可，无需 `ConversationBufferWindowMemory`。

```python
from langchain_core.messages import HumanMessage, AIMessage

history: list = []

def keep_last_k_turns(history: list, k: int) -> list:
    """只保留最近 k 轮（每轮 2 条：user + assistant）。"""
    if k <= 0:
        return []
    return history[-(2 * k) :] if len(history) >= 2 * k else history

# 每轮结束后
history.append(HumanMessage(content=user_input))
history.append(AIMessage(content=resp.content))
# 拼 Context 时
window = keep_last_k_turns(history, k=3)
messages = [SystemMessage(...)] + window + [HumanMessage(content=当前输入)]
```

### 3. Summary：用摘要代替原文

- **含义**：不存完整原文，用 **LLM 对历史做摘要**，加载时把摘要（加可选最近几轮原文）注入。
- **特点**：长对话省 token，但摘要会丢细节，且多一次 LLM 调用。
- **适用**：轮数很多、又要保留“背景梗概”时使用；1.0+ 下可用 LangGraph 的 summarization middleware 或自建摘要逻辑。

### 4. 小结：类型与 Day 44 的对应关系

| 概念 / 原 Memory 类型            | 存什么         | 对应 Day 44  | 典型用途          |
| --------------------------- | ----------- | ---------- | ------------- |
| **Buffer**                  | 全量对话原文      | 短期记忆（不裁剪）  | 短对话或自管裁剪      |
| **BufferWindow**（本节实现）      | 最近 K 轮原文    | 短期记忆（时间窗口） | 多轮对话、控制 token |
| **Summary / SummaryBuffer** | 摘要 + 可选最近原文 | 短期压缩为“摘要”  | 长对话、要梗概       |

以上都是**对话历史**维度的记忆；若要实现“用户偏好、关键事实”等**长期/用户级记忆**，需自己维护（如列表或键值表），在每轮拼 Context 时注入——下一节就做这件事。

## 二、基于对话构造简单的个性化记忆（如用户偏好）并在后续轮次中使用

“个性化记忆”这里指：从对话里**抽出**用户明确说的偏好或事实（如“用英文回复”“我喜欢简洁”），**存下来**，在**后续每一轮**拼 Context 时**注入**到 System 或参考块里，让模型遵守。

### 1. 思路

- **对话历史**：用**手动消息列表** + **keep_last_k_turns**（最近 K 轮）即可，与 Day 41 一致，保证本会话内连贯。
- **用户偏好**：单独维护一个结构（如 `list[str]`），在**每轮用户输入之后**判断是否包含“偏好类”表达；若是，则**追加**到该结构。在**每轮拼 messages 时**，把当前偏好列表写成一段话（如“用户偏好：英文回复；喜欢简洁。”）放进 **System** 或紧跟 System 的第一条内容里。

这样既实现了“历史窗口”记忆，又用自建的“偏好记忆”在后续轮次中生效。

### 2. 何时“记”一条偏好（写入策略）

从简起见，可以用**规则**触发写入，例如：

- 用户说 **“记住：……”** 或 **“请记住……”**：把省略号里的内容当作一条偏好保存。
- 用户说 **“我偏好……”**、**“我喜欢……”**、**“以后请……”**：同样截取后半句作为一条偏好（可再做一次 LLM 抽取或正则）。

写入时做**去重或覆盖**：若新偏好和已有某条语义相同（如“用英文”和“请用英文回复”），可覆盖或合并，避免列表无限增长（对应 Day 45 的“克制地记忆”）。

### 3. 在后续轮次中如何使用

每一轮调用 LLM 前：

1. 用 **keep_last_k_turns(history, K)** 得到最近 K 轮历史消息。
2. 读取当前 **用户偏好列表**，拼成字符串，例如：`"用户偏好：偏好1；偏好2。"`，若为空则不加。
3. 组装 **System Prompt**：`base_system + "\n\n" + 用户偏好字符串`（若有）。
4. 组装 **messages**：`[SystemMessage(...)] + 窗口历史 + [HumanMessage(当前用户输入)]`。
5. 调用 LLM，得到回复后：**将本轮 HumanMessage、AIMessage 追加到 history**，并**根据本轮用户输入判断是否新增/更新偏好**。

这样后续每一轮模型都能在 System 里“看到”当前偏好，回复就会体现个性化。

### 4. 完整可运行示例

下面脚本演示：**手动消息列表保留最近 3 轮**（等价 BufferWindow）+ **一个列表存“用户偏好”**；用户输入若包含 `记住：XXX` 或 `我偏好 XXX`，就把 XXX 加入偏好列表；每轮把偏好注入 System，再拼历史与当前问题调用 LLM。仅依赖 `langchain_core`、`langchain_openai`，兼容 **LangChain 1.0+**。

完整代码已放在 **`week7/47_code/langchain_memory_demo.py`**，可在项目根目录执行：

```bash
python week7/47_code/langchain_memory_demo.py
```

**核心逻辑示意：**

```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage
from langchain_openai import ChatOpenAI
import re

llm = ChatOpenAI(model="qwen-plus", base_url="https://dashscope.aliyuncs.com/compatible-mode/v1")
history: list = []  # 对话历史（HumanMessage / AIMessage）
user_preferences: list[str] = []
K = 3

BASE_SYSTEM = "你是贴心助手。请遵守【用户偏好】中的要求（若有）。"

def keep_last_k_turns(history: list, k: int) -> list:
    if k <= 0:
        return []
    return history[-(2 * k) :] if len(history) >= 2 * k else history

def extract_preference(user_input: str) -> str | None:
    m = re.search(r"记住[：:]\s*(.+)", user_input)
    if m:
        return m.group(1).strip()
    m = re.search(r"我偏好\s*(.+)", user_input)
    if m:
        return m.group(1).strip()
    return None

def build_messages(user_input: str) -> list:
    pref_block = "用户偏好：" + "；".join(user_preferences) if user_preferences else ""
    system_content = BASE_SYSTEM + ("\n\n【用户偏好】\n" + pref_block if pref_block else "")
    window = keep_last_k_turns(history, K)
    return (
        [SystemMessage(content=system_content)]
        + window
        + [HumanMessage(content=user_input)]
    )

# 主循环示意
while True:
    user_input = input("你: ").strip()
    if user_input.lower() in ("quit", "exit", "q"):
        break
    pref = extract_preference(user_input)
    if pref:
        user_preferences.append(pref)
        print(f"[已记住偏好：{pref}]\n")
    messages = build_messages(user_input)
    resp = llm.invoke(messages)
    history.append(HumanMessage(content=user_input))
    history.append(AIMessage(content=resp.content))
    print("助手:", resp.content, "\n")
```

**使用方式：**

- 先正常聊几句，再输入 **“记住：请用简洁的一两句话回答”**，下一轮起 System Prompt里会带这条偏好，助手应更简洁。
- 或输入 **“我偏好 英文回复”**，后续回复会倾向英文（若模型遵守 System Prompt里的偏好说明）。
- 输入 `quit` 退出。当前示例偏好与 `history` 均在进程内，重启即清空；若要跨会话持久化，需把 `user_preferences` 与历史写入数据库或文件，并按 user_id 区分（见 Day 44、46）。
