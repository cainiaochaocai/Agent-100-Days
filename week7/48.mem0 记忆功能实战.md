# 48. mem0 记忆功能实战

Day 47 用 LangChain 做了对话历史（BufferWindow）和自建的“用户偏好”列表。本节换一种方案：用 **mem0** 实现**记忆的写入、检索与更新**，并对比 **LangChain 内置 Memory** 与 **mem0** 的适用场景。

mem0 是面向 AI Agent 的**通用记忆层**：支持按 user_id / agent_id / run_id 组织记忆、用 LLM 从对话中**推断**结构化记忆、向量检索与更新/删除，适合“长期、跨会话、可检索”的个性化记忆。本节的示例基于 **mem0 开源 Python SDK**（`pip install mem0ai`），需配置 `OPENAI_API_KEY`（用于推理与向量嵌入）。

## 一、mem0 简介与安装

### 1. 是什么

- **mem0**（mem-zero）：为 AI 助手/Agent 提供“记忆层”的开源库与托管服务。核心能力包括：
  - **从对话中推断记忆**：传入若干轮 user/assistant 消息，mem0 用 LLM 抽取“值得记住”的事实与偏好并写入存储。
  - **向量存储与语义检索**：记忆向量化后可按 query 做 **search**，取回与当前问题最相关的记忆，再注入 Context。
  - **按主体组织**：支持 `user_id`、`agent_id`、`run_id`（及 metadata），便于多用户、多会话、多 Agent 隔离。
  - **更新与删除**：单条 `update`、按 id `delete`、按 user `delete_all` 等，对应 Day 45 的覆盖与“忘记”。

### 2. 安装与初始化

```bash
pip install mem0ai
```

```python
import os
from mem0 import Memory

os.environ["OPENAI_API_KEY"] = "your-api-key"  # 或从 .env 加载
m = Memory()
```

默认使用内存型向量存储；生产可改为 Qdrant、PG 等，通过 `Memory.from_config(config)` 配置（见 [mem0 文档](https://docs.mem0.ai)）。

## 二、记忆写入（add）

mem0 的写入入口是 **`add`**，支持两种方式：

### 1. 用对话消息推断记忆（推荐）

传入多轮 `messages`（`role` + `content`），mem0 会用内置 LLM **从对话中推断**“该记什么”（事实、偏好、事件等），并写入多条记忆。适合“边聊边记”、无需自己写抽取规则。

```python
messages = [
    {"role": "user", "content": "我打算今晚看场电影，有推荐吗？"},
    {"role": "assistant", "content": "惊悚片怎么样？很刺激。"},
    {"role": "user", "content": "我不太喜欢惊悚，更喜欢科幻片。"},
    {"role": "assistant", "content": "好的，以后给你推荐科幻片。"},
]
result = m.add(messages, user_id="alice", metadata={"category": "movie"})
# result["results"] 为本次写入的记忆列表，每项含 id、memory、event 等
```

可同时传入 `agent_id`、`run_id` 做更细粒度隔离；`metadata` 便于后续按类别筛选或展示。

### 2. 直接写入字符串（不推断）

若你已经在业务里抽好了“一条记忆”（如“用户偏好：英文回复”），可直接传字符串，并设 **`infer=False`**，按原文存储，不做 LLM 推断。

```python
m.add("用户偏好使用英文回复。", user_id="alice", infer=False)
```

## 三、记忆检索（search / get_all / get）

### 1. 语义检索：search

按**当前问题或意图**做语义检索，取回与 query 最相关的若干条记忆，用于注入本轮 Context。这是“什么时候去翻记忆”（Day 46）的典型实现。

```python
related = m.search(query="用户喜欢看什么类型的电影？", user_id="alice", limit=5)
# related["results"] 为列表，每项含 id、memory、score、metadata 等
memories_str = "\n".join(r["memory"] for r in related["results"])
```

可将 `memories_str` 放进 System 或参考块，再拼上当前用户输入，调用 LLM。

### 2. 全量获取：get_all

不需要按 query 筛选、只要“该用户/该会话下的所有记忆”时，用 **get_all**。

```python
all_memories = m.get_all(user_id="alice")
# 可加 agent_id、run_id 缩小范围
# all_memories["results"] 为记忆列表
```

适合“用户画像”一次性加载、或管理端展示。

### 3. 单条获取：get

已知记忆 id 时，用 **get** 取单条内容（如更新前先读、或做冲突判断）。

```python
one = m.get(memory_id="892db2ae-06d9-49e5-8b3e-585ef9b85b8e")
```

## 四、记忆更新与删除（update / delete）

### 1. 更新：update

某条记忆内容需要**覆盖**（用户改口、纠错）时，用 **update** 按 id 替换内容，对应 Day 45 的“同一槽位覆盖”。

```python
m.update(memory_id="892db2ae-06d9-49e5-8b3e-585ef9b85b8e", data="用户最喜欢科幻片，尤其是星际穿越这类。")
```

### 2. 删除：delete / delete_all

- **delete(memory_id="...")**：删单条。
- **delete_all(user_id="alice")**：删该用户下全部记忆（如用户请求“清除我的记忆”、或合规要求）。

对应 Day 45 的“忘记是能力的一部分”。

### 3. 清空（开发/测试）：reset

```python
m.reset()  # 清空所有记忆，慎用于生产
```

## 五、完整流程：对话中写入 → 检索注入 → 回复后再写入

与 Day 47 类似，把“记忆”嵌进多轮对话的每一轮：

1. **用户输入后**：用当前 **query** 调用 **m.search(query=..., user_id=..., limit=K)**，得到相关记忆列表。
2. **拼 Context**：把检索到的记忆拼成一段（如“用户记忆：\n- 记忆 1\n- 记忆 2”），放进 **System Prompt** 或紧跟 System Prompt的参考块；再拼对话历史（可用 LangChain BufferWindow 或自维护）和当前用户输入。
3. **调用 LLM** 得到助手回复。
4. **本轮到记忆**：把本轮 **[user, assistant]**（或最近几轮）传给 **m.add(messages, user_id=...)**，让 mem0 推断并写入新记忆；下一轮 search 时就有机会被检索到。

这样既做到“按问题检索相关记忆”，又做到“聊完就记、跨会话可用”。完整可运行示例见 **`week7/48_code/mem0_memory_demo.py`**（需先 `pip install mem0ai`，并配置 `OPENAI_API_KEY`）。

**核心逻辑示意：**

```python
from mem0 import Memory
from openai import OpenAI

m = Memory()
client = OpenAI()

def chat_with_memories(message: str, user_id: str = "default_user") -> str:
    # 1. 检索相关记忆
    related = m.search(query=message, user_id=user_id, limit=3)
    memories_str = "\n".join(f"- {r['memory']}" for r in related.get("results", []))
    # 2. 拼 System Prompt + 用户输入，调 LLM
    system = f"你是贴心助手。根据以下用户记忆回答：\n{memories_str}" if memories_str else "你是贴心助手。"
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "system", "content": system}, {"role": "user", "content": message}],
    )
    assistant_content = resp.choices[0].message.content
    # 3. 本轮到记忆
    m.add(
        [{"role": "user", "content": message}, {"role": "assistant", "content": assistant_content}],
        user_id=user_id,
    )
    return assistant_content
```

## 六、LangChain 内置 Memory 与 mem0 的适用场景对比

| 维度        | LangChain 内置 Memory（Buffer / BufferWindow / Summary） | mem0                                                        |
| --------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| **主要用途**  | 对话**历史**的保存与加载（最近 K 轮或摘要），保证本会话内连贯                   | **长期、可检索**的记忆：事实、偏好、跨会话信息                                   |
| **存储形态**  | 进程内或随链绑定，多为“消息列表”或“摘要字符串”                            | 向量存储 + 可选图/关系，支持按 user/agent/run 隔离                         |
| **写入方式**  | 每轮 `save_context(input, output)`，无“推断”               | `add(messages)` 由 LLM 推断多条记忆，或 `add(text, infer=False)` 直接存 |
| **检索方式**  | 通常“全量或滑动窗口”加载，不做语义检索                                 | **search(query)** 语义检索 Top-K，适合“按问题找相关记忆”                   |
| **更新/删除** | 无单条更新；窗口型自动丢旧轮                                       | **update(id, data)**、**delete(id)**、**delete_all(user_id)** |
| **适用场景**  | 单会话多轮对话、Context 内历史窗口、与 LangChain 链深度集成              | 跨会话个性化、用户画像、需“记什么/忘什么”的精细控制                                 |
| **依赖**    | langchain + LLM（Summary 型）                           | mem0ai + LLM + 向量存储（默认内存，可换 Qdrant 等）                       |

**简单取舍**：

- 若你主要需要“**当前会话里最近几轮对话**”且已用 LangChain 组链 → 用 **ConversationBufferWindowMemory**（或 Summary）即可。
- 若你需要“**跨会话记住用户是谁、喜欢什么、说过什么关键事实**”，并希望**按问题检索相关记忆再注入** → 用 **mem0**（或类似向量记忆层）更合适。
- 实践中可以**同时用**：LangChain 管“本会话历史”，mem0 管“长期用户记忆”；每轮先 search mem0 得到记忆块，再和 BufferWindow 的历史一起拼进 Context。

## 小结

| 学习点                        | 要点                                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------------------- |
| **mem0 记忆写入**              | `add(messages, user_id=..., metadata=...)` 由 LLM 推断多条记忆；`add(text, user_id=..., infer=False)` 直接存字符串。 |
| **mem0 记忆检索**              | `search(query, user_id=..., limit=K)` 语义检索；`get_all(user_id=...)` 全量；`get(memory_id)` 单条。             |
| **mem0 记忆更新与删除**           | `update(memory_id, data)` 覆盖单条；`delete(memory_id)` / `delete_all(user_id)` 删除；`reset()` 清空。           |
| **与 LangChain Memory 的对比** | LangChain 侧重对话历史（窗口/摘要），mem0 侧重长期、可检索、可更新的用户/会话记忆；二者可组合使用。                                            |
