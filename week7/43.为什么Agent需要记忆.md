# 43. 为什么 Agent 需要记忆

Week 6 我们学了**上下文工程**：在一次调用里塞进 System Prompt、历史、参考内容、当前问题，并控制长度与顺序。但上下文有一个根本限制——**它只存在于“这一轮”的请求里**，请求结束就没了；下一轮、下一次会话，模型不会自动“记得”之前发生过什么。要让 Agent 在跨轮、跨会话中保持连贯、甚至让用户感到“它认识我”，就需要**记忆系统（Memory）**。本节先搞清楚：**Context 的上限与不可持续性**、**没有记忆的 Agent 能做到什么、做不到什么**、以及**记忆带来的行为一致性与“人格感”**。

## 一、Context 的上限与不可持续性

### 1. 每次调用都是“重新开机”

在 Day 36 已经明确：**Context = 一次 LLM 调用的全部可见输入**。模型不会在两次请求之间保留任何状态；你不在本次请求里显式放进来的内容，模型就“看不到”。所以：

- **跨轮**：同一会话里，你可以把历史消息拼进 Context，模型就能“看到”之前几轮——这是**上下文**在起作用，不是模型自己有记忆。
- **跨会话**：用户关掉页面、第二天再来，若你不把“上次聊过什么、用户是谁、偏好是什么”再次放进 Context，模型对这一切一无所知。

换句话说：**上下文是“这一轮”的输入快照，不是持久化的记忆。**

### 2. Token 窗口的硬约束

即使你想“把之前所有对话都塞进 Context”，也会遇到 **Token Window** 上限（如 8K、32K、128K）。对话一长，要么截断最早的内容，要么做摘要/裁剪；**更早的细节、用户很久以前说过的偏好，很容易被挤掉或压成一句话**。所以：

- **上下文**适合承载“当前会话内、最近若干轮”的信息；
- **跨会话、长期、高价值的事实与偏好**，更适合交给**记忆系统**存储，在需要时再**检索并注入**到 Context 里。

### 3. 小结：为什么光靠 Context 不够

| 维度      | 仅靠 Context 的情况                | 引入记忆后的情况                     |
| ------- | ----------------------------- | ---------------------------- |
| **跨会话** | 新会话 = 全新开始，模型不知道用户是谁、之前聊过什么   | 可存用户 ID、历史摘要、偏好；新会话时检索并注入    |
| **长对话** | 历史受 token 限制，要么截断要么压缩，早期细节丢失  | 重要信息写入记忆，需要时按相关性取出，不依赖“全量历史” |
| **个性化** | 若不在本次 Context 里写“用户偏好”，模型无法遵守 | 记忆里存偏好，每次调用前检索并注入 提示词 或参考内容  |

所以：**Context 解决的是“这一轮让模型看到什么”；记忆解决的是“跨轮数、跨会话，哪些信息要被保留并在合适的时候再次被看到”。** 二者配合，Agent 才能既在单次调用里信息充足，又在长期里保持连贯。

## 二、没有记忆的 Agent 的能力边界

在**不引入记忆系统**的前提下，Agent 能做到什么、做不到什么，可以这样划一条线。

### 1. 能做到的（依赖“上下文”即可）

- **单会话内的多轮对话**：把历史消息拼进 Context，模型能接上指代、延续话题。只要不换会话、不超 token，体验可以很好。
- **单次请求内的 RAG/工具**：在本拍里注入检索结果、工具返回值，模型能基于这些回答。不要求“记住”这些结果，下次再查即可。
- **无状态的单次任务**：例如翻译一段话、写一封邮件、查一次天气，不依赖“用户是谁、上次做了什么”，无需记忆。

这类场景下，**没有记忆的 Agent 已经够用**；记忆是加分项，不是必选项。

### 2. 做不到或做不好的（需要记忆）

- **跨会话的连贯**：用户上周说“我偏好简洁回答”，本周再来，若没有记忆，模型无从知道，又会给长答案。
- **用户级个性化**：不同用户有不同的偏好、权限、历史；若不在某处持久化“这个用户是谁、他喜欢什么”，每次会话都像第一次见面。
- **长期事实与约定**：例如“用户要求不要提某竞品”“用户已同意某条款”，若只靠上下文，换会话或历史被裁掉后就失效。
- **任务与状态的延续**：例如“上次做到第三步，这次继续第四步”，若没有对“任务进度”的存储与检索，Agent 难以无缝续写。

所以：**“记不住”的 Agent，能力边界就是“单会话 + 本拍内的信息”；一旦涉及跨会话、长期、个性化，就需要记忆系统补上。**

## 三、记忆带来的行为一致性与“人格感”

引入记忆之后，Agent 不再每次都是“空白状态”，而是可以**基于过去与当前**做决策，从而带来两种可感知的变化。

### 1. 行为一致性

- **同一用户在不同会话里**：例如用户说过“用英文回复”，记忆里存下这条偏好后，后续每次会话都可以在 提示词 或参考内容里注入“该用户偏好英文”，模型就会持续用英文回答，而不会这次英文、下次又变中文。
- **同一任务跨多轮**：例如订机票，上次已选好日期和舱位，记忆里存下“待完成：付款”，下次用户说“继续”，Agent 检索到这条再接着流程走，行为连贯、不重复问。

这种**在不同时间点、不同请求里表现一致**的能力，依赖的正是“把关键信息写入记忆、在需要时再取出并注入 Context”。

### 2. “人格感”与信任

- 用户说“我不吃辣”，下次推荐餐厅时 Agent 自动排除川菜馆，用户会感到**它记住了我**。
- 用户多次提到某项目名称，Agent 在后续对话里自然用该名称称呼，而不是再次问“您说的是哪个项目？”——这种**延续感**会让人更愿意把 Agent 当成一个稳定的对话对象，而不是每次都要重新解释一遍的陌生人。

所以记忆不仅解决“信息不丢”，也直接影响到**体验上的连贯与可信**；这是“没有记忆的 Agent”很难给到的。

## 小结

| 学习点                   | 要点                                                                              |
| --------------------- | ------------------------------------------------------------------------------- |
| **Context 的上限与不可持续性** | Context 只存在于单次调用，请求结束即消失；且受 token 窗口限制，无法无限制保留“全部历史”。跨会话、长期、个性化信息需要持久化存储，即记忆系统。 |
| **没有记忆的 Agent 的能力边界** | 能做好：单会话多轮对话、单次 RAG/工具、无状态单次任务。做不好：跨会话连贯、用户级个性化、长期事实与约定、任务状态延续。                  |
| **记忆带来的行为一致性与“人格感”**  | 记忆使 Agent 能在不同会话、不同请求中表现一致（如持续遵守用户偏好）；并让用户感到“它认识我”，提升信任与使用意愿。                   |
