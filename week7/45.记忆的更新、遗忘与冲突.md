# 45. 记忆的更新、遗忘与冲突

Day 44 讲了记忆的分类与写入策略：记什么、记多少、克制地记。但记忆一旦写入，还会面临**如何更新**（覆盖还是追加）、**如何随时间淡化**（遗忘曲线）、**多条记忆互相矛盾时怎么办**（冲突处理），以及**为什么要主动“忘记”**。本节围绕这四点展开：**记忆覆盖 vs 追加**、**时间衰减与遗忘曲线**、**冲突记忆的处理**、**“忘记”是能力的一部分**。

## 一、记忆覆盖 vs 追加：何时替换、何时累积

同一条“槽位”上的信息，是**用新内容替换旧内容**（覆盖），还是**在原有基础上增加新内容**（追加），取决于信息类型与业务语义。

### 1. 适合覆盖（Replace）的情况

- **同一语义槽位的更新**：例如用户先说“我偏好英文回复”，后来说“改成中文吧”——应**覆盖**“语言偏好”这条记忆，而不是再追加一条“偏好中文”，否则检索到两条会冲突。
- **任务态势的当前状态**：例如“当前步骤：第三步”“待支付订单：ORD-001”；步骤推进、订单变化时，用新状态**覆盖**旧状态，保持“当前只有一个最新状态”。
- **用户显式更正**：用户说“刚才说错了，我其实是 X”——对 X 的陈述应覆盖之前记下的错误信息。

原则：**当新信息与旧信息描述的是“同一件事”、且新信息代表“当前正确版本”时，用覆盖。**

### 2. 适合追加（Append / 累积）的情况

- **同一主题的多条独立事实**：例如用户先后提到“喜欢跑步”“喜欢读书”“不喜欢熬夜”——是**多条偏好**，应**追加**多条记忆，而不是用最后一句覆盖前面所有。
- **历史事件或会话摘要**：每次会话结束写一条摘要，不同会话的摘要是不同时间点的记录，应**追加**保存，便于按时间线或按会话检索。
- **任务历史/操作日志**：若需要保留“做过哪些步骤”的完整轨迹，每完成一步**追加**一条，而不是只保留“当前步骤”一条。

原则：**当新信息与旧信息是“不同事件、不同方面、或需要保留时间线”时，用追加。**

### 3. 小结表

| 场景             | 建议策略   | 说明               |
| -------------- | ------ | ---------------- |
| 用户更新同一项偏好/事实   | **覆盖** | 同一语义槽位，以最新为准     |
| 任务/会话的“当前状态”   | **覆盖** | 只保留一个最新状态，避免歧义   |
| 用户显式更正之前说过的话   | **覆盖** | 新信息替代错误信息        |
| 同一主体的多条独立偏好/事实 | **追加** | 多条记忆并存，检索时可能都用到  |
| 多会话的摘要或历史记录    | **追加** | 保留时间线，便于按会话/时间筛选 |
| 需要完整轨迹的任务日志    | **追加** | 每步一条，不覆盖         |

实际实现时，可对“槽位”建模：例如用户画像里“语言偏好”是一个槽位，新值写入即覆盖；而“兴趣标签”是列表，新兴趣则追加。

## 二、时间衰减与“遗忘曲线”：记忆随时间如何自然“淡化”

人的记忆会随时间变模糊、不常用的会淡忘。Agent 的记忆也可以引入**时间衰减**：不是立刻删除，而是让“越旧、越久未使用”的记忆在检索或排序时**权重降低**，从而自然“淡化”。

### 1. 为什么需要时间衰减

- **信息过期**：用户一年前说“我在北京”，现在可能已搬家；很久以前的偏好可能已改变。
- **控制检索噪音**：若所有记忆一视同仁，旧的不重要信息会和新信息一起被检索出来，占用 Context、稀释重点。
- **存储与性能**：配合“低权重或超旧记忆可归档/删除”的策略，避免无限增长。

### 2. 常见做法：遗忘曲线与衰减因子

- **按时间衰减**：每条记忆带 `created_at` 或 `last_used_at`；检索或排序时，越久远则分数乘以一个**衰减因子**（例如指数衰减：`score * e^(-λ * t)`，t 为距今天数，λ 为衰减率）。这样“最近写入/最近用到的”会排在前面，“很久以前的”仍可被检索到但权重较低。
- **按使用频率**：若记录“被检索到的次数”或“最近一次被检索时间”，可对“长期未被使用”的记忆降权或标记为可清理——类似“不用就忘”。
- **分层策略**：例如“用户明确声明的偏好”衰减慢甚至不衰减；“会话摘要”随时间较快衰减； “临时任务状态”会话结束即可清理。不同类型用不同 λ 或不同生命周期。

不一定要做成“到期就删”；**在检索阶段用时间衰减调权**，就能让旧记忆自然“淡化”，在 Context 有限时优先让模型看到更新的、更相关的记忆。

### 3. 小结

| 思路        | 做法                          |
| --------- | --------------------------- |
| **时间衰减**  | 记忆带时间戳，检索/排序时按距今时间降权（如指数衰减） |
| **使用频率**  | 按“最近是否被检索/使用”降权或清理长期未用记忆    |
| **按类型分层** | 偏好类衰减慢，摘要/临时类衰减快或短生命周期      |

## 三、冲突记忆如何处理：最新为准 / 来源优先级 / 置信度加权

多条记忆在语义上**互相矛盾**时（例如一条说“偏好英文”、一条说“偏好中文”），若都注入 Context，模型可能困惑或随机选一边。需要在**写入时或检索时**处理冲突。

### 1. 最新为准（Last-Write-Wins）

- **做法**：同一“槽位”或同一主题只保留**最新一条**；新写入时覆盖旧（见第一节）。检索时若按槽位去重，自然就不会返回冲突的多条。
- **适用**：用户偏好、当前状态、可被“更正”的事实。实现简单，语义清晰。
- **注意**：要能识别“同一槽位”（例如用 key/type 或 embedding 相似度），否则会变成多条独立记忆而非覆盖。

### 2. 来源优先级（Source Priority）

- **做法**：不同来源的记忆赋予不同优先级；冲突时**高优先级覆盖或压制低优先级**。例如：用户显式说的 > 模型推断的；本会话的 > 历史会话的。
- **适用**：既有“用户原话”又有“模型总结”时，优先信任用户原话；或多源记忆（如从 CRM 同步的 vs 对话中抽取的）需要定一个优先级顺序。
- **实现**：每条记忆带 `source` 或 `priority` 字段，检索后若发现冲突，只保留或优先展示高优先级的一条（或在前端/注入时做合并规则）。

### 3. 置信度加权（Confidence / 可信度）

- **做法**：每条记忆带一个**置信度或权重**（例如 0~1）；冲突时取高置信度，或把多条都注入但标注“存在冲突，以高置信度为准”。也可在检索排序时直接用置信度参与打分。
- **适用**：记忆来自模型抽取、有多条候选时；或来自不同渠道（用户说的 vs 行为推断的），可信度不同。置信度可由规则给出（如“用户原话=1.0，模型推断=0.7”），也可由模型或反馈学习得到。
- **与时间衰减结合**：置信度 × 时间衰减因子，得到最终权重，既考虑“谁说的”，也考虑“多久以前”。

### 4. 小结表

| 策略        | 做法                | 适用场景            |
| --------- | ----------------- | --------------- |
| **最新为准**  | 同槽位只保留最新一条，新写覆盖旧  | 偏好、状态、可更正事实     |
| **来源优先级** | 冲突时高优先级来源压制低优先级   | 多源记忆、用户原话 vs 推断 |
| **置信度加权** | 记忆带置信度，冲突时取高或参与排序 | 模型抽取、多候选、需软判断   |

实践中可组合：例如**先按槽位 + 最新为准**减少冲突条数，再对仍可能冲突的条用**来源优先级或置信度**决定最终展示/注入顺序。

## 四、为什么“忘记”是能力的一部分：防止污染、保持系统健壮

记忆系统不仅要“记得”，还要**能忘**。主动的遗忘与淘汰，是防止污染、控制规模、保持系统可维护的关键。

### 1. 防止污染

- **错误与噪音**：错误写入的记忆（例如模型误抽、用户口误后被记下）若永远不删，会持续被检索出来，污染后续回答。通过**覆盖、衰减、或用户反馈后删除**，可以减轻污染。
- **过时信息**：旧事实、旧偏好若一直和新信息同等权重，会误导模型。**时间衰减 + 定期清理/归档**相当于“忘掉过时的”，让行为更贴近当前真实状态。
- **敏感与合规**：用户要求“删除我的某条信息”或合规要求保留期限，**主动删除或过期清理**是必须能力，也属于“忘记”。

### 2. 保持系统健壮

- **存储与性能**：记忆无限增长会导致存储与检索成本上升、延迟变高。**按条数上限、按时间/重要性淘汰**，相当于“忘掉不重要的”，系统才能长期稳定。
- **检索质量**：Context 有限，若注入太多低价值记忆，高价值信息被挤占。**遗忘**使检索结果更聚焦，模型看到的更少更准，行为更稳定。
- **可解释与可维护**：保留“当前有用”的记忆、清理或归档陈年旧账，便于排查问题、理解 Agent 当前“记得什么”，也便于做数据迁移与备份策略。

### 3. 小结

> **“忘记”不是缺陷，而是设计的一部分。** 通过覆盖、时间衰减、冲突处理、条数/时间淘汰与合规删除，记忆系统才能既发挥“跨会话连贯与个性化”的作用，又避免被噪音和过时信息拖垮。

## 小结

| 学习点             | 要点                                                                |
| --------------- | ----------------------------------------------------------------- |
| **记忆覆盖 vs 追加**  | 同一语义槽位、当前状态、用户更正 → 覆盖；多条独立事实、历史摘要、操作轨迹 → 追加。可按“槽位”建模，槽位内覆盖、槽位间追加。 |
| **时间衰减与遗忘曲线**   | 用时间戳/最近使用时间做衰减（如指数衰减），让旧记忆在检索时权重降低；可按类型分层（偏好衰减慢、摘要/临时衰减快）。        |
| **冲突记忆处理**      | 最新为准（同槽位覆盖）、来源优先级（多源时高优先压制低）、置信度加权（参与排序或冲突时取高）；可组合使用。             |
| **“忘记”是能力的一部分** | 防止错误与过时信息污染、满足合规与用户删除诉求；控制存储与检索规模，保持系统健壮、检索质量与可维护性。               |
