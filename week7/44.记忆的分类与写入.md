# 44. 记忆的分类与写入

Day 43 说明了为什么 Agent 需要记忆：Context 有上限且不持久，跨会话、个性化、长期事实都需要记忆系统补上。本节在此基础上厘清**记忆与上下文、外部知识三者的边界**，介绍**记忆的常见分类**，并讨论**写入策略**与“**克制地记忆**”的原则。

## 一、记忆 vs 上下文 vs 外部知识：三者各管什么

设计记忆系统前，先要分清三样东西在 Agent 架构里各自负责什么，避免“该记的没记、不该记的塞满”。

### 1. 三者的定义与职责

| 概念                  | 定义                               | 典型职责                                  | 生命周期                    |
| ------------------- | -------------------------------- | ------------------------------------- | ----------------------- |
| **上下文（Context）**    | 某一次 LLM 调用时，模型能看到的全部输入           | 本轮内的 System、对话历史、当前问题、本轮注入的检索/记忆/工具结果 | 单次请求，请求结束即消失            |
| **记忆（Memory）**      | 跨请求、跨会话持久化存储的、与“当前用户/任务/会话”相关的信息 | 用户偏好、历史摘要、任务进度、关键事实与约定                | 持久存储，按需检索并注入 Context    |
| **外部知识（Knowledge）** | 与“谁在问、何时问”无关的通用或领域知识             | 产品文档、FAQ、知识库、规则与政策                    | 通常持久存在，按查询检索后注入 Context |

简单说：**上下文是“这一轮的眼界”；记忆是“关于这个用户/任务/会话的持久信息”；外部知识是“人人都可用的背景知识”。**

### 2. 边界与协作关系

- **上下文**不负责“记住”任何东西，只负责“这一轮装什么”。历史对话、记忆检索结果、RAG 段落，都是**先被准备好，再作为 Context 的一部分**送入模型。
- **记忆**关注**谁、什么任务、什么会话**：同一段“用户偏好简洁”是记忆；同一份《产品手册》是外部知识。记忆通常按 user_id、session_id、task_id 等做隔离与检索。
- **外部知识**一般不按用户区分（除非做权限过滤），而是按**主题、关键词、向量相似度**检索。写进知识库的内容通常不叫“记忆”，而叫“文档”或“知识”。

> **记忆** = 与主体（用户/会话/任务）绑定的、需要跨轮保留的信息；**外部知识** = 与主体解耦的、可供检索的通用或领域知识。二者都会在“需要时”被检索并**注入到 Context**，但来源与组织方式不同。

### 3. 小结表

| 维度         | 上下文                   | 记忆                      | 外部知识          |
| ---------- | --------------------- | ----------------------- | ------------- |
| **作用范围**   | 单次调用                  | 跨调用、跨会话                 | 跨调用、通常跨用户     |
| **与主体绑定**  | 本轮请求                  | 常与 user/session/task 绑定 | 一般不按用户区分      |
| **典型内容**   | 提示词、历史消息、当前输入、本轮注入的一切 | 用户偏好、任务进度、历史摘要、关键事实     | 文档、FAQ、规则、知识库 |
| **如何进入模型** | 本身就是“本轮输入”            | 检索后写入 Context           | 检索后写入 Context |

## 二、记忆的基本分类

实践中常把记忆按**时间跨度、归属对象、用途**分成几类，便于设计存储结构与写入/检索策略。

### 1. 短期记忆（Short-term）

- **含义**：当前会话内、近期几轮内的信息，用于保持本会话的连贯。
- **典型内容**：本会话的对话历史（或最近 N 轮的摘要）、本会话内刚用过的工具结果、当前轮正在讨论的实体（如刚提到的订单号）。
- **特点**：生命周期短（会话结束可清理或压缩），检索时通常“全量或滑动窗口”即可，不一定做向量检索。
- **与 Context 的关系**：短期记忆往往直接以“对话历史”形式存在于 Context 中；也可在会话内先写入记忆再检索，用于超长会话的裁剪与摘要。

### 2. 长期记忆（Long-term）

- **含义**：跨会话保留、需要在一段时间内反复使用的信息。
- **典型内容**：用户明确表达的偏好（“用英文回复”“不要推荐某类内容”）、重要事实（“我是项目经理”“公司在上海”）、历史会话的摘要或关键结论。
- **特点**：持久存储，按 user_id（及可选 session_id/task_id）检索，常配合向量或关键词在“需要时”取回并注入 Context。
- **与短期记忆的区分**：短期服务于“这一场对话别断片”；长期服务于“下次见面还能认出你、延续偏好与事实”。

### 3. 用户画像（User Profile / 用户记忆）

- **含义**：与**单个用户**绑定的属性、偏好、历史行为摘要。
- **典型内容**： demographic 信息（若合规使用）、偏好设置（语言、长度、风格）、禁忌与约束（不吃辣、不提某竞品）、历史交互的统计或摘要（常问哪类问题、常用哪些功能）。
- **特点**：以 user_id 为主键，多会话共享；写入时需考虑更新与冲突（Day 45 会细讲）。
- **用途**：个性化回复、推荐、权限与合规（如“不向未成年人推荐某类内容”）。

### 4. 任务态势（Task / Session State）

- **含义**：与**某一次任务或会话**绑定的进度、中间结果、待办。
- **典型内容**：多步任务的当前步骤、已填表单字段、待支付订单 ID、会话内已调用的工具及其结果摘要。
- **特点**：生命周期与任务/会话绑定，任务结束可归档或清理；检索时按 task_id / session_id 取回，便于“继续上次未完成的操作”。
- **与长期记忆的区分**：任务态势是“进行中的状态”；长期记忆是“跨多次会话都要用的信息”。

### 5. 分类小结表

| 类型       | 绑定对象         | 典型生命周期         | 典型内容                |
| -------- | ------------ | -------------- | ------------------- |
| **短期记忆** | 当前会话         | 会话内或会话结束即清理/压缩 | 本会话对话、近期工具结果、当前讨论实体 |
| **长期记忆** | 用户（及可选任务/会话） | 长期保留，按策略更新或衰减  | 用户偏好、重要事实、历史摘要与结论   |
| **用户画像** | 用户           | 长期保留，随交互更新     | 偏好、禁忌、行为统计与摘要       |
| **任务态势** | 任务/会话        | 任务或会话存续期       | 任务进度、表单状态、待办、中间结果   |

实际系统中，上述类型可以共用一套存储（例如都用同一张“记忆”表，用字段区分 type / scope），也可以分库分表；分类的意义在于**写入与检索时知道“记到哪、从哪取”**。

## 三、写入策略：什么时候记、记什么、记多少

记忆不能“有就记”，需要策略，否则存储膨胀、噪音过多、检索质量下降。

### 1. 什么时候记（触发条件）

- **用户显式表达**：例如“以后都用英文”“不要提 X”“我是 Y 角色”——这类应优先写入（长期记忆或用户画像）。
- **关键事实或约定**：例如用户确认了某条款、选择了某选项、提供了某重要信息（邮箱、项目名），可在当轮或会话结束时写入。
- **任务里程碑**：多步任务完成某一步、或暂停时，写入任务态势（当前步骤、已填信息、待办）。
- **会话摘要**：会话结束或轮数达到阈值时，对会话内容做摘要或抽取关键结论，写入长期记忆，避免“每轮原样存”导致冗余。

不必记的典型情况：**每一轮原始对话**（除非做有选择的摘要）、**纯寒暄与无关闲聊**、**明显的一次性信息**（如“今天天气不错”且与任务无关）。

### 2. 记什么（内容筛选）

- **偏好与约束**：用户明确说的“要/不要”“喜欢/不喜欢”，适合进用户画像或长期记忆。
- **实体与事实**：人物、项目、时间、地点等关键信息，若对后续会话有用，可结构化或半结构化写入。
- **任务状态**：当前步骤、已完成项、待办、关键 ID（订单、会话等），进任务态势。
- **摘要而非全文**：长对话优先记“结论、决定、关键事实”的摘要，而不是整段原文，控制单条记忆的信息密度与可检索性。

### 3. 记多少（数量与粒度）

- **单条记忆不宜过长**：便于检索与注入；过长容易在 Context 里占满 token、稀释其他信息。可拆成多条“原子”记忆，或一条摘要 + 多条关键词/实体。
- **单用户/单会话记忆条数要有上限或淘汰策略**：避免无限增长，结合 Day 45 的“遗忘”与更新策略（如只保留最近 N 条、或按时间/重要性衰减）。
- **写入前可做去重与合并**：例如用户多次说“用英文”，可合并为一条“偏好：英文回复”，避免重复写入。

### 4. 小结表

| 维度        | 建议                                                |
| --------- | ------------------------------------------------- |
| **什么时候记** | 用户显式表达、关键事实/约定、任务里程碑、会话摘要（有选择）；不记每轮原文、纯寒暄、一次性无关信息 |
| **记什么**   | 偏好与约束、实体与事实、任务状态、摘要与结论；优先结构化或半结构化                 |
| **记多少**   | 单条不宜过长；单主体记忆条数有上限或淘汰；写入前可去重与合并                    |

## 四、“克制地记忆”：避免把所有对话都当记忆

“能记”不等于“都要记”。把所有对话都当记忆会带来：

- **存储与成本**：数据量暴增，检索变慢、成本上升。
- **噪音与污染**：无关、过时、重复的信息把真正有用的记忆“冲淡”，检索精度下降。
- **隐私与合规**：记下过多原始对话，增加泄露与合规风险；用户也可能不希望“每句话都被记住”。

### 1. 原则

- **默认不记，按需记**：只有符合“写入策略”的内容才写入记忆（显式偏好、关键事实、任务状态、会话摘要等）。
- **记“提炼结果”多于“原始原文”**：用摘要、关键词、结构化字段代替大段对话拷贝。
- **区分会话内与跨会话**：会话内连贯主要靠 Context 里的历史；跨会话才依赖记忆，因此记忆应偏重“跨会话仍有用的信息”。
- **定期审视与清理**：结合 Day 45 的更新与遗忘策略，对过期、冲突、低价值记忆做合并、覆盖或删除。

### 2. 简单类比

把记忆系统想象成你的笔记本：你不会把和别人的每句话都写上去，而是记**决定、待办、重要事实和偏好**。Agent 的记忆也应如此——**克制地记，记对后续有用的东西**，而不是把所有对话都当记忆。

## 小结

| 学习点                   | 要点                                                                                  |
| --------------------- | ----------------------------------------------------------------------------------- |
| **记忆 vs 上下文 vs 外部知识** | 上下文 = 本轮可见输入；记忆 = 与用户/任务/会话绑定的持久信息；外部知识 = 与主体解耦的通用/领域知识。记忆与外部知识都在需要时被检索并注入 Context。 |
| **记忆的基本分类**           | 短期记忆（会话内）、长期记忆（跨会话）、用户画像（用户级）、任务态势（任务/会话级）；按绑定对象与生命周期区分，便于写入与检索。                    |
| **写入策略**              | 什么时候记：显式表达、关键事实、任务里程碑、会话摘要。记什么：偏好、实体与事实、任务状态、摘要。记多少：单条不宜过长、条数有上限或淘汰、可去重与合并。         |
| **“克制地记忆”**           | 默认不记、按需记；记提炼结果多于原文；跨会话有用才进记忆；结合更新与遗忘策略，避免把所有对话都当记忆。                                 |
