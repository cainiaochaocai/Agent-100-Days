# 64. 为什么任务分解是 Agent 的核心能力

Week 8–9 我们学了 Agent 的组成、失败模式与反思：Agent 通过多轮“推理 → 行动 → 观察”完成目标，并在异常时通过反思纠错。但当用户给的是一个**包含多步、多依赖的复杂目标**时，若不让 Agent 先**把目标拆成可执行的子任务**，再按顺序或依赖执行，往往会出现“一步到位”的失败。本节说明**人类如何自然分解复杂问题**、**一步到位为什么必然失败**，以及**什么是“好”的任务分解**。

## 一、人类如何自然分解复杂问题：子目标、依赖与顺序

### 1. 子目标

- 人类面对“帮我安排一次出差”时，不会一次性给出所有动作，而是先拆成：订机票、订酒店、查目的地天气、准备材料……每个都是**可单独执行、可验证**的小目标。
- **子目标**把“大意图”变成“一串小意图”，每步的输入输出更清晰，出错时也容易定位是哪一步。

### 2. 依赖与顺序

- 有些子任务**依赖前序结果**：例如“根据会议时间订机票”必须先有“会议时间”，“汇总报告”必须在“各小节写完”之后。
- 人类会自然区分**谁先谁后**、**谁依赖谁**，从而形成顺序链或依赖图，而不是随机执行。

### 3. 对 Agent 的启发

- Agent 若也能“先分解、再执行”，就能在**规划层**显式处理复杂目标，而不是在一次推理中塞进所有步骤，容易漏步、错序或超出上下文。

## 二、一步到位为什么必然失败：复杂任务的不可一次性与上下文限制

### 1. 复杂任务不可一次性完成

- **一步到位**：用户说“帮我查北京天气、查订单 ORD001 状态、再给一句总结”，模型若试图在**一次**推理里同时决定“调天气、调订单、写总结”，容易出现：只做了其中一部分、顺序颠倒、或把未执行的结果当事实写进总结。
- **原因**：复杂任务包含多个**独立动作**和**信息依赖**（总结依赖前两步的结果），单次推理的“工作记忆”有限，难以同时规划与执行多步且不丢步、不错序。

### 2. 上下文与 token 限制

- 即使多轮循环，若**不先分解**，模型每一轮都要从“整个大目标 + 已有历史”中推断“下一步做什么”，容易重复、遗漏或顺序混乱。
- 先分解成子任务后，**当前步**只需关注“当前子任务 + 前序子任务结果”，上下文更聚焦，步数也更可控。

### 3. 小结

| 问题       | 表现         | 原因简述                |
| -------- | ---------- | ------------------- |
| **一步到位** | 漏步、错序、幻觉总结 | 复杂任务不可在一次推理中完整规划与执行 |
| **不分解**  | 重复、混乱、难纠错  | 每轮面对“整目标+全历史”，焦点分散  |

## 三、什么是“好”的任务分解：可执行、可验证、依赖清晰、粒度合理

### 1. 可执行

- 每个子任务都能被 Agent **用现有工具或能力**在有限步内完成；不能是模糊的“了解一下”或无法对应到具体工具调用的描述。

### 2. 可验证

- 子任务完成后能判断**是否成功**（如拿到了天气、拿到了订单状态），便于与反思、重试结合；若某步失败，可只重试该步或按 Day 68 的修复策略处理。

### 3. 依赖清晰

- 子任务之间的**先后关系**或**输入输出依赖**要明确（谁先谁后、谁的结果给谁用），这样执行顺序不会错，汇总时也不会用错数据。

### 4. 粒度合理

- **过粗**：如只拆成“准备出差”，仍无法直接执行。
- **过细**：如拆成几十个点击级操作，步数爆炸、成本高、易失败。
- **合理**：每步对应一个可调用的能力或一次明确的决策，通常几步到十几步内能完成整体目标。
