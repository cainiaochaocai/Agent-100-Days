# 69. 实战：任务分解模式 Agent

Day 68 梳理了任务分解的失败模式与修复策略。本节动手**构建一个任务分解模式的 Agent**：设计“分解 → 执行子任务 → 汇总”的流程、子任务表示与状态追踪、以及与工具/反思/上下文的衔接。完整可运行代码见 **`week10/69_code/task_decomposition_agent_demo.py`**。

## 一、设计“分解 → 执行子任务 → 汇总”的 Agent 流程

### 1. 三阶段流程

- **分解**：输入用户目标，输出**有序子任务列表**（如 `["查北京天气", "查订单 ORD001 状态", "用一句话总结"]`）。可用 LLM 一次调用，prompt 中要求“按执行顺序、每步可单独执行、不遗漏关键动作”，并约束输出为 JSON 数组。
- **执行**：按顺序遍历子任务列表；对每个子任务，将**当前子任务 + 整体目标 + 前序步骤结果**作为上下文，调用“执行器”（如带工具的 Agent 或单次工具调用），得到该步结果并追加到结果列表。
- **汇总**：所有子任务执行完后，将**用户目标 + 各步结果**交给 LLM，生成一段面向用户的最终回复（总结、归纳，而非简单罗列）。

### 2. 与 Day 65 线性分解的对应

- 分解阶段产出的是**线性步骤链**；执行阶段严格按序，每步输入包含前序输出，对应 Day 65 的“步骤链、每步输入来自上一步输出”。
- 若某步失败，可将该步结果记为“执行失败”继续后续步，或在汇总时说明“某步未完成”（对应 Day 68 的降级策略）。

## 二、子任务表示与状态追踪、依赖与顺序约束

### 1. 子任务表示

- 本示例采用**字符串列表**：`list[str]`，每项为一句自然语言描述（如“查北京天气”），便于 LLM 生成与理解。
- 若需更强约束，可扩展为结构化（如 `{"id": 1, "desc": "...", "depends_on": []}`），便于表达依赖与去重。

### 2. 状态追踪

- **结果列表** `results`：每执行完一步，将返回值追加到 `results`；下一步与汇总阶段都只读该列表，无需额外状态机。
- **执行器**：每步调用 `run_subtask(subtask, goal, prior_results)`，内部可复用 Week 8 的 Agent 循环（带工具、最大步数），保证单步可完成多轮工具调用。

### 3. 依赖与顺序约束

- 当前实现为**严格顺序**：子任务顺序由分解时的列表顺序决定，执行时按 index 顺序调用，隐式满足“前一步完成再执行下一步”。
- 若后续要支持树状或 DAG，可让分解阶段输出带 `depends_on` 的结构，执行阶段按拓扑序调度（见 Day 67）。

## 三、与工具、反思、上下文的衔接

### 1. 与工具衔接

- 每个子任务的执行器（`run_subtask`）内部使用 **Week 8 同款** 工具绑定与 Agent 循环：`llm_with_tools`、`tool_map`，工具包括 `get_weather`、`get_current_time`、`search_order`。子任务描述会驱动模型在该步内选择合适的工具并调用。

### 2. 与反思衔接

- 若在**单步执行**中接入 Week 9 的反思节点：可在 `run_subtask` 内每轮工具执行后判断是否触发反思，按 decision 做继续/调整/停止；若为停止，可将该步结果设为“本步经反思终止”，并继续后续子任务或提前结束汇总。
- 本示例未内置反思，保留为可选扩展点。

### 3. 与上下文衔接

- **分解**：仅用用户目标，无需历史。
- **执行**：每步上下文 = 目标 + 前序结果列表，控制 token；若需长期记忆（Week 7），可在目标前拼接检索到的记忆片段。
- **汇总**：输入 = 目标 + 各步结果，输出为最终回复。

## 四、完整可运行示例说明与开发流程建议

### 1. 脚本做了什么

- **`week10/69_code/task_decomposition_agent_demo.py`** 实现：
  - **decompose_goal(goal)**：调用 LLM 将目标拆成 JSON 数组形式的子任务列表，解析失败时用简单兜底（按句号/换行拆分）。
  - **run_subtask(subtask, goal, prior_results)**：用带工具的 Agent 循环执行单步，最多 `MAX_STEP_TURNS` 轮，返回最后一条模型回复或“未结束”提示。
  - **summarize(goal, results)**：调用 LLM 根据目标与各步结果生成最终回复。
  - **run_task_decomposition_agent(goal)**：先分解 → 顺序执行 → 汇总，并可选打印每步的分解与执行结果（verbose=True）。

### 2. 运行方式

在项目根目录执行：

```bash
python week10/69_code/task_decomposition_agent_demo.py
```

输入示例：“查北京天气、查订单 ORD001 状态、用一句话总结”。可观察控制台输出的 `[分解]`、`[执行]` 与最终 `回复`。

### 3. 开发流程建议

1. **先跑通线性流程**：确认分解 → 执行 → 汇总三阶段在本地可运行，再考虑树状或并行。
2. **调分解质量**：若子任务过粗或漏步，可加强分解 prompt（如“必须包含用户目标中的每个关键动作”）或增加校验（如关键词 checklist）。
3. **单步失败处理**：在 `run_subtask` 内捕获异常或工具错误，返回“该步失败: …”；汇总时在 prompt 中说明“若某步为失败，请在回复中说明”。
4. **可选接入反思**：在 `run_subtask` 的循环中接入 Week 9 的反思逻辑，对单步内的重复错误做调整或停止。
