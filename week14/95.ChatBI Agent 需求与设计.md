# 95. ChatBI Agent 需求与设计

Day 94 完成了 DeepResearch Agent 的实现。本节在平台上实现**第二个垂直场景 Agent：ChatBI**。说明 **ChatBI 场景与风险**（自然语言问指标、趋势、对比；SQL 注入、误删/写操作、安全范围控制）、**数据源与 schema 建模**（从数据库/CSV 抽取 schema，为模型准备“schema 提示”），以及**作为平台上的“数据工具链 Agent”**（ChatBI 通过 ToolPlugin 接入数据库工具，Agent 逻辑处理自然语言 → SQL → 解释）。

## 一、ChatBI 场景与风险：自然语言问指标、趋势、对比；SQL 注入、误删/写操作、安全范围控制

### 1. 典型场景

- **指标查询**：用户问“上个月的销售额是多少？”“月活用户数是多少？”
- **趋势分析**：用户问“最近 3 个月的销售额趋势如何？”“用户增长趋势如何？”
- **对比分析**：用户问“A 产品与 B 产品的销售额对比如何？”“不同地区的用户分布如何？”

### 2. 风险点

- **SQL 注入**：若模型生成的 SQL 包含用户输入，可能被恶意利用（如 `SELECT * FROM users WHERE name = 'admin' OR '1'='1'`）。
- **误删/写操作**：模型可能生成 `DELETE` 或 `UPDATE` 语句，误删或误改数据。
- **越权访问**：模型可能查询用户无权访问的表或字段。
- **性能问题**：模型可能生成**低效 SQL**（如全表扫描、缺少索引），导致数据库负载过高。

### 3. 安全范围控制

- **只读模式**：ChatBI Agent 应**只允许 SELECT 查询**，禁止 DELETE、UPDATE、INSERT、DROP 等写操作。
- **表/字段白名单**：限制 Agent 只能查询**允许的表和字段**，不能访问敏感表（如用户密码表）。
- **行级权限**：根据用户身份限制查询范围（如只能查询自己部门的数据）。

### 4. 小结表

| 场景     | 示例                     | 风险                     |
| -------- | ------------------------ | ------------------------ |
| **指标查询** | 上个月的销售额           | SQL 注入、越权访问       |
| **趋势分析** | 最近 3 个月的销售额趋势   | 性能问题、低效 SQL       |
| **对比分析** | A 产品与 B 产品的对比    | 误删/写操作、越权访问   |

## 二、数据源与 schema 建模：从数据库/CSV 抽取 schema，为模型准备“schema 提示”

### 1. Schema 抽取

- **数据库**：从数据库**抽取 schema**（表名、字段名、字段类型、主键、外键、索引等）。
- **CSV**：从 CSV 文件**推断 schema**（列名、数据类型、示例数据）。
- **实现**：用 ToolPlugin（如 `get_schema(table_name)`）或直接查询数据库元数据（如 `SELECT * FROM information_schema.tables`）。

### 2. Schema 提示

- **含义**：将 schema 信息**格式化**，作为 System Prompt 的一部分，让模型知道“有哪些表、有哪些字段、字段类型是什么”。
- **格式**：例如：
  ```
  可用数据表：
  - orders: order_id (int), user_id (int), amount (decimal), created_at (datetime)
  - users: user_id (int), name (str), department (str)
  
  关系：orders.user_id → users.user_id
  ```
- **作用**：模型根据 schema 生成正确的 SQL，避免表名/字段名错误。

### 3. 示例数据

- **含义**：除了 schema，还可以提供**示例数据**（如每个表的几行示例），帮助模型理解数据格式。
- **作用**：模型可以根据示例数据生成更准确的 SQL（如知道 `amount` 是小数，不是整数）。

### 4. 小结表

| 内容         | 含义                     | 作用                         |
| ------------ | ------------------------ | ---------------------------- |
| **Schema 抽取** | 从数据库/CSV 抽取表结构 | 让模型知道有哪些表/字段     |
| **Schema 提示** | 格式化 schema 作为 prompt | 模型根据 schema 生成 SQL    |
| **示例数据** | 提供表的示例数据         | 帮助模型理解数据格式         |

## 三、作为平台上的“数据工具链 Agent”：ChatBI 通过 ToolPlugin 接入数据库工具，Agent 逻辑处理自然语言 → SQL → 解释

### 1. 数据库工具（ToolPlugin）

- **功能**：通过 ToolPlugin 接入数据库工具（如 `execute_sql(sql)`、`get_schema(table_name)`）。
- **实现**：`DatabaseToolPlugin` 实现 `execute_sql(sql)`，内部连接数据库、执行 SQL、返回结果。
- **安全**：ToolPlugin 内部做**安全校验**（只读模式、表/字段白名单、行级权限），拒绝危险 SQL。

### 2. Agent 逻辑

- **自然语言 → SQL**：ChatBI Agent 接收用户问题，根据 schema 提示生成 SQL。
- **SQL review**：生成 SQL 后，可以先用 LLM 做 **SQL review**（检查 SQL 是否正确、是否安全、是否高效）。
- **执行 SQL**：通过 DatabaseToolPlugin 执行 SQL，获取结果。
- **结果 → 自然语言解释**：将 SQL 结果（表格数据）转换为自然语言解释（如“上个月的销售额为 ¥100,000，环比增长 10%”）。

### 3. 工具链

- **流程**：用户问题 → ChatBI Agent → SQL 生成 → SQL review → 执行 SQL → 结果解释 → 返回用户。
- **复用平台能力**：ChatBI Agent 通过 ToolPlugin 调用数据库工具，通过反思检查 SQL 质量，通过 HITL 审批敏感查询（如金额超阈值）。

### 4. 小结

| 层         | 职责                     | 实现方式                         |
| ---------- | ------------------------ | -------------------------------- |
| **ToolPlugin** | 数据库工具（执行 SQL、获取 schema） | DatabaseToolPlugin               |
| **Agent 逻辑** | 自然语言 → SQL → 解释    | ChatBI Agent（LLM + ToolPlugin） |
| **安全控制** | 只读模式、白名单、权限   | ToolPlugin 内部校验              |

## 四、实战中的实现
