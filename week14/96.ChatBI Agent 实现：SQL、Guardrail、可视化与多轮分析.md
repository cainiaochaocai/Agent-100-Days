# 96. ChatBI Agent 实现：SQL、Guardrail、可视化与多轮分析

Day 95 讲了 ChatBI Agent 的需求与设计。本节完整实现 ChatBI 核心能力：**SQL 生成与执行闭环**、**Guardrail 与权限控制**、**指标定义与语义对齐**，以及**可视化建议、多轮对话上下文、指标计算与缓存**。

## 一、SQL 生成与执行闭环：自然语言 → SQL → SQL review → 执行 → 结果 → 自然语言解释

### 1. 自然语言 → SQL

- **输入**：用户问题（如“上个月的销售额是多少？”）+ schema 提示（表结构、字段、示例数据）。
- **输出**：SQL 语句。
- **实现**：用 LLM 生成 SQL，prompt 中包含 schema 提示与用户问题，要求输出 SQL。

### 2. SQL review

- **含义**：生成 SQL 后先用 LLM 做 **SQL review**：检查正确性、安全性（禁止写操作）、高效性（WHERE、索引）。
- **实现**：review prompt 输入 SQL 与 schema，要求检查上述项；不通过则拒绝执行并返回原因。

### 3. 执行 SQL 与结果解释

- **执行**：通过 DatabaseToolPlugin 的 `execute_sql(sql)` 执行，返回表格数据；执行失败时返回可读错误信息。
- **结果解释**：用 LLM 将表格数据转换为自然语言解释（用户问题 + SQL + 结果 → 自然语言）。

### 4. 小结表

| 步骤         | 输入                     | 输出           |
| ------------ | ------------------------ | -------------- |
| **SQL 生成** | 用户问题 + schema        | SQL 语句       |
| **SQL review** | SQL + schema            | 通过/拒绝      |
| **执行 SQL** | SQL                      | 表格数据       |
| **结果解释** | 用户问题 + SQL + 结果    | 自然语言解释   |

## 二、Guardrail 与权限控制：禁止写操作、限制查询范围、行级权限

- **禁止写操作**：只允许 SELECT，禁止 DELETE、UPDATE、INSERT、DROP、ALTER；在 `execute_sql` 或 review 阶段做关键字检查。
- **表/字段白名单**：配置允许的表和字段，SQL 解析后校验，访问不允许的表/字段则拒绝执行。
- **行级权限**：根据用户身份（如部门）在 SQL 中加 WHERE 条件，或依赖数据库 RLS。

| 控制项       | 实现方式                         |
| ------------ | -------------------------------- |
| **禁止写操作** | SQL 解析 + 关键字检查            |
| **表/字段白名单** | SQL 解析 + 白名单校验            |
| **行级权限** | SQL 改写或数据库级权限           |

## 三、指标定义与语义对齐

- **指标定义**：用 YAML/JSON 或指标库显式定义指标（如“月活”“留存率”）的 SQL 或计算逻辑。
- **语义对齐**：用户问“月活是多少？”时，用 Embedding 或关键词将问题匹配到指标定义，命中则用定义 SQL，否则按 schema 生成 SQL。
- **指标库**：统一管理指标，避免同一指标被生成成不同 SQL。

## 四、可视化建议：指导前端做简单图表（折线、柱状、数字卡片）

- **结果类型判断**：单值（1 行 1 列）→ 数字卡片；时间序列（多行+日期列）→ 折线/柱状；分类对比 → 柱状/饼图；多维度 → 表格/热力图。
- **可视化建议生成**：根据结果结构输出 JSON（chart_type、x_axis、y_axis、title、data），前端据此渲染。
- **结构化响应**：Agent 返回 `explanation` + `visualization` + `data`，便于前端统一处理。

## 五、多轮对话上下文与指标计算、缓存

- **分析会话状态**：多轮提问时保持“当前分析会话”的上下文（筛选条件、时间范围、粒度）；从上一轮 SQL 与结果中提取上下文，在新一轮 SQL 生成 prompt 中注入。
- **指标计算**：复杂指标在指标库中定义计算逻辑（多步 SQL 或函数），Agent 匹配后直接调用，而非让模型生成 SQL。
- **结果缓存**：相同 SQL 或指标+参数的结果可缓存（key 为 SQL hash 或指标名+参数），TTL 或 LRU 策略；数据更新时相关缓存失效。

## 六、实战中的实现

在 **`week14/97_code/platform_with_scenario_agents_demo.py`** 中：

- **SQL 生成**：`run_chatbi()` 内用 `sql_prompt`（含 `ORDERS_SCHEMA` 与用户问题）调用 LLM 得到原始 SQL，经 strip/去 markdown 后得到 `raw_sql`。
- **Guardrail**：`_guardrail_sql(sql)` 校验仅允许 SELECT、禁止 INSERT/UPDATE/DELETE/DROP 等关键字，不通过则直接返回错误信息，不执行。
- **执行与解释**：`_execute_memory_sql(sql)` 对内存表 `DEMO_ORDERS` 做简化执行（支持 SUM/COUNT/AVG 与全表）；执行结果用 `explain_prompt` 交给 LLM 生成自然语言解释。
- **扩展**：可视化建议、多轮上下文、指标库与缓存可在同一文件中增加 `generate_visualization()`、`extract_context()`、指标匹配与缓存层实现。
