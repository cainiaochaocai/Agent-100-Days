# 92. DeepResearch Agent 需求与设计

Week 12-13 我们搭建了 Gateway + Runtime + 插件系统的完整平台。本节在平台上实现**第一个垂直场景 Agent：DeepResearch**。说明 **DeepResearch 问题范式**（开放问题、多来源、多轮验证、证据管理）、**研究流程设计**（Problem framing → Plan → Search → Read → Synthesize → Critique），以及**作为平台上的“高级 Tool”**（DeepResearch 不是独立系统，而是平台上的复杂工具链 Agent）。

## 一、DeepResearch 问题范式：开放问题、多来源、多轮验证、证据管理

### 1. 开放问题

- **含义**：用户提出的问题**没有标准答案**，需要 Agent 主动探索、收集信息、形成观点。例如：“AI 在医疗领域的最新应用有哪些？”“2026 年 AI 发展趋势是什么？”
- **特点**：不像“查天气”“查订单”那样有明确的工具与答案，而是需要**多步检索、阅读、分析、综合**。

### 2. 多来源

- **含义**：研究问题需要从**多个来源**收集信息：搜索引擎、RAG 知识库、学术论文、新闻网站等。
- **作用**：单一来源可能偏颇或遗漏，多来源可以**交叉验证**、**补充视角**、**发现冲突**。

### 3. 多轮验证

- **含义**：不是“查一次就结束”，而是**多轮检索与验证**：第一轮检索得到初步结果，根据结果**再检索**（如查更具体的子问题、查反对观点），直到信息充分。
- **作用**：避免“第一页结果就下结论”，提升研究的**深度与平衡性**。

### 4. 证据管理

- **含义**：收集到的信息需要**结构化管理**：来源、时间、置信度、是否被引用、是否冲突等。
- **作用**：用于后续的**证据合成**、**引用生成**、**质量评估**。

### 5. 小结表

| 特征       | 含义          | 作用         |
| -------- | ----------- | ---------- |
| **开放问题** | 没有标准答案，需要探索 | 驱动多步检索与分析  |
| **多来源**  | 从多个来源收集信息   | 交叉验证、补充视角  |
| **多轮验证** | 多轮检索与验证     | 提升深度与平衡性   |
| **证据管理** | 结构化管理收集到的信息 | 用于合成、引用、评估 |

## 二、研究流程设计：Problem framing → Plan → Search → Read → Synthesize → Critique

### 1. Problem framing（问题框架化）

- **含义**：将用户的**模糊问题**转化为**可研究的问题**：明确范围、拆分子问题、确定研究角度。
- **实现**：用 Week 10 的**任务分解**模式，将研究问题拆成若干子问题（如“AI 在医疗的应用”拆成“诊断、治疗、药物研发、管理”等）。

### 2. Plan（研究计划）

- **含义**：制定**研究计划**：每个子问题用什么来源检索、检索什么关键词、预期得到什么信息。
- **实现**：用 LLM 生成研究计划（JSON 格式），包含子问题列表、检索策略、预期结果。

### 3. Search（检索）

- **含义**：根据研究计划，**多轮检索**：调用搜索工具、RAG 工具，收集信息。
- **实现**：Runtime 通过 ToolPlugin 调用搜索工具（如 `search_tool(query)`），收集检索结果。

### 4. Read（阅读）

- **含义**：对检索结果进行**阅读与分析**：提取关键信息、识别观点、标注来源。
- **实现**：用 LLM 对检索结果做摘要与提取，识别关键信息与观点。

### 5. Synthesize（合成）

- **含义**：将多来源信息**整合成结构化报告**：合并相似观点、列出不同观点、形成结论。
- **实现**：用 LLM 将证据池整合成报告，包含：摘要、主要观点、不同观点、结论。

### 6. Critique（自我审查）

- **含义**：对生成的报告做**自我审查**：检查覆盖度、平衡性、是否遗漏反对观点、是否过度概括。
- **实现**：用 LLM 做 self-critique prompt，检查报告质量，必要时补充检索或修正。

### 7. 小结

| 阶段                  | 含义          | 实现方式                     |
| ------------------- | ----------- | ------------------------ |
| **Problem framing** | 问题框架化，拆分子问题 | 任务分解模式（Week 10）          |
| **Plan**            | 制定研究计划      | LLM 生成计划（JSON）           |
| **Search**          | 多轮检索        | ToolPlugin（搜索工具）         |
| **Read**            | 阅读与分析       | LLM 摘要与提取                |
| **Synthesize**      | 整合成报告       | LLM 合成多来源信息              |
| **Critique**        | 自我审查        | LLM self-critique prompt |

## 三、作为平台上的“高级 Tool”：DeepResearch 不是独立系统，而是平台上的复杂工具链 Agent

### 1. 作为 ToolPlugin 或自定义 Agent

- **方式一：ToolPlugin**：DeepResearch 作为**一个复杂工具**（如 `deep_research(query)`），Runtime 调用该工具，工具内部执行完整研究流程。
- **方式二：自定义 Agent**：DeepResearch 作为**一个专用 Agent**，Gateway 路由到该 Agent，Agent 内部执行研究流程。
- **推荐**：作为**自定义 Agent**，因为研究流程需要多轮 LLM 调用与工具调用，更适合作为独立的 Agent Runtime。

### 2. 复用平台能力

- **工具系统**：DeepResearch Agent 通过 ToolPlugin 调用搜索工具、RAG 工具，无需自己实现工具。
- **反思与 HITL**：研究过程中可以触发反思（检查检索质量、是否需要补充）与 HITL（用户确认研究方向）。
- **记忆系统**：研究结果可以写入记忆（MemoryPlugin），供后续查询。

### 3. 插件化优势

- **可扩展**：新增研究能力（如新增数据源、新增分析方法）只需扩展 ToolPlugin 或 Agent 逻辑，无需修改平台核心。
- **可替换**：可以切换不同的研究策略（如不同的检索工具、不同的合成方法），而不影响平台架构。

### 4. 小结与平台对照

| 方式             | 含义         | 优势         |
| -------------- | ---------- | ---------- |
| **ToolPlugin** | 作为复杂工具     | 简单，但灵活性有限  |
| **自定义 Agent**  | 作为专用 Agent | 灵活，可复用平台能力 |

**与 OpenClaw 的对照**：OpenClaw 支持多通道（WhatsApp、Telegram、飞书等）接入同一套智能体能力；本课在自建平台上实现**垂直场景 Agent**（DeepResearch、ChatBI），是「教学版平台 + 场景化能力」的路线，与 OpenClaw 的「生产级多通道 + 可插拔模型/工具」互为参考，见 [OpenClaw 实现指南](https://openclaw-docs.dx3n.cn/)。
