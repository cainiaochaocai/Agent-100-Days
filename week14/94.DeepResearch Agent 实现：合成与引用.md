# 94. DeepResearch Agent 实现：合成与引用

Day 93 讲了研究计划生成与多轮检索。本节实现**证据合成**（将多来源证据整合成结构化报告）、**引用与可追溯性**（自动生成引用和参考文献列表），以及**质量评估**（自评 prompt，检查覆盖度、平衡性、是否遗漏反对观点）。

## 一、证据合成：将多来源证据整合成结构化报告

### 1. 证据整理

- **输入**：证据池（多来源的证据列表）。
- **整理**：按**子问题**分组证据，每个子问题下的证据按时间或可信度排序。
- **实现**：DeepResearch Agent 将证据池按 `sub_question` 分组，每组证据排序后交给 LLM 合成。

### 2. 结构化报告

- **格式**：报告包含以下章节：
  - **摘要**：研究问题的简要回答。
  - **主要观点**：各子问题的核心发现，按子问题组织。
  - **不同观点**：冲突或不同来源的观点，明确列出。
  - **不确定项**：无法确定或存在争议的内容。
  - **结论**：综合所有证据的结论。
- **实现**：用 LLM 将证据池合成成结构化报告，prompt 中要求按上述格式输出。

### 3. 合成策略

- **合并相似观点**：多个来源的相似观点合并为一条，标注“多个来源支持”。
- **列出不同观点**：冲突观点单独列出，标注来源。
- **避免过度概括**：只基于证据池中的内容，不添加未检索到的信息。

### 4. 小结表

| 步骤         | 含义                     | 实现方式                         |
| ------------ | ------------------------ | -------------------------------- |
| **证据整理** | 按子问题分组，排序       | 分组与排序逻辑                   |
| **结构化报告** | 生成包含摘要、观点、结论的报告 | LLM 合成（结构化 prompt）        |
| **合成策略** | 合并相似、列出不同、避免过度概括 | prompt 中规定策略                |

## 二、引用与可追溯性：自动生成引用（[1][2]）和参考文献列表

### 1. 引用生成

- **含义**：在报告的**关键观点**后自动标注引用（如 `[1]`、`[2]`），表示该观点来自哪个证据。
- **实现**：
  - **证据编号**：证据池中的每个证据分配一个编号（如 1, 2, 3...）。
  - **引用映射**：LLM 在合成报告时，标注哪些观点引用了哪些证据（如“AI 诊断准确率 95% [1][2]”）。
  - **引用格式**：可以用 `[1]`、`[2]` 等编号，或 `[来源1]`、`[来源2]` 等描述性引用。

### 2. 参考文献列表

- **含义**：报告末尾附上**参考文献列表**，列出所有被引用的证据。
- **格式**：每个参考文献包含：
  - 编号（如 `[1]`）
  - 来源（如“搜索引擎结果：AI 医疗诊断应用综述”）
  - 时间戳（如“检索时间：2025-02-17”）
  - 可选：URL、作者、标题等
- **实现**：DeepResearch Agent 根据引用映射，生成参考文献列表，追加到报告末尾。

### 3. 可追溯性

- **含义**：用户可以根据引用**追溯到原始证据**，查看证据的完整内容。
- **实现**：报告中的引用链接到证据池中的证据，用户可以通过引用编号查询原始证据。

### 4. 小结表

| 内容         | 含义                     | 实现方式                         |
| ------------ | ------------------------ | -------------------------------- |
| **引用生成** | 在观点后标注引用编号     | LLM 标注 + 引用映射              |
| **参考文献列表** | 列出所有被引用的证据     | 根据引用映射生成列表             |
| **可追溯性** | 用户可根据引用查询原始证据 | 引用编号 → 证据池查询            |

## 三、质量评估：自评 prompt（检查覆盖度、平衡性、是否遗漏反对观点）

### 1. 覆盖度检查

- **含义**：检查报告是否**覆盖了研究计划的所有子问题**，是否遗漏关键信息。
- **实现**：用 LLM 做 self-critique prompt，输入研究计划与报告，要求检查覆盖度：
  ```
  请检查报告是否覆盖了研究计划的所有子问题：
  研究计划：{plan}
  报告：{report}
  请指出遗漏的子问题或关键信息。
  ```

### 2. 平衡性检查

- **含义**：检查报告是否**只呈现一方观点**，是否遗漏反对观点或不同视角。
- **实现**：self-critique prompt 要求检查平衡性：
  ```
  请检查报告是否平衡地呈现了不同观点：
  报告：{report}
  证据池：{evidence_pool}
  请指出是否遗漏了反对观点或不同视角。
  ```

### 3. 遗漏反对观点检查

- **含义**：检查报告是否**遗漏了证据池中的反对观点**，是否过度偏向某一方。
- **实现**：对比报告与证据池，识别证据池中的反对观点是否在报告中体现。

### 4. 质量评估结果

- **输出**：质量评估返回一个**评估报告**，包含：
  - 覆盖度评分（如“覆盖了 90% 的子问题，遗漏了 X、Y”）
  - 平衡性评分（如“较好地呈现了不同观点，但遗漏了反对观点 Z”）
  - 改进建议（如“建议补充检索反对观点 Z”）
- **后续行动**：若评估发现严重问题（如遗漏关键子问题、遗漏反对观点），可以**触发补充检索**或**修正报告**。

### 5. 小结表

| 检查项       | 含义                     | 实现方式                         |
| ------------ | ------------------------ | -------------------------------- |
| **覆盖度**   | 是否覆盖所有子问题       | self-critique prompt             |
| **平衡性**   | 是否平衡呈现不同观点     | self-critique prompt             |
| **遗漏反对观点** | 是否遗漏反对观点     | 对比报告与证据池                 |
| **改进建议** | 根据评估结果提出改进建议 | LLM 生成改进建议                 |

## 四、实战中的实现

在 **`week14/97_code/platform_with_scenario_agents_demo.py`** 的 `run_deep_research()` 中：

- **证据合成**：将 `evidence_pool` 格式化为 `evidence_text` 后，用 `synth_prompt` 调用 LLM 生成简短报告（摘要、主要发现、结论），对应本节的“结构化报告”；可进一步在 prompt 中要求“主要观点”“不同观点”“不确定项”等章节。
- **引用与参考文献**：Demo 未实现引用编号与参考文献列表；可在证据池中为每条证据分配编号，在合成 prompt 中要求 LLM 在观点后标注 `[1]`、`[2]`，再根据引用生成参考文献列表追加到报告末尾。
- **质量评估**：可增加 `evaluate_report(report, plan, evidence_pool)` 步骤，用 self-critique prompt 检查覆盖度、平衡性、遗漏反对观点，不通过则补充检索或修正报告。
