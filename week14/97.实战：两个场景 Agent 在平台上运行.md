# 97. 实战：两个场景 Agent 在平台上运行

Day 96 完成了 ChatBI Agent 的实现。本节动手**将 DeepResearch 与 ChatBI 作为 ToolPlugin 或自定义 Agent 接入平台**：展示插件化优势（新增场景 Agent 无需修改核心代码，只需实现插件接口），以及**端到端演示**（用户通过 CLI/Web 发起研究或 BI 查询，平台路由到对应 Agent，返回结果）。完整可运行代码见 **`week14/97_code/platform_with_scenario_agents_demo.py`**（若已实现）。

## 一、将 DeepResearch 与 ChatBI 作为 ToolPlugin 或自定义 Agent 接入平台

### 1. DeepResearch Agent 接入

- **方式**：作为**自定义 Agent**（专用 Agent Runtime），Gateway 路由到该 Agent。
- **实现**：在 Router 中注册 `"deep_research_agent"`；研究类问题（如“研究”“分析”“调查”）路由到该 Agent；DeepResearch Runtime 实现规划 → 检索 → 合成 → 引用。

### 2. ChatBI Agent 接入

- **方式**：作为**自定义 Agent**（专用 Agent Runtime），Gateway 路由到该 Agent。
- **实现**：在 Router 中注册 `"chatbi_agent"`；BI 类问题（如“查询”“数据”“报表”“指标”）路由到该 Agent；ChatBI Runtime 实现 SQL 生成 → review → 执行 → 解释（+ 可视化、多轮上下文）。

### 3. 插件化优势

- **无需修改核心代码**：新增场景 Agent 只需实现 Agent 接口并注册到 Router。
- **可替换性**：可替换不同研究策略或 BI 策略，平台架构不变。
- **可扩展性**：可新增更多场景 Agent（如代码生成、写作），平台架构不变。

## 二、新增 Agent 的步骤与端到端演示

- **步骤**：实现 Agent Runtime（`run(user_input, context, session_id)`）→ 在 Router 中注册 → 配置路由规则 → 启动平台。
- **DeepResearch 演示**：用户输入“研究一下 AI 在医疗领域的最新应用” → 路由到 deep_research_agent → 返回结构化研究报告。
- **ChatBI 演示**：用户发送“查询上个月的销售额” → 路由到 chatbi_agent → 返回自然语言解释 + 可视化建议 + 数据。

## 三、完整可运行示例说明

- **代码路径**：`week14/97_code/platform_with_scenario_agents_demo.py`（单文件，包含 Gateway、路由、三个 Agent Runtime、CLI/Web 入口）。
- **运行前**：在项目根目录配置 `.env`，设置 `OPENAI_API_KEY` 或 `DASHSCOPE_API_KEY`（Demo 使用 `langchain-openai` 兼容 DashScope）。
- **运行方式**：
  - CLI：`python week14/97_code/platform_with_scenario_agents_demo.py --channel cli`
  - Web：`python week14/97_code/platform_with_scenario_agents_demo.py --channel web`（Flask，`POST /api/chat`，`GET /health`）。
- **脚本结构**：

| 模块 | 说明 |
|------|------|
| `route()` | 根据消息关键词返回 `general_agent` / `deep_research_agent` / `chatbi_agent` |
| `run_general()` | 通用 Agent：工具调用（天气、时间、订单查询） |
| `run_deep_research()` | 规划（LLM 拆子问题）→ 模拟检索 → LLM 合成报告 |
| `run_chatbi()` | NL → SQL（LLM）→ Guardrail（仅 SELECT）→ 内存表执行 → LLM 解释 |
| `Gateway.handle_request()` | 按 `agent_id` 分发到对应 Runtime，写回会话历史 |

- **验证插件化**：在 `ROUTE_RULES` 中增加一条规则、实现新的 `run_xxx()` 并在 `Gateway.handle_request()` 中增加分支，即可接入新场景 Agent，无需改 Gateway 核心接口。
