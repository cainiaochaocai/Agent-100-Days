# 93. DeepResearch Agent 实现：规划与检索

Day 92 讲了 DeepResearch Agent 的需求与设计。本节具体实现**研究计划生成**（用任务分解模式将研究问题拆成子问题）、**多轮检索与证据池**（调用搜索工具、RAG 工具，维护证据池），以及**去重与冲突处理**（多来源信息冲突时的策略）。

## 一、研究计划生成：用任务分解模式将研究问题拆成子问题

### 1. 问题分解

- **输入**：用户的研究问题（如“AI 在医疗领域的最新应用有哪些？”）。
- **输出**：研究计划（JSON 格式），包含子问题列表、检索策略、预期结果。
- **实现**：用 Week 10 的**任务分解**模式，调用 LLM 将问题拆成子问题：
  ```python
  plan = decompose_research_question(question)
  # 返回：
  # {
  #   "sub_questions": [
  #     {"question": "AI 在医疗诊断中的应用", "keywords": ["AI", "医疗诊断", "影像识别"]},
  #     {"question": "AI 在药物研发中的应用", "keywords": ["AI", "药物研发", "分子设计"]},
  #     ...
  #   ],
  #   "search_strategy": "多轮检索，先查综述，再查具体案例",
  #   "expected_sources": ["学术论文", "新闻", "行业报告"]
  # }
  ```

### 2. 检索策略

- **策略**：每个子问题有**检索关键词**、**检索来源**（如搜索引擎、RAG 知识库、学术数据库）、**检索深度**（如第一轮查综述，第二轮查具体案例）。
- **实现**：研究计划中包含检索策略，DeepResearch Agent 根据策略执行检索。

### 3. 预期结果

- **含义**：每个子问题预期得到什么信息（如“诊断应用：至少 3 个案例，包含技术原理与应用效果”）。
- **作用**：用于后续的**质量评估**（检查是否达到预期）与**补充检索**（若未达到预期，再检索）。

## 二、多轮检索与证据池：调用搜索工具、RAG 工具，维护证据池（来源、时间、置信度）

### 1. 多轮检索

- **第一轮**：根据研究计划的子问题，**并行检索**多个子问题（如同时检索“诊断应用”“药物研发应用”）。
- **第二轮**：根据第一轮结果，**补充检索**（如查更具体的案例、查反对观点、查最新进展）。
- **实现**：DeepResearch Agent 通过 ToolPlugin 调用搜索工具（如 `search_tool(query)`），收集检索结果。

### 2. 证据池管理

- **结构**：证据池是一个**列表**，每个证据包含：
  - `source`：来源（如“搜索引擎结果 1”“RAG 知识库 2”）
  - `content`：内容（检索结果的文本）
  - `timestamp`：时间戳
  - `confidence`：置信度（如 0.8，表示“较可信”）
  - `sub_question`：关联的子问题
  - `cited`：是否已被引用（用于后续生成引用）
- **实现**：DeepResearch Agent 维护一个 `evidence_pool` 列表，每轮检索后追加证据。

### 3. 证据去重

- **问题**：多轮检索可能返回**重复或相似的内容**（如同一篇文章被多个关键词检索到）。
- **处理**：检索后做简单去重（如按内容相似度或 URL 去重），避免证据池冗余。

### 4. 小结表

| 步骤         | 含义                     | 实现方式                         |
| ------------ | ------------------------ | -------------------------------- |
| **研究计划** | 拆分子问题、制定检索策略 | 任务分解模式（Week 10）          |
| **多轮检索** | 第一轮并行检索、第二轮补充检索 | ToolPlugin（搜索工具）            |
| **证据池**   | 维护证据列表（来源、内容、置信度） | 内存列表或数据库                 |
| **去重**     | 去除重复或相似证据       | 相似度匹配或 URL 去重            |

## 三、去重与冲突处理：多来源信息冲突时的策略（列出双方证据、标明不确定）

### 1. 冲突检测

- **含义**：多来源信息可能**冲突**（如 A 来源说“AI 诊断准确率 95%”，B 来源说“准确率 80%”）。
- **检测**：在证据合成阶段，LLM 可以识别冲突（如数值不一致、观点相反）。

### 2. 冲突处理策略

- **列出双方证据**：在报告中**明确列出**不同来源的观点，不强行统一。
- **标明不确定**：若冲突无法解决，在报告中**标明不确定**（如“不同来源给出的准确率不同，范围在 80%-95%之间”）。
- **来源优先级**：可选地，根据来源的**可信度**（如学术论文 > 新闻 > 论坛）决定以谁为准。

### 3. 实现方式

- **证据合成阶段**（Day 94）：LLM 在合成报告时，识别冲突并采用上述策略。
- **报告格式**：报告可以包含“主要观点”“不同观点”“不确定项”等章节。

### 4. 小结

| 策略         | 含义                     | 适用场景           |
| ------------ | ------------------------ | ------------------ |
| **列出双方证据** | 明确列出不同来源的观点 | 冲突无法判断时     |
| **标明不确定** | 在报告中标明不确定项   | 冲突无法解决时     |
| **来源优先级** | 根据可信度决定以谁为准 | 有明确优先级时     |

## 四、实战中的实现

在 **`week14/97_code/platform_with_scenario_agents_demo.py`** 的 `run_deep_research()` 中：

- **研究计划生成**：用 LLM 将用户问题拆成 2～3 个子问题（`plan_prompt` → `plan_msg`），得到 `sub_questions` 列表，对应本节的“任务分解”。
- **检索与证据池**：对每个子问题按关键词匹配预设内容（Demo 用 `SEARCH_SIMULATE_DB` 模拟检索），将结果加入 `evidence_pool`（含 `sub_question`、`source`、`content`）；真实场景可替换为 `search_tool(query)` 等 ToolPlugin。
- **去重与冲突**：当前 Demo 为简化版，未做去重与冲突检测；可在证据池收集后增加按内容/URL 去重，合成阶段（Day 94）再做冲突识别与标注。
