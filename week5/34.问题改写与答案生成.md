# 34. 问题改写与答案生成

检索拿到高相关 chunk 之后，还有两道关键环节：**用什么样的“问题”去检索**，以及**如何让模型基于检索内容生成答案、并标明出处**。用户提问往往口语化、模糊或过于简短，直接用来做向量检索效果未必最好；而生成阶段若不做约束，模型容易脱离检索内容编造或无法在“搜不到”时拒答。本节围绕三块学习内容展开：**Query Transformation（问题改写）**、**Prompt 工程实践**、**引用归属（Citations）实现**。

## 一、Query Transformation 技术：把模糊提问变成更好的检索词

用户输入可能是“这个怎么弄”“报销能报多少”等简短、口语化的句子，与知识库里的正式表述（如“差旅报销上限与审批流程”）在表述风格、用词上差距较大，直接用来做 Embedding 检索，相似度可能偏低。**Query Transformation** 的思路是：**先用 LLM 把用户问题改写成更贴近文档表述的“检索用 query”**，再用改写后的 query（或由此衍生的多条 query）去做检索，从而提升命中率。

### 1. 常见改写策略

| 策略                                         | 做法                                                             | 适用场景                                 |
| ------------------------------------------ | -------------------------------------------------------------- | ------------------------------------ |
| **HyDE（Hypothetical Document Embeddings）** | 让 LLM 根据问题**生成一段假设性答案**，对这段“假设答案”做 Embedding 去检索               | 问题很短、文档偏长句/段落时，假设答案的表述往往更接近真实段落，检索更准 |
| **Multi-query**                            | 让 LLM 根据原问题**生成多个不同表述的 query**（如换说法、拆子问题），对每个 query 分别检索，再合并去重 | 问题较复杂、可能对应多种问法或子问题时，提高覆盖度            |
| **Query 扩展 / 规范化**                         | 把口语化、缩写展开成完整、书面化的问句或关键词                                        | 专有名词、内部用语多的知识库                       |

可以只选一种，也可以组合：例如先用 Multi-query 生成 2 ～ 3 个 query，再对每个 query 用 HyDE 生成假设答案并检索，最后合并结果去重、重排。

### 2. HyDE 简要流程

```text
用户问题 Q → LLM 生成“假设性答案” H → 对 H 做 Embedding → 用 H 的向量在向量库中检索 → 得到与“假设答案”最相似的文档块（往往与真实答案段落更接近）
```

**Prompt 示例**：

```text
请根据下面的问题，写一段简短的假设性答案（2～3 句即可，不需要真实准确，只需风格和长度类似真实文档）。不要复述问题本身。

问题：公司差旅报销上限是多少？
```

模型可能输出类似：“差旅报销每人每年上限为 5000 元，超出需特批。” 用这段话的向量去检索，更容易命中真正写“报销上限 5000 元”的段落。

### 3. Multi-query 简要流程

```text
用户问题 Q → LLM 生成多个等价或子问题 Q1, Q2, Q3 → 分别用 Q1/Q2/Q3 做检索 → 合并结果（按 doc_id 去重或按分数融合）→ 再重排 / 压缩
```

**Prompt 示例**：

```text
用户问题：今年报销制度有什么变化？

请生成 2～3 个与上述问题等价或互补的检索用问句（换一种说法、或拆成子问题），每行一个，不要解释。
```

生成的多条 query 分别检索后合并，能覆盖“报销制度”“变化”“2024”等不同表述，减少漏检。

## 二、Prompt 工程实践：基于检索内容回答与拒答逻辑

生成阶段的 Prompt 需要做两件事：**明确要求模型只根据检索到的内容回答**，以及**在检索不到相关内容时拒绝作答**，从而控制幻觉、提高可验证性。

### 1. 结构化的 System Prompt 设计

建议在 System Prompt 中写清角色、输入格式和硬性规则，例如：

```text
你是基于公司知识库的问答助手。请严格依据【参考内容】回答问题。

规则：
1. 仅使用【参考内容】中的信息作答，不得编造或引用未出现的内容。
2. 若【参考内容】与用户问题无关或不足以回答问题，请明确说明“根据现有资料无法回答该问题”，并建议用户补充说明或联系相关部门。
3. 若参考内容中有明确出处（如页码、文档名），请在回答中通过 [1]、[2] 等形式标注引用（对应下方参考内容的编号）。
```

这样模型会倾向于“有据才答、无据拒答”，并在有依据时带上引用编号。

### 2. 把检索结果结构化放进 Prompt

在 User Message（或 Human Message）中，把检索到的 chunk 按编号列出，便于模型引用和核对：

```text
【参考内容】

[1] 来源：policy_2024.pdf 第 3 页
差旅报销每人每年上限为 5000 元，超出部分需提交特批申请……

[2] 来源：policy_2024.pdf 第 5 页
报销需在返回后 30 日内提交 OA 申请，并附票据……

【用户问题】
公司差旅报销上限是多少？多久内要提交？
```

要求模型“仅根据上述参考内容回答，并标注 [1][2]”，即可把“基于检索内容”和“引用归属”绑在一起。

### 3. “搜不到相关内容”时的拒答逻辑

- **判定方式**：可在检索后根据 Rerank 分数或相似度设定阈值，若 Top-N 条均低于阈值，则视为“无相关内容”；或在 Prompt 中提供一段占位内容如“【参考内容】暂无与当前问题直接相关的资料。”
- **Prompt 要求**：在 System 或 User 中明确写：“若参考内容为空或与问题无关，必须回答「根据现有资料无法回答该问题」，并不要猜测或编造。”
- **产品层**：前端可根据模型输出中的固定拒答话术（如“无法回答”“暂无相关资料”）展示为“未找到相关说明，请换一种方式提问或联系客服”等，提升体验。

这样既能减少幻觉，又能在知识库确实没有答案时给出清晰边界。

## 三、引用归属（Citations）实现：在回答中标注出处

让模型在回答里自动标注出处（如 [1]、[2]），可以增强**可信度和可追溯性**：用户和审核都能看到每句话对应哪一段资料。

### 1. 基本做法

- **检索阶段**：每条检索到的 chunk 带上唯一编号和来源信息（如 `[1] 来源：xxx.pdf 第 3 页`），如上节示例。
- **Prompt 要求**：在 System 或 User 中明确写“回答时请用 [1]、[2] 标注所依据的参考内容编号”。
- **模型输出**：模型在陈述某条事实时，在句末或句中加入 [1]、[2]，与【参考内容】的编号一一对应。

部分模型或产品会支持“输出时附带 citation 结构”（如 JSON 里单独一个 `citations` 数组），若 API 支持，可在解析时把 citation 映射到具体 chunk 和链接；若不支持，用“编号 [1][2] + 参考内容列表”的方式即可实现最小可用的引用归属。

### 2. 可选增强

- **后端映射**：若前端要展示“点击 [1] 跳转到某页”，可在保存 chunk 时记录 `doc_id`、`source`、`page` 等，返回给前端时把 [1]、[2] 映射到具体 URL 或预览信息。
- **校验**：对模型输出做简单校验，确保出现的 [n] 在参考内容编号范围内，避免幻觉引用；若发现越界或无效编号，可在后处理中剔除或替换为“出处不详”。

## 小结

| 学习点                      | 要点                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| **Query Transformation** | 用 LLM 把模糊提问改写成更利于检索的表述：**HyDE** 生成假设性答案再检索；**Multi-query** 生成多条 query 分别检索后合并；可组合使用以提升命中率。 |
| **Prompt 工程实践**          | 设计**结构化 System Prompt**：规定仅依据【参考内容】作答、无相关内容时**拒答**并说明；将检索结果按 [1][2] 编号写入 Prompt，便于引用与核查。   |
| **引用归属（Citations）**      | 检索结果带编号与来源；在 Prompt 中要求模型用 [1]、[2] 标注出处；后端可做编号与文档/页码的映射，供前端展示可点击引用。                        |

问题改写、Prompt 约束与引用归属三者配合，能让 RAG 在“问得准、答得准、有据可查”上更可控。
