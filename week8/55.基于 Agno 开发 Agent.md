# 55. 基于 Agno 开发 Agent

Day 54 用 LangChain 手写了 Agent 循环（bind_tools + while）并实现了多轮推理与工具调用。本节换一个框架：**Agno**。先说明 **Agno 的定位与基本用法**、与 LangChain 的差异与适用场景，再介绍**在 Agno 中定义 Agent、工具与执行流程**，并给出**一个完整 Agent 的端到端示例**，最后**对比 LangChain 与 Agno 的选型考量**。

环境要求：`agno`、`openai`（或其它 Agno 支持的模型依赖）、`python-dotenv`。本节示例需 `pip install agno`；若项目未包含，可单独安装后运行示例。

## 一、Agno 的定位与基本用法：与 LangChain 的差异与适用场景

### 1. Agno 是什么

**Agno** 是一个面向“可学习”的多智能体系统**的 Python 框架：强调 Agent 在多次交互中**记住用户、积累知识、从决策中学习，而不是“每次对话都从零开始”。核心特点包括：

- **学习能力**：通过 `learning=True` 或 `LearningMachine` 配置，Agent 可自动或通过工具**抽取并存储**用户画像、用户记忆、甚至跨用户共享的“学到的知识”，在后续会话中自动召回。
- **开箱即用的会话与持久化**：内置与 **db**（如 `SqliteDb`）的集成，用于存历史、用户画像、记忆；支持 **user_id**、**session_id** 做多用户与会话隔离。
- **模型无关**：支持 OpenAI、Anthropic、Google 及本地模型，通过统一接口切换。
- **工具与知识**：支持自定义工具（普通函数或 `@tool`）、内置 120+ 预置工具包（如 HackerNews）、知识库与向量存储集成、Guardrails 等。

### 2. 与 LangChain 的差异（简要）

| 维度          | LangChain                                                      | Agno                                                                                                           |
| ------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **抽象风格**  | 偏“积木”：Runnable、Tool、手写或 LangGraph 图组合成 Agent 循环 | 偏“一站式”：`Agent(model=..., tools=..., instructions=..., db=..., learning=...)` 即一个可运行、可学习的 Agent |
| **学习/记忆** | 需自建记忆层（如 Week 7 的 mem0 或自维护列表）并注入 Context   | 内置 learning、db、user/session 隔离，配置即可做用户记忆与跨会话召回                                           |
| **工具**      | `@tool` + `bind_tools`，自己写循环解析 tool_calls 并执行       | 工具以函数或 Toolkit 传入 `tools=[]`，框架内部完成“模型 → 工具 → 模型”的循环                                   |
| **适用场景**  | 需要精细控制每一步、或与 LangChain 生态（RAG、Chain）深度结合  | 快速搭建“带记忆、带工具”的 Agent，或做多智能体与生产运行时（AgentOS）                                          |

### 3. 基本用法（最小 Agent）

```python
from agno.agent import Agent
from agno.models.dashscope import DashScope

agent = Agent(model=model=DashScope(
        id="qwen-plus",
        base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    ))
agent.print_response("你好，介绍一下你自己。", stream=True)
```

不加工具时，就是一个“带对话能力”的 Agent；加上 **tools**、**instructions**、**db**、**learning** 即可扩展为带工具、带记忆、可学习的 Agent。

## 二、在 Agno 中定义 Agent、工具与执行流程

### 1. 定义 Agent

通过 **Agent** 类，传入 **model**、**tools**、**instructions**（系统级说明），以及可选的 **db**、**learning**、**session_state** 等：

```python
from agno.agent import Agent
from agno.models.dashscope import DashScope

agent = Agent(
    model=DashScope(
        id="qwen-plus",
        base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    ),
    tools=[get_weather, get_current_time],  # 见下
    instructions="你是助手。根据用户问题选择合适的工具获取信息，然后给出简洁回答。",
    markdown=True,
)
```

### 2. 定义工具

Agno 中**普通 Python 函数**即可作为工具：函数名与 **docstring**（含 **Args** 说明）会被自动转成模型所需的 **function/schema**，无需单独写 JSON schema 或 `@tool`（Agno 也支持 `@tool` 装饰器）。模型在推理时会输出 tool_calls，由框架执行并回传结果。

```python
def get_weather(city: str) -> str:
    """当用户询问某地天气时，使用此工具查询该城市的天气。
    Args:
        city (str): 要查询天气的城市名称。
    """
    # 实际项目里这里调真实 API
    return f"{city}：晴，25°C"

def get_current_time() -> str:
    """当用户问当前时间或日期时，使用此工具。"""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")
```

将上述函数放入 **tools=[...]** 即可；Agno 会负责“模型请求工具 → 执行 → 结果回传 → 模型继续”的循环，无需手写 while。

### 3. 执行流程：run / print_response

- **开发/调试**：**agent.print_response(message, user_id=..., session_id=..., stream=True)**，在终端打印回复与工具调用过程。
- **生产**：**agent.run(message, ...)** 或 **agent.arun(message, ...)**（异步），返回结构化输出（如 `RunOutput`），可从中取最终内容、工具调用记录等。

执行时，Agno 内部会：把 **instructions**、**工具定义**、**会话历史**（若配置了 db）与**当前用户输入**组装成上下文 → 调模型 → 若有 tool_calls 则执行工具并回传 → 再调模型，直到模型不再请求工具并返回最终回复。即 Day 51 所说的“推理 → 行动 → 观察 → 再推理”循环，由框架内置完成。

### 4. 学习与持久化

若希望 Agent **跨会话记住用户**，可加上 **db** 与 **learning**：

```python
from agno.db.sqlite import SqliteDb

agent = Agent(
    model=DashScope(
        id="qwen-plus",
        base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    ),
    tools=[get_weather],
    db=SqliteDb(db_file="tmp/agents.db"),
    learning=True,  # 自动抽取并存储用户画像、记忆，后续会话召回
    add_history_to_context=True,
)
agent.print_response("我叫小明，喜欢简洁回答。", user_id="user_1", session_id="s1", stream=True)
agent.print_response("你还记得我吗？", user_id="user_1", session_id="s2", stream=True)  # 新会话，仍可召回
```

## 三、实现一个完整 Agent 并跑通端到端

下面用 Agno 实现与 Day 54 类似的“天气 + 当前时间”Agent：两个工具、一段 instructions，跑通“用户输入 → 多轮推理与工具调用 → 最终回复”。

### 1. 完整示例代码（核心）

```python
from agno.agent import Agent
from agno.models.dashscope import DashScope
import os
from dotenv import load_dotenv
load_dotenv()

def get_weather(city: str) -> str:
    """当用户询问某地天气时，使用此工具查询该城市的天气。Args: city (str): 城市名称。"""
    fake_db = {"北京": "晴，25°C", "上海": "多云，22°C"}
    return fake_db.get(city, f"{city}：暂无数据")

def get_current_time() -> str:
    """当用户问当前时间或日期时，使用此工具。"""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

agent = Agent(
    model=DashScope(
        id="qwen-plus",
        base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    ),
    tools=[get_weather, get_current_time],
    instructions="你是助手。根据用户问题选择合适的工具获取信息，然后给出简洁回答。",
    markdown=True,
)

if __name__ == "__main__":
    agent.print_response("北京天气怎么样？现在几点了？", stream=True)
```

完整可运行脚本见 **`week8/55_code/agno_agent_demo.py`**（需先 `pip install agno`）。运行前请设置 **DASHSCOPE_API_KEY**（环境变量或 .env）。在项目根目录执行 `python week8/55_code/agno_agent_demo.py`，可尝试“上海天气”“现在几点”“先查深圳天气再告诉我时间”等，观察工具调用与最终回复。

### 2. 与 Day 54 的对应关系

| Day 54（LangChain）                                                        | Day 55（Agno）                                                             |
| -------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 用 @tool 定义工具，llm.bind_tools(tools)                                   | 用普通函数（或 @tool）定义工具，传入 Agent(tools=[...])                    |
| 手写 while：invoke → 解析 tool_calls → 执行 → 追加 ToolMessage → 再 invoke | Agent 内部完成“模型 → 工具 → 模型”循环，无需手写                           |
| System 与 messages 自己拼                                                  | instructions 即系统级说明；历史由 db + add_history_to_context 管理（可选） |
| 记忆需自建或接 mem0                                                        | learning=True + db 即可做用户记忆与跨会话召回（可选）                      |

## 四、对比 LangChain 与 Agno 的选型考量

| 考量维度           | LangChain                                                    | Agno                                                                           |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| **学习曲线与上手** | 概念多（Runnable、Chain、LangGraph），需理解“谁拼谁、谁调谁” | 一个 Agent 类配齐 model/tools/instructions/db/learning，上手快                 |
| **控制粒度**       | 高：每轮 messages、工具执行顺序、自定义循环都可自己写        | 中：循环与工具执行由框架包办，通过 instructions、工具设计、learning 配置调行为 |
| **记忆与学习**     | 需自建或集成 mem0 等，灵活但要自己设计写入/检索              | 内置 learning + db，适合“用户记忆、跨会话”场景，配置即用                       |
| **生态与集成**     | 与 LangChain 生态（RAG、Chain、LangSmith 等）结合紧密        | 自带知识库、Guardrails、多智能体与 AgentOS 运行时，偏“全家桶”                  |
| **生产与运维**     | 需自建部署与可观测；或配合 LangSmith 等                      | 提供 AgentOS 运行时与 UI 控制面，适合“快速上线、统一运维”                      |

**简单建议**：若你更需要**精细控制**、或已有大量 LangChain/LangGraph 代码与生态，优先 LangChain；若你希望**快速做出“带工具、带记忆”的 Agent** 或考虑**多智能体与生产运行时**，可优先尝试 Agno。两者都符合 Day 51 的“大脑 + 工具 + 记忆与上下文 + 循环”的组成模型，只是抽象层次与默认能力不同。

## 小结

| 学习点                  | 要点                                                                                                                |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **Agno 的定位**         | 面向“可学习”的多智能体框架；内置学习/记忆、db、user/session 隔离；模型无关；工具与知识开箱可用。                    |
| **与 LangChain 的差异** | LangChain 偏积木与可控循环；Agno 偏一站式 Agent + 内置学习与执行循环。                                              |
| **定义 Agent 与工具**   | Agent(model=..., tools=[...], instructions=..., db=..., learning=...)；工具为普通函数（docstring + Args）或 @tool。 |
| **执行流程**            | print_response 开发调试，run/arun 生产；框架内部完成“模型 → 工具 → 模型”循环。                                      |
| **选型**                | 要精细控制与 LangChain 生态选 LangChain；要快速带记忆、带工具或生产运行时可选 Agno。                                |
