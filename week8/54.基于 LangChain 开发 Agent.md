# 54. 基于 LangChain 开发 Agent

Day 51 把 Agent 的组成与数据流讲清了，Day 53 梳理了失败模式。本节用 **LangChain** 把“多轮推理与工具调用”落到代码：先理清 **Runnable、Tool、Agent 循环** 在 LangChain 中的对应关系，再完成**工具定义与绑定**、**完整 Agent 循环**（接收用户输入 → 多轮推理与工具调用 → 返回最终结果），并简要说明如何与**上下文、记忆**衔接。

环境要求：`langchain-core`、`langchain-openai`（或其它兼容的 Chat 模型）、`python-dotenv`。可选：若使用 LangGraph 预置 Agent，需 `langgraph` / `langgraph-prebuilt`。

## 一、LangChain / LangGraph 中的 Agent 抽象：Runnable、Tool、循环

### 1. Runnable

在 LangChain 里，**Runnable** 是“可链式调用”的抽象：`invoke(input)` 进、结果出。LLM、Tool、以及“先调 LLM 再根据输出调工具”的**组合**，都可以是 Runnable。Agent 的“多轮循环”本质上是一个 **Runnable**：输入当前 messages，输出下一轮 messages 或最终结果；内部要么手写循环（见下），要么用 **LangGraph** 的图（节点 + 边）描述“模型节点 → 工具节点 → 再回模型”的流程。

### 2. Tool

**Tool** 是对“可被模型调用的能力”的封装：**名称 + 描述（description）+ 参数 schema**。LangChain 里常用 `@tool` 装饰器或 `StructuredTool.from_function` 把 Python 函数变成 Tool；模型通过 **tool_calls** 指定要调用的工具与参数，运行时根据名称找到对应 Tool 并执行，结果封装成 **ToolMessage** 回传给模型。对应 Day 51 的“工具：感知与行动的外延”。（Week 4 的 Day 24 已详细讲工具定义与 `bind_tools`，此处只做串联。）

### 3. Agent 循环与 AgentExecutor / LangGraph

- **经典 LangChain 写法**：用 **AgentExecutor** 包住一个“Agent”（例如由 `create_tool_calling_agent` 生成的 Runnable），由 Executor 负责“调用 Agent → 若有 tool_calls 则执行工具 → 把 ToolMessage 拼回 → 再调 Agent”的循环，直到 Agent 返回 `AgentFinish`（无 tool_calls）。这类 API 在部分版本中位于 `langchain` 或 `langchain_community`。
- **LangGraph 写法（当前推荐）**：用 **create_react_agent**（来自 `langgraph-prebuilt`）构建一个**图**：节点包括“模型”和“工具”，边描述“模型 → 工具 → 模型”的流转；编译后的图就是一个“带循环的 Runnable”，输入 messages、输出最终 messages。无需自己写 while 循环。
- **本节采用**：为减少对额外包的依赖并突出“循环在做什么”，下面用 **手写 Agent 循环**：`llm.bind_tools(tools)` 得到支持 tool_calls 的模型，然后 **while** “调用模型 → 若有 tool_calls 则执行并追加 ToolMessage → 再调用”，直到没有 tool_calls 或达到最大步数。逻辑与 Day 51 的数据流一致，且与 Week 7 的“仅用 core + openai”风格统一。

### 4. 小结表

| 概念                | 在 LangChain 中的体现                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| **Runnable**      | LLM、Tool、以及“Agent 循环”都可视为 Runnable；invoke 进、结果出。                                                               |
| **Tool**          | `@tool` 或 StructuredTool；名称 + 描述 + 参数 schema；执行后得到 ToolMessage。                                                |
| **Agent 循环**      | 手写：bind_tools + while（invoke → 执行 tool_calls → 追加 ToolMessage → 再 invoke）。或使用 LangGraph create_react_agent 的图。 |
| **AgentExecutor** | 经典 LangChain 中负责驱动“Agent + 工具执行”循环的组件；新项目可优先考虑 LangGraph。                                                      |

## 二、工具的定义、绑定与调用流程

### 1. 定义工具

用 `@tool` 或 `StructuredTool.from_function` 将函数暴露为 Tool；**函数的 docstring 会变成模型的工具描述**，参数类型会生成 schema。名称、描述写清楚，模型才能选对、填对（见 Day 53）。

```python
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """当用户询问某地天气时，使用此工具查询该城市的天气。"""
    # 实际项目里这里调真实 API
    return f"{city}：晴，25°C"

@tool
def get_current_time() -> str:
    """当用户问当前时间或日期时，使用此工具。"""
    from datetime import datetime
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")
```

### 2. 绑定到模型

用 **`llm.bind_tools(tools)`** 得到“带工具能力”的模型；调用时会把工具 schema 注入到请求中，模型可返回 **tool_calls**。

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="qwen-plus", base_url="https://dashscope.aliyuncs.com/compatible-mode/v1")
tools = [get_weather, get_current_time]
llm_with_tools = llm.bind_tools(tools)
tool_map = {t.name: t for t in tools}
```

### 3. 调用流程（单轮）

- 用 **messages**（如 `[HumanMessage(content=用户输入)]`）调用 `llm_with_tools.invoke(messages)`。
- 若返回的 **AIMessage** 带 **tool_calls**，则遍历每个 call：用 `tool_map[call["name"]]` 找到 Tool，`tool.invoke(call["args"])` 执行，用 **ToolMessage(content=str(result), tool_call_id=call["id"])** 收集结果。
- 将 **AIMessage** 与所有 **ToolMessage** 追加到 messages，再次 **invoke**；重复直到返回的 AIMessage 无 tool_calls，其 **content** 即为最终回复。

## 三、实现一个完整 Agent：接收用户输入 → 多轮推理与工具调用 → 返回最终结果

下面用**手写循环**实现完整 Agent：支持多轮 tool_calls、最大步数、以及可选的 System 与历史（为与上下文、记忆衔接留口子）。

### 1. 核心循环逻辑

```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage, ToolMessage

def run_agent(user_input: str, system: str | None = None, max_steps: int = 10) -> str:
    messages = []
    if system:
        messages.append(SystemMessage(content=system))
    messages.append(HumanMessage(content=user_input))

    for _ in range(max_steps):
        response = llm_with_tools.invoke(messages)
        messages.append(response)

        if not response.tool_calls:
            return response.content

        for call in response.tool_calls:
            tool = tool_map[call["name"]]
            result = tool.invoke(call.get("args", {}))
            messages.append(
                ToolMessage(content=str(result), tool_call_id=call["id"])
            )

    return "达到最大步数，未得到最终回复。"
```

- **输入**：用户文本、可选 System、可选“历史 messages”。
- **终止**：本轮响应无 `tool_calls` 时返回 `response.content`；或达到 `max_steps` 时返回提示信息。

### 2. 与上下文、记忆的衔接

- **上下文（历史）**：若希望 Agent 带“会话历史”，可在首轮或每轮拼消息时，把**此前几轮的 HumanMessage、AIMessage**（以及中间的 ToolMessage）按时间顺序拼在 **System Prompt 之后、当前 HumanMessage 之前**；注意 token 上限，可只保留最近 K 轮（对应 Week 6 的时间窗口）。
- **记忆**：若已接入记忆系统（Week 7），可在**拼首轮 messages 前**按 user_id 检索相关记忆，把结果拼成一段“用户记忆：……”放入 **System Prompt** 或单独一条系统/用户消息；任务结束后可按策略写入记忆。这样 Agent 的“感知”里就包含长期记忆。

完整可运行示例见 **`week8/54_code/langchain_agent_demo.py`**：包含两个工具（天气、当前时间）、System Prompt提示、最大步数，以及一个简单的主循环读用户输入并打印最终回复。

## 四、完整可运行示例说明

脚本 **`week8/54_code/langchain_agent_demo.py`** 实现：

1. 定义 **get_weather**、**get_current_time** 两个工具并 **bind_tools**。
2. **run_agent(user_input, system=..., max_steps=10)**：拼 System（若有）+ HumanMessage；循环 invoke → 若有 tool_calls 则执行并追加 ToolMessage → 再 invoke，直到无 tool_calls 或达 max_steps。
3. 主循环：读用户输入，调用 **run_agent**，打印最终回复；输入 `quit` 退出。

运行前请在项目根目录配置 `.env` 中的 `OPENAI_API_KEY`，在项目根目录执行：

```bash
python week8/54_code/langchain_agent_demo.py
```

可尝试：“北京天气怎么样？”、“现在几点了？”、“先查上海天气再告诉我现在时间”等，观察多步调用与最终回复。

## 小结

| 学习点                        | 要点                                                                                                                     |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Runnable、Tool、Agent 循环** | Runnable 为可 invoke 的抽象；Tool 为名称+描述+参数；Agent 循环可手写（bind_tools + while）或使用 LangGraph create_react_agent。                 |
| **工具定义与绑定**                | @tool 定义工具，llm.bind_tools(tools) 绑定；调用后解析 tool_calls、执行并构造 ToolMessage 回传。                                             |
| **完整 Agent**               | 用户输入 → System Prompt（可选）+ messages → 循环：invoke → 执行 tool_calls → 追加 ToolMessage → 再 invoke，直到无 tool_calls 或 max_steps。 |
| **与上下文、记忆衔接**              | 历史 messages 按时间窗口拼入；记忆检索结果注入 System 或首轮上下文；任务结束后可写记忆。                                                                  |
