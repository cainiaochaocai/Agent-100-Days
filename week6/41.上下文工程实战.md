# 41. 上下文工程实战

前面几节把**什么是上下文、组成与优先级、多轮膨胀、裁剪与压缩、检索结果怎么进上下文**都讲过了，本节用 **LangChain** 做一版能跑起来的**多轮对话 + 上下文管理**，亲手体会：**每一拍塞进哪些消息、时间窗口怎么裁、参考内容放在哪**。

目标有三：

1. **组装“一拍”的 Context**：用 LangChain 的 `SystemMessage` / `HumanMessage` / `AIMessage` 拼出「System + 历史 + 当前问题」（可选加「参考内容」），对应 Day 37 的组成与顺序。
2. **时间窗口**：只保留**最近 K 轮**历史，超出部分不塞进本次请求，对应 Day 38、39。
3. **模拟 RAG 注入**：把「参考内容」放在当前用户问题**之前**、同一条 `HumanMessage` 里，对应 Day 40 的放置方式。

环境要求：`langchain`、`langchain-openai`（或其它 LangChain 兼容的 Chat 模型）、`python-dotenv`、`tiktoken`（用于估 token）。项目里已包含这些依赖。

## 一、用 LangChain 组装“一拍”的 Context

在 LangChain 里，一次调用的输入就是 **message 列表**。每一拍你构造的 `messages`，就是 Day 36 说的「一次 LLM 调用的全部可见输入」。

- **System**：`SystemMessage(content="...")`
- **历史**：若干对 `HumanMessage`、`AIMessage`
- **当前用户输入**：一条 `HumanMessage(content=用户本轮的输入)`

若本轮有“参考内容”（例如 RAG 检索结果），就按 Day 37、40 的约定，把参考内容放在**当前问题前面**，拼成一条 `HumanMessage`，例如：

```python
content = "【参考内容】\n" + ref_text + "\n\n【用户问题】\n" + user_input
HumanMessage(content=content)
```

这样模型看到的顺序是：System → 历史 → 参考内容+当前问题，**当前问题在最后**，便于以问题为锚点生成。

下面示例：先不用 RAG，只做「System + 历史 + 当前问题」的组装，并只保留**最近 3 轮**历史（时间窗口 K=3）。

## 二、时间窗口：只保留最近 K 轮

历史存在一个列表里，每轮追加 `HumanMessage` 和 `AIMessage`。在**发起本次调用前**，不把整段历史都塞进去，而是只取**最近 K 轮**（每轮 = 1 条 user + 1 条 assistant）。

例如 `history` 里有 10 条（5 轮），K=3 时只取最后 6 条（3 轮），和 System、当前 `HumanMessage` 一起组成本拍的 `messages`。这样：

- 总 token 受控，不会随轮数线性爆炸；
- 指代和话题主要依赖最近几轮，一般够用。

实现上就是切片：`recent = history[-(2*K):]`（每轮 2 条消息）。

## 三、注入“参考内容”并控制顺序

模拟 RAG：不接真实向量库，用一段**固定的参考文本**（例如报销制度的两句话）当作本轮的“检索结果”。在拼**当前轮**的 `HumanMessage` 时，把这段参考放在用户问题前面：

```python
REF = """[1] 差旅报销每人每年上限 5000 元，超出需特批。
[2] 报销需在返回后 30 日内提交 OA。"""

def build_user_message(user_input: str, ref: str | None = None) -> HumanMessage:
    if ref:
        content = f"【参考内容】\n{ref}\n\n【用户问题】\n{user_input}"
    else:
        content = user_input
    return HumanMessage(content=content)
```

这样本轮请求里，**参考内容 + 用户问题**作为同一条 user 消息，且位于历史之后，符合「参考在前、问题在后」的推荐结构。

## 四、估 token 与超限时的裁剪

用 `tiktoken` 可以估算当前 `messages` 的总 token 数（按 OpenAI 的编码方式，其它模型可换编码器）。若超过你设定的上限（如 4000），可以按 Day 37 的**优先级**从历史里再裁：先保证当前问题、System、参考内容（若有），再保留最近 1 ～ 2 轮，更早的整轮丢弃，直到总 token 低于上限。实战代码里可以加一个 `trim_history_to_fit(messages, max_tokens)`，按整轮从**最早**的历史开始删。

## 五、完整可运行示例

完整脚本已放在 **`week6/41_code/context_engineering_demo.py`**，可直接运行。下面为实现要点示意（多轮对话 + System + 时间窗口最近 3 轮 + 可选参考内容注入 + token 估算）。

```python
# 核心逻辑示意，完整可运行代码见 week6/41_code/context_engineering_demo.py
import os
from dotenv import load_dotenv
load_dotenv()

from langchain_core.messages import SystemMessage, HumanMessage, AIMessage
from langchain_openai import ChatOpenAI
import tiktoken

llm = ChatOpenAI(model="qwen-plus", base_url="https://dashscope.aliyuncs.com/compatible-mode/v1")

SYSTEM = "你是公司知识库助手。若存在【参考内容】，请仅根据参考内容回答，并尽量简洁；无法从资料得出时请说明。"
REF_SAMPLE = """[1] 差旅报销每人每年上限 5000 元，超出需特批。
[2] 报销需在返回后 30 日内提交 OA。"""

def keep_last_k_turns(history: list, k: int):
    """只保留最近 k 轮（每轮 2 条：user + assistant）。"""
    return history[-(2 * k) :] if len(history) >= 2 * k else history

def count_tokens(messages: list, model: str = "gpt-4o-mini") -> int:
    try:
        enc = tiktoken.encoding_for_model(model)
    except Exception:
        enc = tiktoken.get_encoding("cl100k_base")
    total = 0
    for m in messages:
        total += len(enc.encode(m.content if hasattr(m, "content") else str(m)))
    return total

def build_messages(history: list, user_input: str, ref: str | None, k: int = 3) -> list:
    window = keep_last_k_turns(history, k)
    if ref:
        user_content = f"【参考内容】\n{ref}\n\n【用户问题】\n{user_input}"
    else:
        user_content = user_input
    return [SystemMessage(content=SYSTEM)] + window + [HumanMessage(content=user_content)]

def main():
    history = []
    print("输入 'ref' 开启本轮参考内容注入，'quit' 退出。\n")
    while True:
        user_input = input("你: ").strip()
        if not user_input:
            continue
        if user_input.lower() == "quit":
            break
        use_ref = user_input.lower() == "ref"
        if use_ref:
            user_input = input("（请再输入问题）你: ").strip()
        ref = REF_SAMPLE if use_ref else None
        messages = build_messages(history, user_input, ref, k=3)
        n_tokens = count_tokens(messages)
        print(f"[Context 约 {n_tokens} token，历史仅保留最近 3 轮]\n")
        resp = llm.invoke(messages)
        history.append(HumanMessage(content=user_input))
        history.append(AIMessage(content=resp.content))
        print("助手:", resp.content, "\n")

if __name__ == "__main__":
    main()
```

**使用方法**

- 在项目根目录：`python week6/41_code/context_engineering_demo.py`（或先 `cd week6/41_code` 再 `python context_engineering_demo.py`，需保证能读到根目录的 `.env`）。
- 正常输入问题：助手按“无参考内容”回答；输入 `ref` 再输入问题：本轮会注入上面的报销制度两句话，助手应能答出“5000 元”“30 日内”。
- 多轮几句后再问“那住宿标准呢？”：因为历史里保留了最近 3 轮，模型能接上话题；若你改成 `k=0` 再跑，就不会带历史，模型不知道“那”指什么。

## 六、把上下文工程封装成 LangChain 中间层（middleware）

上面的 demo 还是“手写 messages，再自己调一次 LLM”。在真实项目里，一般会把这套「收集信息 → 拼 Context → 调模型」封成一个**中间层（middleware）**，上游只管传“用户意图 + 历史 + 外部来源”，下游只管收 `messages` 或最终回复。

可以粗略理解成三段：

```text
用户输入 / 事件
    ↓
上下文中间层（Context Middleware）
    - 读取历史（Memory / 自维护的 history 列表）
    - 视情况从文件系统 / 向量库拿片段
    - 做裁剪 / 摘要 / 排序
    - 拼成 messages
    ↓
LLM（ChatOpenAI 等）
```

### 1. 一个最小版的「上下文中间层」设计

先不引入复杂的 Runnable，最小版可以就是一个函数：

```python
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

SYSTEM = "你是公司知识库助手……"

def context_middleware(user_input: str, history: list, fs_refs: list[str] | None = None, k: int = 3):
    """根据用户输入、历史和文件系统片段，拼出本拍要发给 LLM 的 messages。"""
    # 1. 时间窗口：只取最近 k 轮
    window = history[-(2 * k):] if k > 0 else []

    # 2. 文件系统片段（比如 skills/ 里读出来的几段说明）
    ref_block = "\n\n".join(fs_refs) if fs_refs else ""

    if ref_block:
        content = f"【参考内容】\n{ref_block}\n\n【用户问题】\n{user_input}"
    else:
        content = user_input

    messages = [SystemMessage(content=SYSTEM)] + window + [HumanMessage(content=content)]
    return messages
```

业务侧只需要：维护好 `history`，决定何时读哪些文件系统片段 (`fs_refs`)，再调用这个函数拿到 `messages` 去调 LLM。以后加时间窗口、裁剪、摘要、RAG、文件系统片段，都集中改这一处。

### 2. 基于文件系统的中间件：读技能 / 规则进 Context

结合 Day 40「基于文件系统的上下文工程」，可以在 middleware 里直接挂上一层文件系统 loader，比如按 Agent / 模块读对应技能文件：

```python
from pathlib import Path

BASE = Path(__file__).resolve().parent.parent  # 项目根目录

SKILL_MAP = {
    "pdf": BASE / "skills" / "pdf-processing" / "SKILL.md",
    "web": BASE / "skills" / "web-article-summarizer" / "SKILL.md",
}

def load_fs_refs(mode: str | None) -> list[str]:
    if not mode or mode not in SKILL_MAP:
        return []
    path = SKILL_MAP[mode]
    text = path.read_text(encoding="utf-8")
    # 这里可以只取前几节，或再做一次摘要
    return [text]
```

然后调用时，根据当前任务选择要读的技能，把它们作为 `fs_refs` 传给 `context_middleware`：

```python
mode = "pdf"  # 例如根据路由 / Agent 类型决定
fs_refs = load_fs_refs(mode)
messages = context_middleware(user_input, history, fs_refs=fs_refs, k=3)
resp = llm.invoke(messages)
```

这样就实现了一个基于文件系统的上下文中间层：上游只管说“我要 pdf 相关的技能”，中间层负责“读文件 + 选片段 + 拼参考内容”，下游 LLM 看到的仍然只是一串 messages。

## 小结

- **Context = 本拍发出去的 message 列表**：在 LangChain 里就是 `[SystemMessage, ...history..., HumanMessage]`，可选地在最后一条 `HumanMessage` 里带上「参考内容 + 用户问题」。
- **时间窗口**：历史只取最近 K 轮再拼进 messages，控制膨胀；K 可按业务调（如 3 ～ 5）。
- **参考内容**：放在当前问题**之前**、同一段 user 内容里，且建议条数/总长有上限（本节示例只用了 2 条），对应 Day 40 的“少而精”。
- **可选**：用 tiktoken 估 token，超限时按优先级从历史里按轮裁剪，保证当前问题与 System 不丢。
