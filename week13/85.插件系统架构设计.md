# 85. 插件系统架构设计

Week 12 我们搭建了 Gateway + Runtime 的核心架构。但若每次新增工具、记忆后端、LLM 提供者或通道都要改核心代码，系统会难以扩展。本节引入**插件系统**：**插件接口设计**（ProviderPlugin、ToolPlugin、MemoryPlugin、ChannelPlugin）、**插件生命周期**（注册、加载、卸载、热更新），以及**插件依赖与版本管理**（插件间依赖、版本兼容性、向后兼容策略）。OpenClaw 的 [Hook 与插件注入框架](https://openclaw-docs.dx3n.cn/beginner-openclaw-framework-focus/14-AI-Hook%E4%B8%8E%E6%8F%92%E4%BB%B6%E6%B3%A8%E5%85%A5%E6%A1%86%E6%9E%B6%E5%8E%9F%E7%90%86%E4%B8%8E%E5%AE%9E%E7%8E%B0) 与 [多插件冲突治理与优先级规范](https://openclaw-docs.dx3n.cn/beginner-openclaw-framework-focus/15-%E5%A4%9A%E6%8F%92%E4%BB%B6%E5%86%B2%E7%AA%81%E6%B2%BB%E7%90%86%E4%B8%8E%E4%BC%98%E5%85%88%E7%BA%A7%E8%A7%84%E8%8C%83%E5%AE%9E%E6%88%98) 提供了「可扩展但不失控」的工程结构参考。

## 一、插件接口设计：ProviderPlugin、ToolPlugin、MemoryPlugin、ChannelPlugin

### 1. ProviderPlugin（LLM 提供者）

- **职责**：统一 LLM 调用接口，支持多模型切换（OpenAI、DashScope、本地模型等）。
- **接口**：
  - `invoke(messages, **kwargs)` → 返回模型响应（含 tool_calls）
  - `stream(messages, **kwargs)` → 流式返回（可选）
  - `get_model_info()` → 返回模型信息（名称、版本、能力描述）
- **作用**：Runtime 通过 ProviderPlugin 调用 LLM，无需关心底层是哪个 API 或本地模型。

### 2. ToolPlugin（工具扩展）

- **职责**：工具插件的注册、发现、执行；工具元数据（名称、描述、参数 schema、权限要求）。
- **接口**：
  - `get_tools()` → 返回工具列表（Tool 对象或 schema）
  - `execute(tool_name, args)` → 执行工具，返回结果
  - `get_tool_schema(tool_name)` → 返回工具 schema
- **作用**：新增工具只需实现 ToolPlugin，无需修改 Runtime 核心代码。

### 3. MemoryPlugin（记忆后端）

- **职责**：记忆后端的抽象接口（写入、检索、更新、删除）；支持多种后端（内存、数据库、向量库）。
- **接口**：
  - `write(user_id, content, metadata)` → 写入记忆
  - `retrieve(user_id, query, limit)` → 检索记忆
  - `update(memory_id, updates)` → 更新记忆
  - `delete(memory_id)` → 删除记忆
- **作用**：Runtime 通过 MemoryPlugin 访问记忆，可切换不同后端（内存、SQLite、向量库）而不改代码。

### 4. ChannelPlugin（通道）

- **职责**：通道接口（接收消息、发送响应、状态同步）；实现 CLI 通道与 Web 通道（简化版）。
- **接口**：
  - `receive()` → 接收用户消息（阻塞或异步）
  - `send(user_id, message)` → 发送响应给用户
  - `get_user_id()` → 获取当前用户 ID
  - `get_channel_info()` → 返回通道信息（类型、标识）
- **作用**：Gateway 通过 ChannelPlugin 接入不同通道，统一处理多端请求。

### 5. 小结表

| 插件类型       | 职责                         | 接口示例                     |
| -------------- | ---------------------------- | ---------------------------- |
| **ProviderPlugin** | 统一 LLM 调用接口           | `invoke(messages)`、`stream(messages)` |
| **ToolPlugin** | 工具扩展                     | `get_tools()`、`execute(name, args)` |
| **MemoryPlugin** | 记忆后端抽象                 | `write(...)`、`retrieve(...)` |
| **ChannelPlugin** | 通道接口                     | `receive()`、`send(user_id, message)` |

## 二、插件生命周期：注册、加载、卸载、热更新

### 1. 注册

- **含义**：插件实现后，需要**注册到平台**，平台才能发现并使用。
- **方式**：
  - **静态注册**：在配置文件中列出插件路径，启动时加载。
  - **动态注册**：运行时通过 API 或命令行注册插件（如 `plugin.register("path/to/plugin.py")`）。
- **元数据**：注册时需提供插件元数据（名称、版本、类型、依赖、作者等）。

### 2. 加载

- **含义**：平台启动或运行时，**加载插件**：导入插件模块、初始化插件实例、注册到对应管理器（如 ToolRegistry、MemoryManager）。
- **时机**：
  - **启动时加载**：平台启动时加载所有已注册插件。
  - **按需加载**：首次使用时才加载（懒加载），减少启动时间。
- **错误处理**：加载失败应记录错误但不影响平台启动，可提供“禁用该插件”的选项。

### 3. 卸载

- **含义**：运行时**卸载插件**，停止使用该插件的能力。
- **场景**：插件出错、需要更新、或用户禁用。
- **实现**：从管理器移除插件、清理资源、通知相关组件（如 Runtime 不再使用该工具）。

### 4. 热更新

- **含义**：**不重启平台**的情况下更新插件（如更新工具逻辑、修复 bug）。
- **实现**：先加载新版本插件，再卸载旧版本，最后注册新版本；或支持“版本切换”（保留多个版本，运行时切换）。
- **限制**：热更新可能影响正在执行的请求，需要谨慎处理（如等待当前请求完成再更新）。

### 5. 小结表

| 生命周期 | 含义                     | 实现方式                         |
| -------- | ------------------------ | -------------------------------- |
| **注册** | 插件注册到平台           | 配置文件或运行时 API             |
| **加载** | 平台加载插件并初始化     | 启动时加载或按需加载             |
| **卸载** | 运行时移除插件           | 从管理器移除、清理资源           |
| **热更新** | 不重启平台更新插件       | 加载新版本 → 卸载旧版本 → 注册新版本 |

## 三、插件依赖与版本管理：插件间依赖、版本兼容性、向后兼容策略

### 1. 插件间依赖

- **含义**：一个插件可能**依赖另一个插件**（如某个 ToolPlugin 依赖特定的 MemoryPlugin 来存储工具调用历史）。
- **管理**：插件元数据中声明依赖（如 `dependencies: ["memory_sqlite"]`），平台加载时检查依赖是否满足。
- **加载顺序**：按依赖关系排序，先加载被依赖的插件，再加载依赖它的插件。

### 2. 版本兼容性

- **含义**：插件有**版本号**（如 `1.0.0`），平台需要检查插件版本是否与平台版本兼容。
- **检查**：平台声明“支持的插件版本范围”（如 `tool_plugin >= 1.0.0, < 2.0.0`），加载时校验。
- **不兼容处理**：版本不兼容时拒绝加载，并提示用户更新插件或平台。

### 3. 向后兼容策略

- **含义**：平台升级后，**旧版本插件**应仍能工作（向后兼容），或提供迁移路径。
- **策略**：
  - **接口版本化**：插件接口支持多版本（如 `v1`、`v2`），旧插件用 v1，新插件用 v2。
  - **适配层**：平台提供适配层，将旧接口调用转换为新接口。
  - **迁移工具**：提供工具帮助插件作者迁移到新版本接口。

### 4. 小结

| 概念         | 含义                           | 管理方式                     |
| ------------ | ------------------------------ | ---------------------------- |
| **插件依赖** | 插件间依赖关系                 | 元数据声明、加载时检查       |
| **版本兼容性** | 插件版本与平台版本的兼容性     | 版本范围检查、不兼容时拒绝   |
| **向后兼容** | 平台升级后旧插件仍能工作       | 接口版本化、适配层、迁移工具 |

## 四、代码示例：插件接口与 PluginManager

以下来自 **`week13/90_code/platform_with_plugins_demo.py`**。抽象基类定义统一接口，PluginManager 负责注册与获取。

```python
from abc import ABC, abstractmethod

class BaseProviderPlugin(ABC):
    @abstractmethod
    def invoke(self, messages: list, **kwargs) -> Any: ...
    def bind_tools(self, tools: list) -> Any: ...
    def get_model_info(self) -> dict: ...

class BaseToolPlugin(ABC):
    @abstractmethod
    def get_tools(self) -> list: ...
    @abstractmethod
    def execute(self, tool_name: str, args: dict) -> str: ...

class BaseMemoryPlugin(ABC):
    @abstractmethod
    def write(self, user_id: str, content: str, metadata: dict | None = None) -> str: ...
    @abstractmethod
    def retrieve(self, user_id: str, query: str, limit: int = 10) -> list[dict]: ...

class BaseChannelPlugin(ABC):
    @abstractmethod
    def receive(self) -> tuple[str, str, str | None]: ...  # (user_id, message, session_id?)
    @abstractmethod
    def send(self, user_id: str, message: str) -> None: ...
```

PluginManager 注册与获取（启动时加载、按类型管理）：

```python
class PluginManager:
    def register_provider(self, name: str, plugin: BaseProviderPlugin) -> None: ...
    def get_provider(self, name: str | None = None) -> BaseProviderPlugin | None: ...
    def register_tool_plugin(self, plugin: BaseToolPlugin) -> None: ...
    def get_all_tools(self) -> list: ...
    def execute_tool(self, tool_name: str, args: dict) -> str: ...
    def register_memory(self, plugin: BaseMemoryPlugin) -> None: ...
    def get_memory(self) -> BaseMemoryPlugin | None: ...
    def register_channel(self, name: str, plugin: BaseChannelPlugin) -> None: ...
    def get_channel(self, name: str) -> BaseChannelPlugin | None: ...
```
