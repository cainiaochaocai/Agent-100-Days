## 一、MemoryPlugin：记忆后端的抽象接口（写入、检索、更新、删除）

### 1. 接口设计

- **BaseMemoryPlugin**：定义统一接口
  - `write(user_id, content, metadata)` → 写入记忆，返回 memory_id
  - `retrieve(user_id, query, limit)` → 检索记忆，返回相关记忆列表
  - `update(memory_id, updates)` → 更新记忆（内容、元数据）
  - `delete(memory_id)` → 删除记忆
  - `get_memory(memory_id)` → 查询单个记忆
  - `list_memories(user_id, filters)` → 列出用户的所有记忆（可选过滤）

### 2. 实现示例：SQLiteMemoryPlugin

- **存储**：用 SQLite 存储记忆，表结构：memory_id、user_id、content、metadata（JSON）、created_at、updated_at。
- **检索**：简化版用全文搜索（SQLite FTS）或关键词匹配；完整版可用向量检索（Week 7 的向量库）。
- **实现**：
  ```python
  class SQLiteMemoryPlugin(BaseMemoryPlugin):
      def __init__(self, db_path):
          self.db = sqlite3.connect(db_path)
          self._init_table()
      
      def write(self, user_id, content, metadata):
          cursor = self.db.execute(
              "INSERT INTO memories (user_id, content, metadata) VALUES (?, ?, ?)",
              (user_id, content, json.dumps(metadata))
          )
          return cursor.lastrowid
      
      def retrieve(self, user_id, query, limit=10):
          # 简化版：关键词匹配
          rows = self.db.execute(
              "SELECT * FROM memories WHERE user_id = ? AND content LIKE ? LIMIT ?",
              (user_id, f"%{query}%", limit)
          )
          return [dict(row) for row in rows]
  ```

### 3. 实现示例：InMemoryMemoryPlugin（简化版）

- **存储**：用内存字典存储记忆，适合开发与测试。
- **实现**：`memories = {}`，key 为 memory_id，value 为记忆内容与元数据。

### 4. Runtime 接入

- **方式**：Runtime 的 ContextBuilder 通过 MemoryManager 获取 MemoryPlugin，调用 `retrieve(user_id, query)` 检索记忆，将结果注入上下文。
- **时机**：在组装上下文时，根据用户请求检索相关记忆，追加到 System 或首轮 UserMessage。

### 5. 小结表

| 方法         | 含义                     | 参数                           |
| ------------ | ------------------------ | ------------------------------ |
| **write**    | 写入记忆                 | user_id, content, metadata      |
| **retrieve** | 检索记忆                 | user_id, query, limit           |
| **update**   | 更新记忆                 | memory_id, updates              |
| **delete**   | 删除记忆                 | memory_id                       |
| **list_memories** | 列出用户的所有记忆   | user_id, filters                |

## 二、ChannelPlugin：通道接口（接收消息、发送响应、状态同步）

### 1. 接口设计

- **BaseChannelPlugin**：定义统一接口
  - `receive()` → 接收用户消息（阻塞或异步），返回 (user_id, message, session_id?)
  - `send(user_id, message)` → 发送响应给用户
  - `get_user_id()` → 获取当前用户 ID（若通道支持）
  - `get_channel_info()` → 返回通道信息（类型、标识）
  - `start()` → 启动通道（如启动 Web 服务器、CLI 循环）
  - `stop()` → 停止通道

### 2. 实现示例：CLIChannelPlugin

- **功能**：命令行通道，用户通过终端输入，Agent 通过终端输出。
- **实现**：
  ```python
  class CLIChannelPlugin(BaseChannelPlugin):
      def __init__(self):
          self.user_id = "cli_user"
      
      def receive(self):
          user_input = input("你: ").strip()
          return (self.user_id, user_input, None)
      
      def send(self, user_id, message):
          print(f"助手: {message}")
      
      def start(self):
          print("CLI 通道已启动，输入 quit 退出")
          while True:
              user_id, message, _ = self.receive()
              if message.lower() in ("quit", "exit"):
                  break
              # Gateway 会处理消息并调用 send
  ```

### 3. 实现示例：WebChannelPlugin（简化版）

- **功能**：Web 通道，用户通过浏览器访问，Agent 通过 HTTP/WebSocket 返回响应。
- **实现**：用 Flask 或 FastAPI 实现 HTTP 接口
  - `POST /api/chat` → 接收用户消息，返回响应
  - `GET /api/sessions/{session_id}` → 查询会话历史
  - WebSocket `/ws` → 支持流式响应（可选）

### 4. Gateway 接入

- **方式**：Gateway 通过 ChannelManager 管理多个 ChannelPlugin，每个通道独立运行（如 CLI 在终端、Web 在 HTTP 服务器）。
- **消息流转**：ChannelPlugin 的 `receive()` → Gateway 的 `handle_request()` → ChannelPlugin 的 `send()`。

### 5. 小结表

| 方法           | 含义                     | 返回类型           |
| -------------- | ------------------------ | ------------------ |
| **receive**    | 接收用户消息             | (user_id, message, session_id?) |
| **send**       | 发送响应给用户           | None               |
| **start**      | 启动通道                 | None               |
| **stop**       | 停止通道                 | None               |
| **get_channel_info** | 返回通道信息       | dict               |

## 三、实战：实现一个 MemoryPlugin（如基于 SQLite 的记忆）和一个 ChannelPlugin（CLI），接入平台

### 1. SQLiteMemoryPlugin 实现

- **表结构**：`memories` 表（memory_id, user_id, content, metadata, created_at, updated_at）。
- **功能**：写入记忆、检索记忆（关键词匹配）、更新/删除记忆。
- **接入**：Runtime 的 ContextBuilder 通过 MemoryManager 获取 SQLiteMemoryPlugin，在组装上下文时检索记忆。

### 2. CLIChannelPlugin 实现

- **功能**：命令行交互，用户输入 → Gateway → Runtime → 返回响应 → 终端输出。
- **接入**：Gateway 通过 ChannelManager 加载 CLIChannelPlugin，启动时调用 `start()`，进入交互循环。

### 3. 完整流程示例

```
1. 用户通过 CLI 输入："查一下北京天气"
2. CLIChannelPlugin.receive() → (user_id="cli_user", message="查一下北京天气", session_id=None)
3. Gateway.handle_request(user_id, channel="cli", message, session_id)
4. Gateway 路由决策 → Runtime.run(...)
5. Runtime 组装上下文（可选：从 SQLiteMemoryPlugin 检索记忆）
6. Runtime 执行（LLM + 工具调用）
7. Gateway 更新会话，调用 CLIChannelPlugin.send(user_id, response)
8. 终端输出："助手: 北京：晴，25°C"
```

### 4. 实战代码结构（week13/90_code）

- **MemoryPlugin 实现**：`SQLiteMemoryPlugin`、`InMemoryMemoryPlugin`（简化版）。
- **ChannelPlugin 实现**：`CLIChannelPlugin`、`WebChannelPlugin`（简化版，用 Flask/FastAPI）。
- **MemoryManager / ChannelManager**：管理插件注册、加载、查询。
- **Gateway 接入**：Gateway 通过 ChannelManager 加载通道，通过 MemoryManager 加载记忆后端。

## 三、代码示例：MemoryPlugin 与 ChannelPlugin（week13/90_code/platform_with_plugins_demo.py）

**InMemoryMemoryPlugin**：内存字典存储，适合开发与单机测试。

```python
class InMemoryMemoryPlugin(BaseMemoryPlugin):
    def __init__(self) -> None:
        self._memories: dict[str, dict] = {}
        self._id_counter = 0

    def write(self, user_id: str, content: str, metadata: dict | None = None) -> str:
        self._id_counter += 1
        mid = f"mem_{self._id_counter}"
        self._memories[mid] = {"user_id": user_id, "content": content, "metadata": metadata or {}}
        return mid

    def retrieve(self, user_id: str, query: str, limit: int = 10) -> list[dict]:
        result = []
        for mid, m in self._memories.items():
            if m["user_id"] == user_id and (not query or query in m["content"]):
                result.append({"memory_id": mid, **m})
        return result[:limit]
```

**CLIChannelPlugin**：终端输入/输出，`receive()` 返回 (user_id, message, session_id)。

```python
class CLIChannelPlugin(BaseChannelPlugin):
    def __init__(self) -> None:
        self.user_id = "cli_user"

    def receive(self) -> tuple[str, str, str | None]:
        line = input("你: ").strip()
        return self.user_id, line, None

    def send(self, user_id: str, message: str) -> None:
        print("助手:", message)

    def get_channel_info(self) -> dict:
        return {"type": "cli", "user_id": self.user_id}
```

**Runtime 中接入 Memory**：组装上下文时调用 `memory_plugin.retrieve(user_id, query)`，将结果注入 System 或首条 User 前（见 `build_context` 中对 `memory_plugin` 的调用）。
