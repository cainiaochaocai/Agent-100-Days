Day 89 讲了状态持久化与会话恢复。本节动手**整合 Gateway + Runtime + 插件系统 + 多通道**：实现完整流程（CLI 通道接收请求 → Gateway 路由 → Runtime 执行带工具 → 返回结果 → Web 通道展示），并**验证插件化**（加载自定义 ToolPlugin、切换不同 ProviderPlugin、使用不同 MemoryPlugin）。完整可运行代码见 **`week13/90_code/platform_with_plugins_demo.py`**。

## 一、整合 Gateway + Runtime + 插件系统 + 多通道

### 1. 架构整合

- **Gateway**：接收请求、路由决策、会话管理、调用 Runtime、返回响应。
- **Runtime**：上下文组装、LLM 调用（通过 ProviderPlugin）、工具执行（通过 ToolPlugin）、状态持久化。
- **插件系统**：ProviderPlugin（LLM）、ToolPlugin（工具）、MemoryPlugin（记忆）、ChannelPlugin（通道）。
- **多通道**：CLI 通道与 Web 通道（简化版），Gateway 统一处理。

### 2. 完整流程

1. **CLI 通道**：用户输入 "查一下北京天气"
2. **CLIChannelPlugin.receive()** → (user_id="cli_user", message="查一下北京天气", session_id=None)
3. **Gateway.handle_request()** → 路由决策 → 调用 Runtime
4. **Runtime.run()** → 组装上下文（可选：从 MemoryPlugin 检索记忆） → LLM 调用（通过 ProviderPlugin） → 工具执行（通过 ToolPlugin） → 返回结果
5. **Gateway** → 更新会话（SessionManager） → 调用 CLIChannelPlugin.send() → 终端输出

### 3. Web 通道流程（类似）

1. **WebChannelPlugin**：接收 HTTP POST `/api/chat`，提取 user_id、message、session_id
2. **Gateway.handle_request()** → 路由决策 → 调用 Runtime
3. **Runtime 执行**（同上）
4. **Gateway** → 更新会话 → 返回 JSON 响应 → Web 前端展示

## 二、实现一个完整流程：CLI 通道接收请求 → Gateway 路由 → Runtime 执行（带工具） → 返回结果 → Web 通道展示

### 1. CLI 通道示例

```python
# CLI 通道启动
cli_channel = CLIChannelPlugin()
gateway.register_channel("cli", cli_channel)

# 交互循环
while True:
    user_id, message, session_id = cli_channel.receive()
    if message.lower() in ("quit", "exit"):
        break
    response = gateway.handle_request(user_id, "cli", message, session_id)
    cli_channel.send(user_id, response["response"])
```

### 2. Web 通道示例（Flask）

```python
# Web 通道启动
app = Flask(__name__)
web_channel = WebChannelPlugin(app)

@app.route("/api/chat", methods=["POST"])
def chat():
    data = request.json
    user_id = data.get("user_id", "web_user")
    message = data.get("message")
    session_id = data.get("session_id")
    
    response = gateway.handle_request(user_id, "web", message, session_id)
    return jsonify(response)
```

### 3. 端到端演示

- **CLI**：用户输入 "查一下北京天气" → Gateway → Runtime → 工具执行（get_weather） → 返回 "北京：晴，25°C" → CLI 输出
- **Web**：用户通过浏览器发送请求 → Gateway → Runtime → 工具执行 → 返回 JSON → Web 前端展示

## 三、验证插件化：加载自定义 ToolPlugin、切换不同 ProviderPlugin、使用不同 MemoryPlugin

### 1. 加载自定义 ToolPlugin

- **示例**：加载 `FileToolPlugin`（Day 86），Runtime 的工具池包含文件操作工具（read_file、write_file）。
- **验证**：用户请求 "读取文件 /tmp/test.txt"，模型选择 `read_file` 工具，ToolExecutor 通过 FileToolPlugin 执行。

### 2. 切换不同 ProviderPlugin

- **示例**：平台支持 `OpenAIProviderPlugin` 与 `DashScopeProviderPlugin`，可以通过配置切换。
- **验证**：切换 Provider 后，Runtime 调用不同模型的 API，但接口不变（都是 `invoke(messages)`）。

### 3. 使用不同 MemoryPlugin

- **示例**：平台支持 `SQLiteMemoryPlugin` 与 `InMemoryMemoryPlugin`，可以通过配置切换。
- **验证**：切换 MemoryPlugin 后，Runtime 的 ContextBuilder 从不同后端检索记忆，但接口不变（都是 `retrieve(user_id, query)`）。

### 4. 插件化的优势

- **扩展性**：新增工具、记忆后端、通道无需修改核心代码，只需实现插件接口。
- **可替换性**：可以切换不同的 Provider、Memory、Channel，而不影响 Runtime 逻辑。
- **可测试性**：可以用 Mock 插件（如 InMemoryMemoryPlugin）做单元测试，不依赖真实数据库。

### 2. 运行方式

在项目根目录配置 `.env`（`OPENAI_API_KEY` 或 `DASHSCOPE_API_KEY`），然后：

**CLI 模式**：
```bash
python week13/90_code/platform_with_plugins_demo.py --channel cli
```
输入「查一下北京天气」「列出当前目录」等，可验证 BuiltinTool 与 FileTool；多轮输入会复用同一 session_id。

**Web 模式**（需安装 `flask`）：
```bash
pip install flask
python week13/90_code/platform_with_plugins_demo.py --channel web
```
然后 `POST http://localhost:5000/api/chat`，Body：`{"user_id":"web_user","message":"查北京天气"}`，可选 `"session_id":"..."` 做多轮；`GET http://localhost:5000/health` 检查状态。

### 3. 验证插件化

- **加载 ToolPlugin**：在 `create_platform()` 中 `pm.register_tool_plugin(FileToolPlugin())`，启动即加载；可注释该行对比「无文件工具」时的行为。
- **切换 Provider**：仅注册一个 Provider 时 `get_provider()` 即该实例；若注册多个，可 `get_provider("dashscope")` 或通过配置选择。
- **切换 Memory**：将 `pm.register_memory(InMemoryMemoryPlugin())` 改为 `pm.register_memory(SQLiteMemoryPlugin("mem.db"))`，接口不变，Runtime 仍通过 `plugin_manager.get_memory().retrieve(...)` 调用。
