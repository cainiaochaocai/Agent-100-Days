# 89. 状态持久化与会话恢复

Day 88 讲了多通道适配与会话隔离。本节讲**会话状态持久化**（对话历史、工具调用记录、Agent 状态、用户偏好）、**会话恢复**（断线重连、历史加载、状态重建），以及**数据模型设计**（会话表、消息表、工具调用表、状态快照表）。

## 一、会话状态持久化：对话历史、工具调用记录、Agent 状态、用户偏好

### 1. 对话历史

- **内容**：用户消息（UserMessage）、Agent 回复（AssistantMessage）、工具结果（ToolMessage）。
- **存储**：每条消息包含：message_id、session_id、role（user/assistant/tool）、content、timestamp、metadata（可选：工具名、tool_call_id 等）。
- **作用**：用于上下文组装（Week 12 Day 81）、历史查询、断线恢复。

### 2. 工具调用记录

- **内容**：工具名、参数、结果、执行时间、是否成功、错误信息（若失败）。
- **存储**：每条工具调用包含：tool_call_id、session_id、tool_name、args（JSON）、result、status（success/failed）、timestamp。
- **作用**：用于审计（Week 15）、错误分析、成本统计。

### 3. Agent 状态

- **内容**：当前 Agent ID、当前子任务（若任务分解）、反思结论（若触发反思）、HITL 决策（若触发 HITL）。
- **存储**：Agent 状态包含：session_id、agent_id、current_subtask（JSON）、reflection_result（JSON）、hitl_decision（JSON）、updated_at。
- **作用**：用于断线恢复（恢复 Agent 的执行状态）、状态查询。

### 4. 用户偏好

- **内容**：用户偏好（如“喜欢简洁回复”）、历史经验、任务态势（Week 7）。
- **存储**：用户偏好包含：user_id、preference_key、preference_value（JSON）、updated_at。
- **作用**：用于记忆检索（Week 7）、个性化回复。

### 5. 小结表

| 状态类型     | 内容                         | 作用                     |
| ------------ | ---------------------------- | ------------------------ |
| **对话历史** | UserMessage、AssistantMessage、ToolMessage | 上下文组装、历史查询     |
| **工具调用记录** | 工具名、参数、结果、状态     | 审计、错误分析、成本统计 |
| **Agent 状态** | Agent ID、子任务、反思、HITL | 断线恢复、状态查询       |
| **用户偏好** | 偏好、经验、任务态势         | 记忆检索、个性化         |

## 二、会话恢复：断线重连、历史加载、状态重建

### 1. 断线重连

- **场景**：用户关闭客户端（如关闭 Web 页面、退出 CLI）后重新连接，希望**恢复之前的会话**。
- **实现**：用户传入 `session_id`，Gateway 从 SessionManager 查询会话，若存在则恢复，若不存在则创建新会话。
- **恢复内容**：加载对话历史、Agent 状态、工具调用记录，重建上下文。

### 2. 历史加载

- **方式**：SessionManager 的 `get_history(session_id, limit)` 从数据库查询最近 N 条消息，按时间顺序返回。
- **优化**：若历史很长，可以只加载最近 N 条（如最近 20 条），或按 token 窗口加载（如最近 2000 tokens）。

### 3. 状态重建

- **含义**：断线恢复时，不仅加载对话历史，还要**重建 Agent 的执行状态**（当前 Agent、子任务进度、反思结论等）。
- **实现**：从 Agent 状态表加载状态，Runtime 根据状态重建执行上下文（如恢复子任务列表、继续执行未完成的子任务）。

### 4. 简化实现（Day 90 实战）

- **Day 90 先实现基础持久化**：会话表、消息表，支持断线重连与历史加载。
- **Agent 状态与工具调用记录作为扩展点**：Week 15 再完善（接入 Langfuse 时统一记录）。

### 5. 小结

| 恢复类型     | 内容                     | 实现方式                     |
| ------------ | ------------------------ | ---------------------------- |
| **断线重连** | 用户重新连接，恢复会话   | 根据 session_id 查询会话并恢复 |
| **历史加载** | 加载对话历史             | 从消息表查询最近 N 条消息     |
| **状态重建** | 重建 Agent 执行状态      | 从 Agent 状态表加载状态       |

## 三、数据模型设计：会话表、消息表、工具调用表、状态快照表

### 1. 会话表（sessions）

```sql
CREATE TABLE sessions (
    session_id TEXT PRIMARY KEY,
    user_id TEXT NOT NULL,
    channel TEXT NOT NULL,
    agent_id TEXT,
    created_at TIMESTAMP,
    updated_at TIMESTAMP,
    status TEXT,  -- active/ended
    metadata JSON  -- 可选：用户信息、通道信息等
);
```

### 2. 消息表（messages）

```sql
CREATE TABLE messages (
    message_id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    role TEXT NOT NULL,  -- user/assistant/tool/system
    content TEXT,
    tool_call_id TEXT,  -- 若 role=tool，关联 tool_calls
    timestamp TIMESTAMP,
    metadata JSON  -- 可选：工具名、Agent ID 等
);
```

### 3. 工具调用表（tool_calls，可选）

```sql
CREATE TABLE tool_calls (
    tool_call_id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    tool_name TEXT NOT NULL,
    args JSON,
    result TEXT,
    status TEXT,  -- success/failed
    error_message TEXT,
    timestamp TIMESTAMP
);
```

### 4. 状态快照表（agent_states，可选）

```sql
CREATE TABLE agent_states (
    state_id TEXT PRIMARY KEY,
    session_id TEXT NOT NULL,
    agent_id TEXT,
    state_data JSON,  -- 当前子任务、反思结论、HITL 决策等
    timestamp TIMESTAMP
);
```

### 5. 实现方式

- **Day 90 实战**：先用 **SQLite** 实现简化版（sessions 表 + messages 表），工具调用与状态快照作为扩展点。
- **Week 15**：可扩展为 PostgreSQL、MySQL 等，或接入专门的存储系统（如向量库用于记忆、时序数据库用于工具调用记录）。

### 6. 小结表

| 表名         | 主要字段                     | 作用                     |
| ------------ | ---------------------------- | ------------------------ |
| **sessions** | session_id, user_id, channel, agent_id | 会话基本信息             |
| **messages** | message_id, session_id, role, content | 对话历史                 |
| **tool_calls** | tool_call_id, tool_name, args, result | 工具调用记录（可选）     |
| **agent_states** | state_id, session_id, state_data | Agent 状态快照（可选）   |

## 四、代码示例：会话 ID 与历史（week13/90_code/platform_with_plugins_demo.py）

本 demo 使用**内存**存储会话与历史，会话 ID 含 channel 前缀，便于多通道隔离；断线重连时客户端传回 `session_id` 即可恢复历史。

```python
# SessionManager.create_session：session_id 含 channel
def create_session(self, user_id: str, channel: str) -> dict:
    session_id = f"{channel}_{user_id}_{uuid.uuid4().hex[:8]}"
    self._sessions[session_id] = {"id": session_id, "user_id": user_id, "channel": channel, ...}
    self._history[session_id] = []
    return self._sessions[session_id]

# Runtime 返回前写入本轮 user/assistant，Gateway 下次用 get_history 加载
session_manager.append_history(session_id, "user", user_input)
session_manager.append_history(session_id, "assistant", reply)
# ...
history = self.session_manager.get_history(session_id, limit=20)
response = run_runtime(..., context=history, ...)
```

若改为 SQLite/数据库持久化，只需把 `_sessions` / `_history` 换成对表的读写，接口保持不变。
