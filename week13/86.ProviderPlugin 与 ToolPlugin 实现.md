# 86. ProviderPlugin 与 ToolPlugin 实现

Day 85 讲了插件系统架构设计。本节具体实现 **ProviderPlugin**（统一 LLM 调用接口，支持多模型切换）与 **ToolPlugin**（工具插件的注册、发现、执行），并给出**实战示例**（实现一个自定义 ToolPlugin，并在平台上加载使用）。

## 一、ProviderPlugin：统一 LLM 调用接口，支持多模型切换

### 1. 接口设计

- **BaseProviderPlugin**：定义统一接口
  - `invoke(messages, **kwargs)` → 返回模型响应（AIMessage，含 tool_calls）
  - `stream(messages, **kwargs)` → 流式返回（可选，返回 generator）
  - `get_model_info()` → 返回模型信息（名称、版本、能力描述）
  - `bind_tools(tools)` → 绑定工具到模型（返回支持 tool_calls 的模型实例）

### 2. 实现示例：OpenAIProviderPlugin

- **实现**：封装 `langchain_openai.ChatOpenAI`，实现 `invoke`、`stream`、`bind_tools`。
- **配置**：通过初始化参数传入 API key、base_url、model 等。

### 3. 实现示例：DashScopeProviderPlugin

- **实现**：封装 DashScope API（如 Week 8-11 用的 qwen-plus），实现相同接口。
- **配置**：通过初始化参数传入 DASHSCOPE_API_KEY、model 等。

### 4. 多模型切换与模型回退

- **方式**：Runtime 通过 **ProviderManager** 管理多个 ProviderPlugin，根据配置或请求选择使用哪个 Provider。
- **切换**：可以在配置文件中指定“默认 Provider”，或运行时通过 API 切换（如 `runtime.set_provider("openai")`）。
- **模型回退**：主模型不可用时自动切换备用模型，提升鲁棒性。OpenClaw 有 [模型回退与鲁棒性原理](https://openclaw-docs.dx3n.cn/beginner-openclaw-framework-focus/10-%E6%A8%A1%E5%9E%8B%E5%9B%9E%E9%80%80%E4%B8%8E%E9%B2%81%E6%A3%92%E6%80%A7%E5%8E%9F%E7%90%86)，可对照实现。

### 5. 小结表

| 方法           | 含义                         | 返回类型           |
| -------------- | ---------------------------- | ------------------ |
| **invoke**     | 调用 LLM，返回响应           | AIMessage（含 tool_calls） |
| **stream**     | 流式调用 LLM                 | Generator[str]     |
| **bind_tools** | 绑定工具到模型               | 支持 tool_calls 的模型实例 |
| **get_model_info** | 返回模型信息             | dict               |

## 二、ToolPlugin：工具插件的注册、发现、执行

### 1. 接口设计

- **BaseToolPlugin**：定义统一接口
  - `get_tools()` → 返回工具列表（Tool 对象或 schema dict）
  - `execute(tool_name, args)` → 执行工具，返回结果（str 或 dict）
  - `get_tool_schema(tool_name)` → 返回工具 schema（名称、描述、参数）
  - `get_plugin_info()` → 返回插件信息（名称、版本、工具列表）

### 2. 工具注册

- **方式**：ToolPlugin 实现 `get_tools()`，返回工具列表；Runtime 的 ToolRegistry 调用 `get_tools()`，将工具注册到工具池。
- **元数据**：每个工具应有名称、描述、参数 schema（用于模型选择与参数校验）。

### 3. 工具发现

- **方式**：Runtime 通过 ToolRegistry 查询工具（`get(name)`、`list()`、`filter(capability)`）。
- **筛选**：可以根据工具的能力标签（如 `capability: ["search"]`）筛选，限制 Agent 的工具范围。

### 4. 工具执行

- **流程**：Runtime 收到 tool_calls → 通过 ToolRegistry 找到对应 ToolPlugin → 调用 `execute(tool_name, args)` → 返回结果。
- **错误处理**：ToolPlugin 的 `execute` 应统一处理错误，返回错误信息而非抛出异常。

### 5. 小结表

| 方法           | 含义                     | 返回类型           |
| -------------- | ------------------------ | ------------------ |
| **get_tools**  | 返回工具列表             | list[Tool] 或 list[dict] |
| **execute**    | 执行工具                 | str 或 dict        |
| **get_tool_schema** | 返回工具 schema     | dict               |
| **get_plugin_info** | 返回插件信息         | dict               |

## 三、实战：实现一个自定义 ToolPlugin（如文件操作、API 调用），并在平台上加载使用

### 1. 自定义 ToolPlugin 示例：FileToolPlugin

- **功能**：文件读写操作（读文件、写文件、列目录）。
- **实现**：
  ```python
  class FileToolPlugin(BaseToolPlugin):
      def get_tools(self):
          return [
              Tool(name="read_file", description="读取文件内容", schema={"path": "str"}),
              Tool(name="write_file", description="写入文件", schema={"path": "str", "content": "str"}),
              Tool(name="list_dir", description="列出目录", schema={"path": "str"}),
          ]
      
      def execute(self, tool_name, args):
          if tool_name == "read_file":
              return open(args["path"]).read()
          elif tool_name == "write_file":
              open(args["path"], "w").write(args["content"])
              return "写入成功"
          elif tool_name == "list_dir":
              return "\n".join(os.listdir(args["path"]))
  ```

### 2. 在平台上加载使用

- **注册**：在配置文件中添加 `FileToolPlugin` 的路径，或运行时调用 `plugin_manager.register(FileToolPlugin())`。
- **加载**：平台启动时或按需加载，ToolRegistry 调用 `get_tools()`，将工具注册到工具池。
- **使用**：Runtime 执行时，模型可以选择调用 `read_file`、`write_file` 等工具，ToolExecutor 通过 ToolPlugin 的 `execute` 执行。

### 3. 实战代码结构（week13/90_code）

- **ProviderPlugin 实现**：`DashScopeProviderPlugin`（见下代码示例），实现 `invoke`、`bind_tools`、`get_model_info`。
- **ToolPlugin 实现**：`BuiltinToolPlugin`（天气/时间/订单）、`FileToolPlugin`（read_file、list_dir），实现 `get_tools()` 与 `execute()`。
- **PluginManager**：`register_provider`、`register_tool_plugin`、`get_all_tools`、`execute_tool`；Runtime 通过 `plugin_manager.get_provider().bind_tools(plugin_manager.get_all_tools())` 调用 LLM，通过 `plugin_manager.execute_tool(name, args)` 执行工具。

### 4. 代码示例（week13/90_code/platform_with_plugins_demo.py）

**DashScopeProviderPlugin**：封装 ChatOpenAI，统一接口。

```python
class DashScopeProviderPlugin(BaseProviderPlugin):
    def __init__(self, model: str = "qwen-plus", base_url: str = BASE_URL, api_key: str = ""):
        self._llm = ChatOpenAI(model=model, base_url=base_url, api_key=api_key)

    def invoke(self, messages: list, **kwargs) -> Any:
        return self._llm.invoke(messages, **kwargs)

    def bind_tools(self, tools: list) -> Any:
        return self._llm.bind_tools(tools)
```

**BuiltinToolPlugin**：`get_tools()` 返回 [get_weather, get_current_time, search_order]；`execute(tool_name, args)` 内用 tool_map 查找并 invoke，异常时返回可读错误字符串。
