# 82. 工具系统与执行引擎

Day 81 讲了上下文组装与会话管理。本节讲**工具系统**：**工具注册与发现**（工具 schema、工具池管理、按能力/场景筛选）、**工具执行引擎**（参数校验、执行、错误处理、结果格式化），以及**工具链与组合**（多工具顺序执行、并行执行、条件分支）。

## 一、工具注册与发现：工具 schema、工具池管理、按能力/场景筛选

### 1. 工具 schema

- **含义**：每个工具都有**明确的 schema**：名称、描述、参数（名称、类型、是否必填、示例）、返回值类型、权限要求（如是否需要审批）。
- **作用**：schema 用于**工具发现**（模型根据描述选择工具）、**参数校验**（执行前校验参数是否符合 schema）、**文档生成**（自动生成工具文档）。
- **格式**：可用 JSON Schema、Pydantic、或自定义格式；Week 4 的 Tool 定义（LangChain `@tool`）就是 schema 的一种形式。

### 2. 工具池管理

- **含义**：Runtime 维护一个**工具池**（ToolRegistry），所有可用工具都注册在这里；工具可以是**内置工具**（如 Week 8 的天气、时间）或**插件工具**（通过 ToolPlugin 加载，Week 13 会讲）。
- **操作**：注册工具（`register(tool)`）、查询工具（`get(name)`）、列出所有工具（`list()`）、按条件筛选（`filter(capability, scenario)`）。

### 3. 按能力/场景筛选

- **能力筛选**：工具可以打标签（如 `capability: ["search", "data_query"]`），Runtime 可以根据 Agent 的“能力范围”筛选工具（如 DeepResearch Agent 只用 search、read 类工具）。
- **场景筛选**：工具可以标记“适用场景”（如 `scenario: ["research", "analysis"]`），Router 或 Runtime 可以根据用户请求的场景筛选工具。

### 4. 小结表

| 概念            | 含义                 | 作用             |
| ------------- | ------------------ | -------------- |
| **工具 schema** | 工具的名称、描述、参数、返回值、权限 | 工具发现、参数校验、文档生成 |
| **工具池**       | Runtime 维护的工具注册表   | 统一管理所有可用工具     |
| **能力/场景筛选**   | 按标签筛选工具（能力、场景）     | 限制 Agent 的工具范围 |

## 二、工具执行引擎：参数校验、执行、错误处理、结果格式化

### 1. 参数校验

- **含义**：执行工具前，根据工具的 **schema** 校验参数：类型是否匹配、必填参数是否都有、取值是否在允许范围内。
- **作用**：提前发现参数错误，避免工具执行失败；返回明确的错误信息（如“参数 city 应为字符串，但收到数字”），便于模型调整。

### 2. 执行

- **含义**：调用工具的**实际实现**（Python 函数、API、或通过 ToolPlugin 调用外部服务）。
- **方式**：同步执行（直接调用函数）、异步执行（如 HTTP 请求，用 asyncio 或线程池）、流式执行（如文件读取，逐 chunk 返回）。

### 3. 错误处理

- **含义**：工具执行可能失败（参数错误、网络错误、业务错误、超时），执行引擎应**统一处理错误**：捕获异常、记录错误信息、返回统一错误格式。
- **格式**：错误结果应包含：错误类型（参数错误/执行错误/超时）、错误信息、可选重试建议。

### 4. 结果格式化

- **含义**：工具返回的结果（可能是任意类型：字符串、字典、对象）应**格式化为统一格式**（如字符串或 JSON），便于追加到 ToolMessage 并传给模型。
- **策略**：简单类型（str、int）直接转字符串；复杂类型（dict、list）用 JSON 序列化；对象用 `str()` 或自定义 `to_dict()`。

### 5. 小结表

| 步骤        | 含义                  | 作用                |
| --------- | ------------------- | ----------------- |
| **参数校验**  | 根据 schema 校验参数      | 提前发现错误，返回明确信息     |
| **执行**    | 调用工具的实际实现           | 执行工具逻辑            |
| **错误处理**  | 统一捕获与格式化错误          | 便于模型调整或重试         |
| **结果格式化** | 将结果转为统一格式（字符串/JSON） | 便于追加到 ToolMessage |

## 三、工具链与组合：多工具顺序执行、并行执行、条件分支

### 1. 多工具顺序执行

- **含义**：模型在一次 tool_calls 中调用**多个工具**，这些工具按**调用顺序**依次执行，每个工具的结果作为 ToolMessage 追加，模型在下一轮可以看到所有结果。
- **场景**：例如“先查天气，再查时间，最后总结”，三个工具顺序执行。
- **实现**：Runtime 遍历 tool_calls，依次执行每个工具，收集所有 ToolMessage，一次性追加到 messages。

### 2. 并行执行

- **含义**：多个工具**无依赖关系**时，可以**并行执行**（如同时查三个城市的天气），缩短总时长。
- **场景**：Week 10 Day 67 的并行与汇合：多个独立工具并行执行，结果汇合后再传给模型。
- **实现**：Runtime 用线程池或 asyncio 并发执行多个工具，等待所有结果后再追加 ToolMessage。

### 3. 条件分支

- **含义**：根据**工具执行结果**决定“下一步调用哪个工具”或“是否继续执行”。例如：工具 A 返回“成功”则调用工具 B，返回“失败”则调用工具 C。
- **场景**：任务分解（Week 10）中的依赖关系：子任务 A 完成后，根据结果决定是否执行子任务 B。
- **实现**：Runtime 可以在工具执行后，根据结果注入一条消息（如“工具 A 返回成功，请调用工具 B”），模型根据该消息决定下一步。

### 4. 小结

| 组合方式     | 含义          | 适用场景         |
| -------- | ----------- | ------------ |
| **顺序执行** | 多个工具按顺序依次执行 | 有依赖关系的工具链    |
| **并行执行** | 多个工具同时执行    | 无依赖关系的独立工具   |
| **条件分支** | 根据工具结果决定下一步 | 有依赖或条件判断的工具链 |

## 四、实战经验分享

- **工具描述要能让模型选对**：schema 里的 description 会直接给模型看，要写清「何时用、输入是什么、输出大概长什么样」。模糊描述（如「查询数据」）会导致误选或漏选；写好示例（如「输入城市名，返回该城市当前天气」）能明显提升调用准确率。
- **错误信息要「可被模型纠错」**：工具报错时不要只返回 "Error" 或堆栈，要返回简短、可读的说明（如「参数 city 应为字符串，当前收到数字」或「订单不存在：ORD999」），模型才能根据错误调整参数或改策略，减少无效重试。
- **并行工具的超时与部分失败**：多工具并行时，若其中一个卡住或超时，不要拖死整次请求。对每个工具设单次超时（如 10s），超时则返回「工具 xxx 执行超时」，和其他工具结果一起交给模型，由模型决定是否重试或降级回答。
- **敏感工具要有审批开关**：涉及写库、发邮件、支付等操作的工具，在 schema 里标记 `requires_approval`，Runtime 在执行前走 HITL（Week 11），避免模型误触；非敏感只读工具可直接执行。
- **工具结果别太长**：工具返回大段文本或大 JSON 时，可先截断或摘要再塞进 ToolMessage（如只保留前 2000 字符 + 「…（已截断）」），否则会占满上下文，影响后续推理。

## 五、代码示例：工具注册与执行

以下来自 **`week12/83_code/gateway_runtime_demo.py`**。工具用 LangChain `@tool` 定义（自带 schema），执行时统一捕获异常并返回可读错误信息。

```python
from langchain_core.tools import tool

@tool
def get_weather(city: str) -> str:
    """当用户询问某地天气时，使用此工具查询该城市的天气。输入为城市名，如北京、上海。"""
    fake_db = {"北京": "晴，25°C", "上海": "多云，22°C", "深圳": "阴，28°C"}
    return fake_db.get(city, f"{city}：暂无数据")

TOOLS = [get_weather, get_current_time, search_order]
TOOL_MAP = {t.name: t for t in TOOLS}
```

执行引擎：按 name 查找工具、invoke(args)、异常时返回统一错误字符串（便于模型纠错）：

```python
def execute_tool(name: str, args: dict) -> str:
    tool_fn = TOOL_MAP.get(name)
    if not tool_fn:
        return f"错误：未知工具 {name}"
    try:
        result = tool_fn.invoke(args or {})
        return str(result) if result is not None else ""
    except Exception as e:
        return f"执行失败: {e}"
```

在 Runtime 循环中，对每个 tool_call 生成 ToolMessage 并追加（顺序见 Day 80）：

```python
for call in response.tool_calls:
    name = call.get("name", "")
    args = call.get("args") or {}
    tid = call.get("id", "")
    content = execute_tool(name, args)
    messages.append(ToolMessage(content=content, tool_call_id=tid))
```

## 六、实现

在 **`week12/83_code/gateway_runtime_demo.py`** 中，工具系统会实现：

- **ToolRegistry**：工具注册表，支持注册、查询、筛选；工具 schema 用 Pydantic 或 JSON Schema。
