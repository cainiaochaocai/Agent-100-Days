# 81. 上下文组装与会话管理

Day 80 讲了 Agent Runtime 的核心循环。本节具体讲**会话状态管理**（用户会话、Agent 会话、工具调用历史）、**上下文组装策略**（历史对话、记忆检索、工具结果、反思结论的合并与优先级），以及**跨 Agent 的上下文共享与隔离**（何时共享、何时隔离）。OpenClaw 将**上下文工程**与**状态机**作为稳定性主心骨：「上下文决定模型看到什么，状态机决定流程怎么走」。

## 一、会话状态管理：用户会话、Agent 会话、工具调用历史

### 1. 用户会话（User Session）

- **含义**：一个用户在一个通道（如 Web、CLI）的**一次对话会话**，从用户发起第一次请求到明确结束（如用户说“结束”“再见”，或超时自动结束）。
- **状态**：会话 ID、用户 ID、通道标识、创建时间、最后活跃时间、状态（active/ended）、元数据（如当前 Agent、工具调用次数）。
- **作用**：Gateway 用会话 ID 关联多轮对话，Runtime 用会话 ID 加载历史上下文。

### 2. Agent 会话（Agent Session）

- **含义**：在一个用户会话内，**当前 Agent 的执行上下文**。若用户切换 Agent（如从 DeepResearch 切换到 ChatBI），会创建新的 Agent 会话，但用户会话不变。
- **状态**：Agent ID、会话 ID（关联到用户会话）、上下文 messages、工具调用历史、反思结论、HITL 决策记录。
- **作用**：Runtime 用 Agent 会话组装上下文，避免不同 Agent 的上下文混在一起。

### 3. 工具调用历史

- **含义**：本次 Agent 会话中**所有工具调用的记录**：工具名、参数、结果、执行时间、是否成功。
- **作用**：用于上下文组装（工具结果作为 ToolMessage）、审计（Week 15）、错误分析（Week 15）。

### 4. 小结表

| 会话类型         | 含义                   | 作用                |
| ------------ | -------------------- | ----------------- |
| **用户会话**     | 用户的一次完整对话            | Gateway 管理，关联多轮对话 |
| **Agent 会话** | 用户会话内当前 Agent 的执行上下文 | Runtime 管理，组装上下文  |
| **工具调用历史**   | Agent 会话中所有工具调用记录    | 上下文组装、审计、分析       |

## 二、上下文组装策略：历史对话、记忆检索、工具结果、反思结论的合并与优先级

### 1. 历史对话

- **来源**：从 SessionManager 获取当前 Agent 会话的**最近 N 轮对话**（UserMessage、AssistantMessage、ToolMessage）。
- **优先级**：**最近优先**，越近的对话越重要；可设置时间窗口（如最近 10 轮）或 token 窗口（如最近 2000 tokens）。
- **压缩**：若历史过长，可用 Week 6 的摘要策略（时间窗口、语义摘要）压缩后再组装。

### 2. 记忆检索（Week 7）

- **来源**：从 MemoryPlugin 检索**与当前请求相关的记忆**（用户偏好、历史经验、任务态势等）。
- **优先级**：记忆通常放在 **System 或首轮 UserMessage 之后**，作为“背景知识”而非“当前对话”。
- **过滤**：只取相关性高的记忆（如相似度 > 0.7），避免噪音。

### 3. 工具结果

- **来源**：当前 Agent 会话的**工具调用历史**，转换为 ToolMessage 追加到 messages。
- **优先级**：工具结果紧跟对应的 AssistantMessage（带 tool_calls 的），**不能插入其他 role**（见 Week 9 Day 62 的 API 要求）。
- **格式**：ToolMessage 包含 tool_call_id、content（工具返回结果）、可选 metadata（工具名、执行时间）。

### 4. 反思结论

- **来源**：若 Runtime 中嵌入了反思节点（Week 9），反思的 **decision、reason、suggestion** 可作为上下文的一部分。
- **优先级**：反思结论通常**不直接当事实**（Week 9 Day 61），而是作为“元级判断”注入：若 decision=adjust，将 suggestion 作为一条 UserMessage 或 System 消息注入。
- **格式**：例如 `"【反思建议】{suggestion} 请根据此建议决定下一步。"`

### 5. 合并与优先级总结

- **顺序**：System（能力描述、记忆摘要） → 历史对话（最近优先） → 当前 UserMessage → [工具执行循环：AssistantMessage + ToolMessage] → [可选：反思建议] → 下一轮推理。
- **优先级**：System > 当前请求 > 最近历史 > 工具结果 > 记忆 > 更早历史。

## 三、跨 Agent 的上下文共享与隔离：何时共享、何时隔离

### 1. 何时共享

- **用户偏好与记忆**：不同 Agent 可以共享**用户记忆**（如用户偏好、历史经验），因为这些是“用户级”而非“Agent 级”的。
- **会话元数据**：用户会话的元数据（如用户 ID、通道、创建时间）可以在不同 Agent 间共享。
- **场景**：用户先问“研究 AI 进展”（DeepResearch），再问“查询销售额”（ChatBI），两个 Agent 可以共享“用户偏好：喜欢简洁回复”。

### 2. 何时隔离

- **对话历史**：不同 Agent 的**对话历史**应隔离，避免 DeepResearch 的历史影响 ChatBI 的上下文。
- **工具调用历史**：每个 Agent 的工具调用历史独立，不共享。
- **Agent 状态**：每个 Agent 的执行状态（当前子任务、反思结论、HITL 决策）独立。

### 3. 实现方式

- **用户会话**：Gateway 管理，所有 Agent 共享。
- **Agent 会话**：Runtime 管理，每个 Agent 独立；Agent 会话关联到用户会话，但不共享对话历史。
- **记忆**：MemoryPlugin 按“用户 ID + 可选 Agent ID”检索；若 Agent ID 为空，则检索“用户级记忆”（共享）；若指定 Agent ID，则检索“Agent 级记忆”（隔离）。

### 4. 小结

| 内容           | 是否共享 | 说明                 |
| ------------ | ---- | ------------------ |
| **用户记忆**     | 共享   | 用户偏好、历史经验是用户级的     |
| **对话历史**     | 隔离   | 不同 Agent 的历史不应混在一起 |
| **工具调用历史**   | 隔离   | 每个 Agent 的工具调用独立   |
| **Agent 状态** | 隔离   | 每个 Agent 的执行状态独立   |

## 四、实战经验分享

- **用 token 数控制历史长度**：优先按「最近 N tokens」截断历史，而不是单纯「最近 N 条」：一条长回复可能上千 token，10 条短消息可能才几百。用 tiktoken 或模型文档里的计费方式估算，保证 System + 历史 + 当前轮不超模型上下文上限并留余量给回复。
- **历史条数上限与摘要**：若保留「最近 20 条」仍超长，可对更早的对话做摘要（如用 LLM 把多轮压成一段「此前用户问了…助手答了…」），再拼上最近几轮原文，既省 token 又保留关键信息。
- **ToolMessage 必须紧跟 AIMessage**：组装或追加消息时，带 tool_calls 的 AIMessage 后面只能跟对应的 ToolMessage，不能先插一条 System/User。否则会触发 Week 9 提到的 API 报错，排查时重点看「是否在工具执行和反思分支里插了别的 role」。
- **Agent 会话与用户会话分离**：同一用户从「研究 Agent」切到「BI Agent」时，不要共用同一段对话历史，否则 BI 会读到大量与研究无关的上下文。用「用户会话 + 当前 agent_id」作为 Agent 会话的 key，按 agent 维度存/取历史。
- **记忆注入位置**：从 MemoryPlugin 查到的记忆建议放在 System 或首条 User 之前，用一句「用户已知信息：…」之类的句式，避免和当轮 UserMessage 混在一起导致模型混淆「当前问题」和「背景知识」。

## 五、代码示例：上下文组装与历史存储

以下来自 **`week12/83_code/gateway_runtime_demo.py`**。**ContextBuilder** 将 SystemMessage、历史、当前请求组装成 messages；**SessionManager** 按 session_id 存历史，便于多轮对话。

```python
def build_context(user_input: str, history: list[dict], session_id: str, system: str = SYSTEM_PROMPT) -> list:
    """组装 LLM 可用的 messages：System + 历史 + 当前 UserMessage。"""
    messages = []
    if system:
        messages.append(SystemMessage(content=system))
    for h in history:
        role, content = h.get("role", ""), h.get("content", "")
        if role == "user":
            messages.append(HumanMessage(content=content))
        elif role == "assistant":
            messages.append(AIMessage(content=content))
    messages.append(HumanMessage(content=user_input))
    return messages
```

历史按会话追加（仅保留 user/assistant 文本，工具调用在当轮内存中，不写回历史可控制长度）：

```python
# Runtime 返回前写入本轮对话
session_manager.append_history(session_id, "user", user_input)
session_manager.append_history(session_id, "assistant", reply)

# Gateway 调用 Runtime 前读取历史
history = self.session_manager.get_history(session_id, limit=20)
response = run_runtime(user_input=message, context=history, ...)
```

## 六、实战中的实现

在 **`week12/83_code/gateway_runtime_demo.py`** 中：

- **SessionManager**：管理用户会话与 Agent 会话，支持创建、查询、更新；Agent 会话关联到用户会话，但不共享对话历史。
- **ContextBuilder**：从 SessionManager 获取 Agent 会话历史，从 MemoryPlugin（若已接入）检索记忆，组装成 messages 列表；按优先级排序：SystemMessage（记忆） → 历史对话 → 当前请求 → 工具结果。
