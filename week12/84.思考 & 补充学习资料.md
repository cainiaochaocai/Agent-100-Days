# 思考 & 补充学习资料

#### 反思问题

- Gateway 与 Agent Runtime 的职责边界是否清晰？如何避免职责重叠？
- 路由决策的准确性如何评估？误路由发生时如何快速定位与修复？
- 如何设计 Gateway 与 Runtime 的接口，使其易于扩展与替换？

## 本周实战经验小结

- **架构**：先单通道、同进程 MVP，会话 ID 由 Gateway 生成并下发给客户端，错误统一格式 + trace_id，接口预留版本。
- **路由**：规则优先、LLM 兜底，路由日志必打，置信度阈值用标注数据调，误路由用 wrong_route 与用户行为监控迭代。
- **Runtime**：设好 max_steps，严守「AIMessage(tool_calls) 后只跟 ToolMessage」的消息顺序，MVP 可非流式，失败时返回结构化错误。
- **上下文**：按 token 截断历史，必要时对更早对话做摘要，Agent 会话按 agent_id 隔离，记忆放在 System/首轮前。
- **工具**：description 写清用途与示例，错误信息要可读以便模型纠错，并行工具设单次超时，敏感工具加审批，结果过长要截断或摘要。
- **调试**：关键节点打 request_id/session_id 日志，遇到 400 先查消息顺序，路由/工具问题先看日志再补规则或 schema。
