# 78. Gateway 架构设计

Week 8-11 我们学了 Agent 的组成、失败模式、反思、任务分解与 HITL：单个 Agent 可以多步推理、调用工具、分解目标、自我纠错并请求人工介入。但真实业务往往需要**多个 Agent 协作**或**统一入口管理多个能力**，这就需要一个Gateway（网关）**作为控制平面。本节说明 Gateway 的职责**（路由决策、会话管理、状态持久化、多通道协调）、**Hub-and-Spoke 架构**（Gateway 作为控制平面，Agent Runtime 作为执行节点），以及**接口设计**（Gateway API、会话与状态管理接口）。架构设计上可参考开源多通道智能体框架 OpenClaw：其 OpenClaw Gateway 即核心常驻进程，负责**统一管理所有通道连接、消息路由、Agent 调度与会话存储**，通过 `openclaw gateway` 启动，默认监听 18789 端口。

## 一、Gateway 的职责：路由决策、会话管理、状态持久化、多通道协调

### 1. 路由决策

- **含义**：根据用户请求（意图、上下文、历史）决定**应该路由到哪个 Agent** 或**哪个工具链**。例如：用户问“帮我研究一下 AI 的最新进展” → 路由到 DeepResearch Agent；用户问“查询上个月的销售额” → 路由到 ChatBI Agent。
- **实现**：可以是规则路由（关键词匹配）、Embedding 相似度路由、LLM 决策路由，或混合策略（见 Day 79）。

### 2. 会话管理

- **含义**：维护**用户会话**（session）的状态：会话 ID、用户标识、对话历史、当前 Agent、会话元数据（创建时间、最后活跃时间等）。
- **作用**：多轮对话中，Gateway 需要知道“这是哪个用户的哪次会话”，才能正确路由与上下文组装。

### 3. 状态持久化

- **含义**：将会话状态、对话历史、工具调用记录等**持久化到存储**（数据库、文件系统等），支持断线重连、历史查询、状态恢复。
- **作用**：用户关闭客户端后重新连接，Gateway 能恢复之前的会话状态与历史。

### 4. 多通道协调

- **含义**：Gateway 作为**统一入口**，接收来自不同通道（CLI、Web、Telegram、Discord 等）的请求，统一路由到 Agent Runtime，再将响应返回给对应通道。
- **作用**：不同通道的用户可以通过同一套 Agent 能力，Gateway 负责“通道适配”与“消息格式转换”。

### 5. 小结表

| 职责        | 含义                  | 作用            |
| --------- | ------------------- | ------------- |
| **路由决策**  | 根据请求决定路由到哪个 Agent   | 将请求分发到合适的执行节点 |
| **会话管理**  | 维护用户会话状态（ID、历史、元数据） | 支持多轮对话与上下文组装  |
| **状态持久化** | 将会话、历史、状态写入存储       | 支持断线重连与历史查询   |
| **多通道协调** | 统一接收多通道请求，适配格式并路由   | 提供统一入口，支持多端接入 |

## 二、Hub-and-Spoke 架构：Gateway 作为控制平面，Agent Runtime 作为执行节点

### 1. Hub-and-Spoke 模式

- **Hub（中心）**：Gateway，负责**控制与协调**：接收请求、路由决策、会话管理、状态持久化。
- **Spoke（辐条）**：Agent Runtime（一个或多个），负责**执行**：上下文组装、LLM 调用、工具执行、流式响应。
- **数据流**：用户请求 → Gateway（路由决策） → Agent Runtime（执行） → Gateway（状态更新、响应返回） → 用户。

### 2. 架构优势

- **职责分离**：Gateway 专注“路由与管理”，Runtime 专注“执行”，边界清晰，易于扩展。
- **可扩展性**：可以部署多个 Runtime 实例（水平扩展），Gateway 负责负载均衡与路由。
- **统一管理**：所有请求都经过 Gateway，便于统一做权限控制、成本统计、监控与审计。

### 3. 与单体 Agent 的区别

- **单体 Agent**：用户直接调用 Agent，Agent 自己管理会话、工具、上下文。
- **Gateway + Runtime**：用户请求先到 Gateway，Gateway 决定路由到哪个 Runtime，Runtime 专注执行；Gateway 统一管理会话、状态、多通道。

## 三、接口设计：Gateway API（接收请求、路由到 Agent、返回响应）、会话与状态管理接口

### 1. Gateway API（核心接口）

- **接收请求**：`POST /api/chat` 或 `gateway.handle_request(user_id, channel, message, session_id?)`
  - 输入：用户 ID、通道标识、消息内容、可选会话 ID（新会话则生成新 ID）
  - 输出：响应内容（流式或一次性）、会话 ID、元数据（路由到的 Agent、工具调用记录等）
- **路由到 Agent**：Gateway 内部调用 `router.route(request, session)`，返回目标 Agent 标识，再调用对应 Runtime。
- **返回响应**：Gateway 接收 Runtime 的响应（流式或一次性），更新会话状态，返回给用户。

### 2. 会话与状态管理接口

- **会话创建**：`POST /api/sessions` 或 `gateway.create_session(user_id, channel, metadata?)`
- **会话查询**：`GET /api/sessions/{session_id}` 或 `gateway.get_session(session_id)`
- **会话更新**：`PUT /api/sessions/{session_id}` 或 `gateway.update_session(session_id, updates)`（如更新元数据、标记结束）
- **历史查询**：`GET /api/sessions/{session_id}/history` 或 `gateway.get_history(session_id, limit?)`

### 3. 接口设计原则

- **RESTful 或 RPC**：根据团队习惯选择；Gateway 内部可用 RPC（如 gRPC）与 Runtime 通信，对外暴露 REST 或 WebSocket。
- **流式支持**：若 Runtime 支持流式响应，Gateway 应透传流式能力（如 WebSocket、SSE）。
- **错误处理**：Gateway 应统一处理错误（路由失败、Runtime 不可用、超时），返回统一错误格式。

## 五、开发思路

- **先单通道再多通道**：第一版建议只接一种通道（如 CLI 或 Web），把「请求进 → 路由 → Runtime → 响应出」跑通，再加第二种通道。否则多通道 + 格式差异会同时排错，难以定位问题。
- **会话 ID 谁生成**：若通道能带会话标识（如 Web 前端传 `session_id`），可由客户端生成或 Gateway 按「channel + user_id」派生；若不能，Gateway 必须在首条请求时生成并下发给客户端，后续请求必须带上，否则多轮对话会断。
- **Gateway 和 Runtime 是否同进程**：MVP 阶段同进程、函数直调即可，便于打日志和调试；要水平扩展时再拆成多进程/多机，Gateway 通过 RPC 或 HTTP 调 Runtime，此时要注意超时、重试和会话存储共享。
- **接口版本化**：对外 API（如 `/api/chat`）建议带版本（如 `/v1/chat` 或请求头 `X-API-Version: 1`），方便以后改请求/响应结构时做兼容与灰度。
- **错误统一返回**：所有异常（路由失败、Runtime 超时、Runtime 报错）都应收敛为统一错误格式（如 `{ "error": true, "code": "...", "message": "..." }`），并打 trace_id，便于前端展示和运维排查。

## 六、代码示例：Gateway 核心接口

以下代码来自 **`week12/83_code/gateway_runtime_demo.py`**，展示 Gateway 的请求处理与会话管理。

```python
class Gateway:
    def __init__(self, session_manager: SessionManager) -> None:
        self.session_manager = session_manager

    def handle_request(
        self,
        user_id: str,
        channel: str,
        message: str,
        session_id: str | None = None,
    ) -> dict:
        """接收请求 → 获取/创建会话 → 路由决策 → 调用 Runtime → 更新会话 → 返回响应。"""
        if not session_id:
            session = self.session_manager.create_session(user_id, channel)
            session_id = session["id"]
        else:
            session = self.session_manager.get_session(session_id)
            if not session:
                return {"response": "错误：会话不存在或已过期。", "session_id": session_id or "", "error": "session_not_found"}

        agent_id = route(message, session)  # 路由决策
        history = self.session_manager.get_history(session_id)

        response = run_runtime(
            user_input=message,
            context=history,
            session_id=session_id,
            session_manager=self.session_manager,
        )

        self.session_manager.update_session(session_id, {"last_agent": agent_id, "last_message": message})
        return {"response": response, "session_id": session_id, "agent_id": agent_id}
```

会话管理接口示例（SessionManager）：

```python
class SessionManager:
    def create_session(self, user_id: str, channel: str) -> dict:
        session_id = f"{channel}_{user_id}_{uuid.uuid4().hex[:8]}"
        self._sessions[session_id] = {"id": session_id, "user_id": user_id, "channel": channel, ...}
        self._history[session_id] = []
        return self._sessions[session_id]

    def get_session(self, session_id: str) -> dict | None:
        return self._sessions.get(session_id)

    def update_session(self, session_id: str, updates: dict) -> None:
        if session_id in self._sessions:
            self._sessions[session_id].update(updates)

    def get_history(self, session_id: str, limit: int = 20) -> list[dict]:
        return self._history.get(session_id, [])[-limit:]
```

## 七、实战中的 Gateway 实现思路

在 **`week12/83_code/gateway_runtime_demo.py`**（Day 83 实战）中，Gateway 会实现：

- **Gateway 类**：`handle_request(user_id, channel, message, session_id)` → 路由决策 → 调用 Runtime → 更新会话 → 返回响应
- **Router 模块**：`route(request, session)` → 返回目标 Agent 标识（简化版可用规则或 LLM 决策）
- **SessionManager**：管理会话状态（内存或数据库），支持创建、查询、更新
- **与 Runtime 的通信**：Gateway 调用 Runtime 的 `run_runtime(...)`（同进程直调）
