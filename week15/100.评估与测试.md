# 100. 评估与测试

Day 99 讲了监控与可观测性。本节讲**评估与测试**：**Agent 评估指标**（任务完成率、准确性、用户满意度、成本效率）、**测试用例设计**（单元测试、集成测试、端到端测试），以及**A/B 测试**（不同 Agent 策略的对比、路由策略的对比、模型版本的对比）。

## 一、Agent 评估指标：任务完成率、准确性、用户满意度、成本效率

### 1. 任务完成率

- **含义**：用户请求中，**成功完成任务的占比**（如用户问“查天气”，Agent 成功返回天气信息）。
- **计算**：`任务完成率 = 成功完成任务数 / 总请求数`
- **判断标准**：
  - **自动判断**：根据 Agent 返回的状态（如 `status: "success"`）或错误类型（如无错误 = 成功）。
  - **人工判断**：对复杂任务，需要人工标注“是否完成任务”。
- **作用**：评估 Agent 的**可靠性**，识别失败模式。

### 2. 准确性

- **含义**：Agent 返回的结果**是否正确**（如 SQL 是否正确、研究报告是否准确）。
- **计算**：`准确性 = 正确结果数 / 总结果数`
- **判断标准**：
  - **自动判断**：对于有标准答案的任务（如 SQL 查询），对比 Agent 结果与标准答案。
  - **人工判断**：对于开放任务（如研究报告），需要人工评估准确性。
- **作用**：评估 Agent 的**质量**，识别错误模式。

### 3. 用户满意度

- **含义**：用户对 Agent 回复的**满意度评分**（如 1-5 分，或 thumbs up/down）。
- **收集方式**：
  - **显式反馈**：用户点击“满意/不满意”按钮。
  - **隐式反馈**：根据用户行为推断（如用户立即追问 = 不满意，用户结束会话 = 满意）。
- **作用**：评估 Agent 的**用户体验**，识别改进点。

### 4. 成本效率

- **含义**：**单位成本下的任务完成率**（如“每元成本完成的任务数”），或**单位任务的平均成本**。
- **计算**：`成本效率 = 任务完成数 / 总成本` 或 `平均成本 = 总成本 / 任务完成数`
- **作用**：评估 Agent 的**经济性**，优化高成本 Agent。

### 5. 小结表

| 指标         | 含义                     | 计算方式                         |
| ------------ | ------------------------ | -------------------------------- |
| **任务完成率** | 成功完成任务的占比       | 成功数 / 总数                    |
| **准确性**   | 结果正确的占比           | 正确数 / 总数                    |
| **用户满意度** | 用户满意度评分           | 显式反馈或隐式反馈               |
| **成本效率** | 单位成本下的任务完成率   | 任务完成数 / 总成本              |

## 二、测试用例设计：单元测试、集成测试、端到端测试

### 1. 单元测试

- **含义**：测试**单个组件**的功能（如 Router 的路由逻辑、ToolExecutor 的工具执行）。
- **示例**：
  - Router 测试：输入“研究 AI 进展”，应路由到 `deep_research_agent`。
  - ToolExecutor 测试：输入工具名与参数，应返回正确结果。
- **实现**：用 pytest 或 unittest，mock 依赖（如 mock LLM、mock 数据库）。

### 2. 集成测试

- **含义**：测试**多个组件协作**的功能（如 Gateway + Runtime、Runtime + ToolPlugin）。
- **示例**：
  - Gateway + Runtime 测试：用户请求 → Gateway 路由 → Runtime 执行 → 返回结果。
  - Runtime + ToolPlugin 测试：Runtime 调用 ToolPlugin 的工具，工具执行成功。
- **实现**：用 pytest，启动测试环境（如测试数据库、测试 LLM），运行完整流程。

### 3. 端到端测试

- **含义**：测试**完整系统**的功能（如用户通过 CLI 发送请求，系统返回结果）。
- **示例**：
  - DeepResearch 端到端：用户问“研究 AI 进展”，系统返回研究报告。
  - ChatBI 端到端：用户问“查询销售额”，系统返回数据与解释。
- **实现**：用 pytest 或 Playwright，启动完整平台，模拟用户请求，验证结果。

### 4. 测试数据

- **含义**：准备**测试数据集**（如测试问题列表、标准答案、预期结果）。
- **格式**：可以用 JSON 或 YAML 定义测试用例：
  ```yaml
  test_cases:
    - name: "研究问题"
      input: "研究 AI 在医疗的应用"
      expected_agent: "deep_research_agent"
      expected_contains: ["摘要", "主要观点", "参考文献"]
    - name: "BI 查询"
      input: "查询上个月的销售额"
      expected_agent: "chatbi_agent"
      expected_sql_contains: ["SELECT", "SUM", "orders"]
  ```

### 5. 小结表

| 测试类型     | 测试范围                 | 示例                         |
| ------------ | ------------------------ | ---------------------------- |
| **单元测试** | 单个组件                 | Router 路由逻辑、ToolExecutor |
| **集成测试** | 多个组件协作             | Gateway + Runtime、Runtime + ToolPlugin |
| **端到端测试** | 完整系统                 | 用户请求 → 系统返回结果     |

## 三、A/B 测试：不同 Agent 策略的对比、路由策略的对比、模型版本的对比

### 1. A/B 测试框架

- **含义**：将用户请求**随机分配**到不同版本（A 版本、B 版本），对比两个版本的指标（完成率、准确性、满意度、成本）。
- **实现**：
  - **流量分配**：按用户 ID 或请求 ID 的 hash 值分配流量（如 50% A 版本，50% B 版本）。
  - **指标收集**：收集两个版本的指标（完成率、准确性、满意度、成本）。
  - **统计分析**：对比两个版本的指标，判断哪个版本更好。

### 2. Agent 策略对比

- **场景**：对比不同的 Agent 实现策略（如 DeepResearch Agent 的不同研究策略）。
- **示例**：
  - A 版本：研究计划用任务分解，检索用单轮检索。
  - B 版本：研究计划用 LLM 直接生成，检索用多轮检索。
  - **对比指标**：研究报告质量、完成时间、成本。

### 3. 路由策略对比

- **场景**：对比不同的路由策略（如规则路由 vs LLM 决策路由）。
- **示例**：
  - A 版本：规则路由（关键词匹配）。
  - B 版本：LLM 决策路由。
  - **对比指标**：路由准确率、延迟、成本。

### 4. 模型版本对比

- **场景**：对比不同的模型版本（如 GPT-4 vs GPT-3.5、不同 prompt 版本）。
- **示例**：
  - A 版本：GPT-4，prompt v1。
  - B 版本：GPT-3.5，prompt v2。
  - **对比指标**：准确性、延迟、成本。

### 5. 小结表

| 对比类型     | 对比内容                 | 对比指标                     |
| ------------ | ------------------------ | ---------------------------- |
| **Agent 策略** | 不同的 Agent 实现策略   | 质量、完成时间、成本         |
| **路由策略** | 不同的路由策略           | 路由准确率、延迟、成本       |
| **模型版本** | 不同的模型或 prompt      | 准确性、延迟、成本           |

## 四、实战中的实现

在 **`week15/105_code/`** 中已提供完整代码与测试示例：

- **评估指标收集**：`production_platform_demo.py` 的 `MetricsCollector` 已统计请求量、错误数、延迟分位数、成本；可在此基础上增加“任务完成”标记与满意度字段，计算任务完成率与成本效率。
- **测试用例**：`test_production_platform.py` 包含**单元测试**（路由 `route`、Guardrail `_guardrail_sql`、RBAC `check_agent_access`、指标 `MetricsCollector`、限流 `TokenBucketRateLimiter`、缓存 `ResponseCache`、审计 `AuditLog`）与**集成测试**（限流返回 429、无权限访问返回 forbidden）；运行：`pytest week15/105_code/test_production_platform.py -v`。
- **A/B 测试框架**：可在 Gateway 中按 `user_id` 或 `session_id` hash 做流量分组，将 `agent_id` 或模型版本写入指标标签，再结合 `MetricsCollector.snapshot()` 做对比分析。
