# 103. 部署与运维

Day 102 讲了性能优化。本节讲**部署与运维**：**容器化部署**（Docker、Docker Compose、Kubernetes）、**配置管理**（环境变量、配置文件、密钥管理），以及**健康检查与回滚策略**（健康检查端点、自动重启、版本回滚）。

## 一、容器化部署：Docker、Docker Compose、Kubernetes

### 1. Docker

- **含义**：将应用**打包成 Docker 镜像**，包含代码、依赖、运行时环境。
- **Dockerfile**：
  
  ```dockerfile
  FROM python:3.12-slim
  WORKDIR /app
  COPY requirements.txt .
  RUN pip install -r requirements.txt
  COPY . .
  CMD ["python", "main.py"]
  ```
- **构建与运行**：
  
  ```bash
  docker build -t agent-platform .
  docker run -p 8000:8000 agent-platform
  ```

### 2. Docker Compose

- **含义**：用 Docker Compose **编排多个容器**（如 Gateway、Runtime、数据库、Redis）。
- **docker-compose.yml**：
  
  ```yaml
  version: '3'
  services:
    gateway:
      build: .
      ports:
        - "8000:8000"
      environment:
        - DATABASE_URL=postgresql://db:5432/agent
      depends_on:
        - db
        - redis
    db:
      image: postgres:15
      environment:
        - POSTGRES_DB=agent
    redis:
      image: redis:7
  ```
- **运行**：`docker-compose up`

### 3. Kubernetes

- **含义**：用 Kubernetes **管理容器集群**（如 Gateway、Runtime 的多个副本、自动扩缩容、负载均衡）。
- **部署文件**：
  - **Deployment**：定义应用部署（副本数、镜像、资源限制）。
  - **Service**：定义服务暴露（负载均衡、服务发现）。
  - **ConfigMap**：定义配置（环境变量、配置文件）。
  - **Secret**：定义密钥（API key、数据库密码）。
- **作用**：生产环境的容器编排，支持高可用、自动扩缩容、滚动更新。

### 4. 小结表

| 方式                 | 适用场景       | 特点           |
| ------------------ | ---------- | ------------ |
| **Docker**         | 单机部署、开发环境  | 简单、快速        |
| **Docker Compose** | 多容器编排、测试环境 | 简单、本地开发      |
| **Kubernetes**     | 生产环境、集群部署  | 复杂、高可用、自动扩缩容 |

## 二、配置管理：环境变量、配置文件、密钥管理

### 1. 环境变量

- **含义**：将配置（如数据库 URL、API key、日志级别）存储在**环境变量**中，不同环境（开发、测试、生产）使用不同的环境变量。
- **方式**：
  - **.env 文件**：开发环境用 `.env` 文件（不提交到代码仓库）。
  - **系统环境变量**：生产环境用系统环境变量或容器环境变量。
- **读取**：代码用 `os.getenv("DATABASE_URL")` 或 `python-dotenv` 读取环境变量。

### 2. 配置文件

- **含义**：将配置存储在**配置文件**中（如 YAML、JSON、TOML），不同环境使用不同的配置文件。
- **方式**：
  - **config.yaml**：开发环境用 `config.dev.yaml`，生产环境用 `config.prod.yaml`。
  - **配置中心**：生产环境用配置中心（如 Consul、etcd），动态加载配置。
- **读取**：代码用 `yaml.load()` 或 `json.load()` 读取配置文件。

### 3. 密钥管理

- **含义**：密钥（API key、数据库密码）需要**安全存储**，不能明文存储在配置文件或代码中。
- **方式**：
  - **环境变量**：密钥存储在环境变量中（如 `OPENAI_API_KEY`）。
  - **密钥管理服务**：使用专门的密钥管理服务（如 AWS Secrets Manager、HashiCorp Vault）。
  - **Kubernetes Secret**：Kubernetes 中用 Secret 存储密钥，挂载到容器。

### 4. 小结表

| 方式         | 适用场景     | 特点       |
| ---------- | -------- | -------- |
| **环境变量**   | 简单配置、密钥  | 简单、安全    |
| **配置文件**   | 复杂配置、多环境 | 灵活、可版本控制 |
| **密钥管理服务** | 生产环境密钥   | 安全、支持轮换  |

## 三、健康检查与回滚策略：健康检查端点、自动重启、版本回滚

### 1. 健康检查端点

- **含义**：应用提供**健康检查端点**（如 `/health`），返回应用状态（健康/不健康）。
- **检查项**：
  - **基础检查**：应用是否启动、端口是否监听。
  - **依赖检查**：数据库是否连接、Redis 是否连接、LLM API 是否可用。
- **实现**：
  
  ```python
  @app.get("/health")
  def health_check():
      # 检查数据库
      if not check_database():
          return {"status": "unhealthy", "reason": "database"}, 503
      # 检查 Redis
      if not check_redis():
          return {"status": "unhealthy", "reason": "redis"}, 503
      return {"status": "healthy"}, 200
  ```

### 2. 自动重启

- **含义**：当应用**不健康**时（如健康检查失败、进程崩溃），自动重启应用。
- **实现**：
  - **Docker**：用 `restart: always` 或 `restart: unless-stopped`。
  - **Kubernetes**：用 `livenessProbe` 和 `restartPolicy: Always`，Kubernetes 自动重启不健康的 Pod。
  - **进程管理器**：用 systemd、supervisor、PM2 等进程管理器，自动重启崩溃的进程。

### 3. 版本回滚

- **含义**：当新版本**出现问题**时（如错误率上升、性能下降），快速回滚到旧版本。
- **实现**：
  - **Docker**：保留旧版本镜像，回滚时切换到旧镜像。
  - **Kubernetes**：用 `kubectl rollout undo` 回滚到上一个版本，或指定版本回滚。
  - **蓝绿部署**：新版本部署到“绿环境”，验证通过后切换流量，有问题则切换回“蓝环境”。

### 4. 小结表

| 内容         | 含义            | 实现方式                                    |
| ---------- | ------------- | --------------------------------------- |
| **健康检查端点** | 应用提供健康检查接口    | `/health` 端点，检查应用与依赖状态                  |
| **自动重启**   | 不健康时自动重启      | Docker restart、Kubernetes livenessProbe |
| **版本回滚**   | 新版本有问题时回滚到旧版本 | 保留旧版本、Kubernetes rollout undo           |
