# 62. 实战：为 Agent 加入反思节点

Day 61 明确了反思与上下文、记忆的边界。本节动手**为 Agent 加入反思节点**：实现反思独立模块（输入输出接口与调用时机）、**可配置触发条件**（如失败次数、超时阈值），以及“继续 / 调整 / 停止”三类输出在主流程中的分支处理。

环境要求：与 Week 8 的 Agent 示例一致（`langchain-core`、`langchain-openai`、`python-dotenv`）；用标准库 `json` 解析反思的结构化输出。完整可运行代码见 **`week9/62_code/agent_with_reflection_demo.py`**。

## 一、反思模块的接口与调用时机

### 1. 输入输出接口

- **输入**：当前状态（目标摘要、当前步数、最大步数）、近期执行历史（最近 N 步的意图、工具、结果摘要）、错误信息（若因失败/异常触发）、可选上下文片段（用户请求摘要）。
- **输出**：结构化结论，例如：
  - `decision`: `"continue"` | `"adjust"` | `"stop"`
  - `reason`: str（简短原因）
  - `suggestion`: str | None（当 decision 为 adjust 时的建议）
  - `stop_type`: `"done"` | `"failed"` | `"human_required"` | None（当 decision 为 stop 时可选）

实现方式：用单独的一个 LLM 调用（或带 JSON mode / 结构化输出的调用），prompt 中明确要求按上述字段输出，解析后返回给主循环。

### 2. 调用时机（与主循环的衔接）

- 在主循环的 **while** 中：每轮“执行完工具、得到 ToolMessage”之后，**先判断是否满足反思触发条件**；若满足，则**先调用反思模块**，再根据 `decision` 分支：
  - `continue` → 把反思结果可选用一句话注入 messages，继续下一轮模型推理。
  - `adjust` → 把 `suggestion` 注入 messages（如 System 或一条 Assistant/User 消息），再继续下一轮推理（或先更新计划再继续）。
  - `stop` → 跳出循环，返回当前结果或转 HITL，并记录 `reason` 与 `stop_type`。

这样反思是**独立的一步**，不改变主循环的“推理 → 工具 → 观察”结构，只在关键点插入“先反思再决定是否继续”。

## 二、可配置触发条件（如失败次数、超时阈值）

### 1. 配置项示例

- **失败触发**：`reflect_on_failure: true`；可选 `max_failures_before_reflect: 1`（连续失败几次后触发，默认 1）。
- **超时触发**：`reflect_on_timeout: true`；`step_timeout_seconds` 或 `total_timeout_seconds`。
- **每 N 步触发**：`reflect_every_n_steps: int | None`（例如 5 表示每 5 步反思一次，None 表示不启用）。
- **开关**：`reflection_enabled: true/false`，便于 A/B 或关闭反思做对比。

### 2. 触发逻辑（伪代码）

在每步执行完工具后：

1. 若 `!reflection_enabled` → 不反思，直接进入下一轮推理。
2. 若本步失败且 `reflect_on_failure` 且（连续失败次数 ≥ `max_failures_before_reflect`）→ 触发反思。
3. 若本步或总时长超时且 `reflect_on_timeout` → 触发反思。
4. 若 `reflect_every_n_steps` 非空且（当前步数 % N == 0）→ 触发反思。
5. 若触发，调用反思模块，根据返回的 `decision` 分支；否则直接进入下一轮推理。

这样“何时反思”完全由配置驱动，便于在不同场景下调优。

## 三、明确“继续 / 调整 / 停止”在主流程中的分支处理

### 1. continue

- 主循环：可选在 messages 中追加一条简短说明（如“经反思，上一步结果可信，继续执行”），然后 `continue` 到下一轮 `invoke` 模型。
- 无需修改计划或工具列表。

### 2. adjust

- 主循环：将 `suggestion` 注入上下文。例如追加一条 User 或 System 消息：“反思建议：…（suggestion）请根据此建议决定下一步。” 然后 `continue` 到下一轮 `invoke`，由模型根据建议决定下一动作为何。
- 若使用显式计划（Plan-and-Execute），可在此处用 suggestion 更新后续步骤再继续。
- 可选：对“重试”类建议做特殊处理（如重试上一次 tool_call 一次，并设重试上限）。

### 3. stop

- 主循环：`break` 出 while，不再调用模型与工具。
- 根据 `stop_type`：
  - `done`：返回当前已有的结果或“任务已完成”的说明。
  - `failed`：返回“任务未完成”及 `reason`，便于用户或上游处理。
  - `human_required`：将当前状态、历史与 reason 整理后交给 HITL 流程（Week 11 会详述）；本示例可先打印或返回“需人工介入”的标记。
- 日志：记录 `decision`、`reason`、`stop_type` 与当前步数，便于观测与排查。

### 4. 小结表

| 反思输出         | 主流程动作                            |
| ------------ | -------------------------------- |
| **continue** | 可选注入一句反思说明，继续下一轮推理与工具执行          |
| **adjust**   | 将 suggestion 注入上下文（或更新计划），再继续下一轮 |
| **stop**     | 跳出循环；按 stop_type 返回结果或转人工，并写日志   |
