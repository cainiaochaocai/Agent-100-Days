# 58. 什么是反思模式

Day 57 说明了没有反思的 Agent 容易重复错误、放大错误，并提到人类“复盘”对设计的启发。本节厘清**反思模式的定义与在 Agent 中的角色**、**反思与推理的区别**（何时“再想一遍”而非“继续推一步”），以及**反思在循环中的位置**（执行前 / 执行后 / 异常时）。

## 一、反思模式的定义与在 Agent 中的角色

### 1. 定义

- **反思（Reflection）**：在 Agent 执行过程中，**暂停“继续执行”**，用一次或多次**元级推理**对当前状态、近期行为或结果进行审视，并输出**是否继续、是否调整、是否停止**以及理由或修正建议。
- **反思模式**：把上述“反思”固化为 Agent 架构中的**一类固定步骤**（反思节点），在满足触发条件时执行，其输出用于驱动主循环的分支（继续 / 调整计划 / 重试 / 停止 / 交给人）。

### 2. 在 Agent 中的角色

- **纠错与止损**：在错误或异常出现时，通过反思决定“重试、换策略还是停止”，避免重复错误与错误放大。
- **策略切换**：当检测到“当前路径可能不对”时，反思可输出“调整”建议（如换工具、换分解方式），由主循环据此更新计划再执行。
- **边界与兜底**：当反思结论为“停止”或“需人工介入”时，Agent 不再继续自主执行，而是返回当前状态或转交给人，对应 Day 53 的“可观测、可纠错”以及后续 HITL 的铺垫。

### 3. 小结表

| 概念       | 含义                              |
| -------- | ------------------------------- |
| **反思**   | 对当前状态与行为的元级审视，输出继续/调整/停止及理由或建议。 |
| **反思模式** | 将反思固化为可触发、可配置的节点，其输出驱动主循环分支。    |
| **角色**   | 纠错与止损、策略切换、边界与兜底（停止或交给人）。       |

## 二、反思与推理的区别：何时“再想一遍”而非“继续推一步”

### 1. 主循环中的“推理”

- **做什么**：根据当前上下文（目标、历史、工具结果）**决定下一步动作**：调用哪个工具、传什么参数，或结束并回复用户。
- **输出**：通常是 **Action**（tool_calls 或 final answer），直接驱动执行或结束。
- **特点**：**往前推**——“在现有信息下，下一步做什么”。

### 2. 反思中的“推理”

- **做什么**：根据当前状态与近期历史，**评价“刚才发生了什么、当前路径是否合理、要不要改或停”**，不直接产出“下一步调哪个工具”，而是产出**元级结论**：继续 / 调整 / 停止，以及理由或修正建议。
- **输出**：**决策类型 + 理由/建议**，供主循环做分支判断（例如：若为“调整”，则用建议更新计划再执行；若为“停止”，则终止或交给人）。
- **特点**：**往回看 + 判断**——“再想一遍：我们是否该继续这样下去”。

### 3. 何时用“再想一遍”、何时“继续推一步”

- **继续推一步**：当前无异常、结果符合预期、步数未超限时，主循环正常“推理 → 行动 → 观察 → 再推理”即可。
- **再想一遍**：当**触发条件**满足时（如失败、超时、置信度低、或定期每 N 步），**先进入反思节点**，再根据反思结论决定是继续推、调整后推、还是停止。这样“反思”与“执行”在时间上分离，避免把反思和主推理混在一团、难以控制和观测。

### 4. 对比表

| 维度     | 主循环推理                     | 反思               |
| ------ | ------------------------- | ---------------- |
| **目标** | 下一步做什么（Action）            | 当前是否该继续/调整/停止    |
| **输出** | tool_calls 或 final answer | 继续/调整/停止 + 理由或建议 |
| **方向** | 往前推                       | 往回看 + 元级判断       |
| **触发** | 每轮都执行                     | 满足条件时执行（可配置）     |

## 三、反思在循环中的位置：执行前 / 执行后 / 异常时

### 1. 执行后反思（最常见）

- **时机**：某一步（或某一小段）执行完后，在“把结果交给主推理继续推”之前，先走反思节点。
- **输入**：上一步（或几步）的意图、行动、工具结果、当前目标与状态。
- **用途**：判断“上一步是否成功、结果是否可信、要不要重试/换策略/停止”，再决定主循环是继续、调整还是终止。对应 Day 57 的“事中暂停”。

### 2. 执行前反思（可选）

- **时机**：在**执行高风险或不可逆动作之前**（如发邮件、下单、删数据），先走反思节点。
- **输入**：即将执行的动作、参数、当前上下文。
- **用途**：做“二次确认”或“最后一次检查”，输出继续执行或取消/交给人。可与 HITL 结合（人审后再执行）。

### 3. 异常时反思

- **时机**：当**异常发生**时（工具报错、超时、格式异常、或业务规则判定失败）触发反思。
- **输入**：错误信息、当前状态、近期步骤。
- **用途**：解释“为什么异常、是否可重试、是否需调整策略或停止”，避免主循环在未理解错误的情况下盲目重试或继续。

### 4. 小结

| 位置      | 典型触发         | 主要用途              |
| ------- | ------------ | ----------------- |
| **执行后** | 每步后 / 每 N 步后 | 判断是否继续、调整或停止，纠错止损 |
| **执行前** | 高风险动作前       | 二次确认、可结合 HITL     |
| **异常时** | 工具/业务报错、超时等  | 理解异常、决定重试/调整/停止   |
