# 59. 反思触发机制

Day 58 明确了反思在循环中的位置（执行前 / 执行后 / 异常时）。本节具体讲**常见触发条件**、**按步骤触发与按结果触发的取舍**，以及**触发频率与成本**——如何避免“反思泛滥”或“从不反思”。

## 一、常见触发条件：失败、超时、置信度低、人工标记等

### 1. 失败触发

- **含义**：某一步工具调用或业务校验**明确失败**时（如 API 返回错误码、工具抛出异常、业务规则判定不通过），在进入下一轮主推理前先触发反思。
- **输入**：错误信息、失败步骤、当前目标与上下文片段。
- **目的**：让反思模块判断“是重试、换参数/换工具、还是停止/交给人”，避免主循环盲目重复同一失败操作。

### 2. 超时触发

- **含义**：单步执行时间或累计执行时间**超过阈值**时触发反思。
- **目的**：防止卡在某一工具或某一策略上无限等待；反思可输出“调整策略或停止”，由主循环执行超时后的分支（如降级、跳过该步、或返回“任务未在限定时间内完成”）。

### 3. 置信度低触发

- **含义**：当模型输出中带有“不确定”信号（如明确说“我不确定”“可能不对”）或**置信度分数低于某阈值**（若使用带置信度的接口）时触发反思。
- **目的**：在“模型自己都不太有把握”时，主动做一次元级检查，决定是否继续、补充信息还是交给人。

### 4. 人工标记触发

- **含义**：人在 HITL 或事后标注中标记“这一步有问题”“需要复盘”时，在下一轮或下次类似场景前触发反思（或把该标记作为反思的输入）。
- **目的**：把人类反馈纳入“何时该反思”的条件，用于改进策略或积累案例。

### 5. 周期性 / 每 N 步触发

- **含义**：不依赖失败或异常，而是**每执行 N 步**（或每完成一个子目标）触发一次反思。
- **目的**：在长任务中定期“踩一脚刹车”，检查当前路径是否仍合理、资源是否超限，避免一路走到黑。

### 6. 小结表

| 触发条件      | 典型场景         | 反思要回答的问题           |
| --------- | ------------ | ------------------ |
| **失败**    | 工具报错、业务校验不通过 | 重试 / 换策略 / 停止？     |
| **超时**    | 单步或总时长超限     | 是否调整策略或终止？         |
| **置信度低**  | 模型表达不确定      | 是否继续 / 补充信息 / 交给人？ |
| **人工标记**  | 人标注“需复盘”     | 如何根据反馈调整行为？        |
| **每 N 步** | 长任务、多子目标     | 当前路径是否仍合理、是否继续？    |

## 二、按步骤触发 vs 按结果触发的取舍

### 1. 按步骤触发

- **含义**：与“执行了多少步”或“是否到达某类步骤”绑定，例如“每 3 步反思一次”“每次调用写文件前反思一次”。
- **优点**：规则清晰、易实现、行为可预测；适合对**执行节奏**有要求的场景（如定期自检）。
- **缺点**：可能与“是否真的需要反思”脱节：步数到了就反思，可能没必要；真正需要反思的那一步若不在触发点上，可能漏掉。

### 2. 按结果触发

- **含义**：与**执行结果**绑定，例如“某步失败时”“某步返回为空时”“某步耗时超过阈值时”才触发反思。
- **优点**：反思发生在“有问题”的时候，更有针对性，成本通常更低（不需要在一切正常时也反思）。
- **缺点**：依赖对“结果”的判定（什么是失败、什么是异常），若判定不全或滞后，可能该反思时未触发；实现上需要明确的错误/异常接口或业务规则。

### 3. 取舍建议

- **以按结果为主**：失败、超时、置信度低、人工标记等都属于“结果驱动”，优先配置这些，使反思用在“需要纠错或决策”的时刻。
- **以按步骤为辅**：在长任务或高风险流程中，**叠加**“每 N 步”或“高风险动作前”的步骤型触发，作为兜底，避免长时间不反思导致错误累积。
- **可配置**：两种方式都做成可配置（开关、阈值、步数 N），便于在不同场景下调优。

## 三、触发频率与成本：避免“反思泛滥”或“从不反思”

### 1. 反思泛滥

- **现象**：反思触发过于频繁（如每步都反思），导致延迟与 token 成本明显上升，且反思结论可能重复、噪音大。
- **应对**：提高触发门槛（如仅失败/超时/置信度低时触发）；若用“每 N 步”，则把 N 设大一些；或对“同一类问题”做去重（例如同一工具连续失败只反思一次，后续直接走重试上限或停止）。

### 2. 从不反思

- **现象**：触发条件过严或未配置，导致几乎从不进入反思节点，Agent 行为退化为“单向执行”，重复错误与错误放大无法被纠正。
- **应对**：至少保留**失败触发**（工具/业务失败时反思）；长任务中建议保留**每 N 步**或**超时**触发作为保底。

### 3. 成本与收益权衡

- **成本**：每次反思多 1 次（或多次）LLM 调用、更多 token（历史与反思 prompt）、以及一轮延迟。
- **收益**：减少无效重试、避免错误放大、在关键点做出“调整或停止”的决策，提升成功率和可控性。
- **实践**：先用“按结果触发”（失败、超时）保证必要时的反思，再根据延迟与成本决定是否加“每 N 步”以及 N 的取值。
