# 61. 反思与上下文

Day 60 设计了反思的输入输出以及如何反馈到主循环。本节讨论**哪些反思结果可以进入记忆**（经验、教训、偏好）、**哪些只能作为一次性判断**（当轮决策，不沉淀），以及**为什么反思结论不能直接当事实**（避免“自我强化谬误”）。

## 一、哪些反思结果可以进入记忆（经验、教训、偏好）

### 1. 可沉淀为记忆的类型

- **经验（experience）**：某类任务或某类工具在什么条件下成功/失败、何种参数或顺序更有效。例如“查订单时先验用户身份再调订单接口成功率更高”。这类反思结论**可写入长期记忆**（如 Week 7 的记忆系统），在后续类似任务中作为参考，减少重复试错。
- **教训（lesson）**：某次失败的原因与修正方式。例如“工具 A 在该场景下常超时，应优先用工具 B 或设更短超时”。可摘要后存入记忆，下次遇到类似场景时检索出来，提示模型或反思模块“曾有类似教训”。
- **偏好（preference）**：用户或业务在“反思后选择”中体现的偏好。例如用户多次在“调整 vs 停止”中选择“停止并交给我”，可记为“该用户/该任务更倾向人工兜底”。用于后续在相似情境下优先采用相同策略。

### 2. 写入记忆的时机与形式

- **时机**：在反思节点输出“调整”或“停止”且**本轮任务告一段落**后（例如子任务结束、或最终返回前），将需要沉淀的结论交给记忆系统写入，而不是在反思的当轮立刻写（避免同一轮内多次写、或尚未验证就写）。
- **形式**：以**摘要**形式写入（谁、什么情境、什么结论/教训/偏好），便于后续检索与注入上下文；可带时间戳与任务/会话标识，方便按任务或用户过滤。

### 3. 小结

| 类型     | 内容示例           | 用途          |
| ------ | -------------- | ----------- |
| **经验** | 某类操作在什么条件下更有效  | 后续类似任务优先采用  |
| **教训** | 某次失败原因与修正方式    | 避免重复同类错误    |
| **偏好** | 用户/业务在反思后的选择倾向 | 相似情境下对齐用户期望 |

## 二、哪些只能作为一次性判断（当轮决策，不沉淀）

### 1. 仅当轮有效的结论

- **当前步的“继续”**：例如“上一步结果可信，继续执行”。只对**本轮回溯**有效，不构成可复用的经验，无需写入记忆。
- **当前步的“调整”建议**：例如“建议改用工具 B”“建议重试一次”。用于**本轮回调主循环**即可，除非在任务结束后抽象为“某类场景下用 B 更好”再写入记忆。
- **当前步的“停止”原因**：例如“因超时停止”“因用户取消停止”。可用于日志与监控，若未抽象为通用教训，不必写入长期记忆（否则容易积累大量琐碎条目）。

### 2. 不沉淀的原因

- **避免记忆膨胀**：若每轮反思都写记忆，会很快塞满且噪音大，检索质量下降。
- **避免过度泛化**：单次“这次我们选停止”不一定代表“以后类似情况都该停止”，需要多次或显式总结后再沉淀。
- **职责分离**：反思的**直接职责**是驱动当轮分支（继续/调整/停止）；“是否写入记忆”应是**事后筛选与摘要**的步骤，而不是默认每轮都写。

### 3. 小结

| 类型           | 是否写入记忆 | 说明              |
| ------------ | ------ | --------------- |
| **当轮继续**     | 否      | 仅驱动本轮回溯，无通用价值   |
| **当轮调整建议**   | 一般否    | 先用于本轮回调；可事后抽象再写 |
| **当轮停止原因**   | 视情况    | 可记日志；通用教训可摘要后写  |
| **经验/教训/偏好** | 是      | 经筛选与摘要后写入，供后续检索 |

## 三、为什么反思结论不能直接当事实：避免“自我强化谬误”

### 1. 反思结论的性质

- **反思输出**是模型在**当前上下文下**的**元级判断**（“该继续/调整/停止”及理由），而不是对客观世界的**事实陈述**。它可能受限于：
  - 当前可见的信息不完整或带噪；
  - 模型本身的偏差（如过度乐观或过度保守）；
  - 单次推理错误（如误判“可继续”实则应停止）。

### 2. 若把反思结论直接当事实会怎样

- **自我强化谬误**：例如反思说“上一步失败是因为参数格式错误”，若把这句话**不加区分地当作事实**写入记忆或强注入后续上下文，后续模型会**默认相信**“那次失败是参数问题”，可能忽略其他原因（如权限、限流、业务规则），导致错误归因被固化。
- **错误传播**：错误的反思结论一旦被当事实使用，会像 Day 57 的“错误放大”一样，影响后续多步决策。
- **混淆“建议”与“事实”**：反思的 suggestion 是“建议换工具 B”，若被当成“工具 A 不可用”的硬事实，可能在未来本应使用工具 A 的场景也被禁用。

### 3. 正确用法

- **当轮**：反思的 **decision** 直接驱动主循环分支（继续/调整/停止）；**reason / suggestion** 可作为**提示信息**注入下一轮上下文（如“反思认为应换工具 B，请考虑”），但**不声明为不可辩驳的事实**，允许主推理在充足信息下做出不同选择。
- **写入记忆时**：若要把反思结论沉淀为经验或教训，应用**摘要与限定**表述，例如“在情境 X 下，曾因 Y 失败并采用 Z 修正”，而不是“Y 是唯一原因”或“永远都该 Z”。检索出来时也应以“历史参考”的形式呈现，而不是“当前事实”。

### 4. 小结

| 做法                | 风险          | 建议                    |
| ----------------- | ----------- | --------------------- |
| 反思结论直接当事实写入记忆或强约束 | 自我强化谬误、错误传播 | 不直接当事实；当轮仅作决策与建议      |
| 反思建议作为提示注入上下文     | 可接受         | 用“反思认为…”等表述，保留主推理判断空间 |
| 沉淀时用限定与摘要         | 可接受         | “在 X 情境下曾…”而非绝对断言     |
