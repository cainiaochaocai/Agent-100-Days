# 71. 为什么 Agent 系统一定需要人

Week 8–10 我们学了 Agent 的组成、失败模式、反思与任务分解：Agent 可以多步推理、调用工具、分解目标并执行。但**完全无人参与的自动系统**在真实业务中必然遇到“不可判定”的区间，并带来误判、越权与无法兜底等问题。本节说明**为什么自动化一定会遇到不可判定区间**、**模型与 Agent 的责任边界**，以及**全自动系统的三种必然失败**。

## 一、为什么自动化一定会遇到“不可判定区间”：模糊边界、价值判断、合规与责任

### 1. 模糊边界

- 很多决策依赖**语境、常识或未写明的规则**，无法被完整形式化。例如：“用户说‘取消吧’是指取消当前操作、当前订单还是整个会话？”；“这条信息算不算敏感，该不该脱敏后再用？”
- 模型可能在多数情况下猜对，但**边界 case** 上会错；系统若全自动执行，一旦踩到边界就会误操作。

### 2. 价值判断

- **该不该做**、**做到什么程度**往往涉及价值与偏好：例如是否允许“代用户发一封语气比较强硬的邮件”、是否在未明确同意时使用某类数据。这类判断**不适合**完全交给模型，因为责任与后果由人或组织承担。
- 自动化无法替代“谁来决定我们的底线”。

### 3. 合规与责任

- 金融、医疗、隐私等场景有**合规要求**：某些操作必须由具备资质的人确认或签字；出错时**责任主体**必须是人或机构，不能是“模型自己”。
- 若系统全自动且无人的参与点，合规审计会无法通过，出事后责任也难以界定。

### 4. 小结

| 维度           | 不可判定性的体现                         |
| -------------- | ---------------------------------------- |
| **模糊边界**   | 语境、隐含规则无法穷举，边界 case 易误判 |
| **价值判断**   | 该不该做、做到哪一步需人定底线           |
| **合规与责任** | 必须有人参与确认，责任主体须为人或机构   |

## 二、模型与 Agent 的责任边界：什么适合交给模型、什么必须保留给人

### 1. 适合交给模型的

- **信息获取与整理**：查数据、摘要、分类、按规则筛选。
- **建议与草稿**：生成方案、写初稿、列出选项，供人最终选择或修改。
- **低风险、可逆或可校验的动作**：在明确规则下的查询、展示、提醒；若出错影响有限且可追溯。

### 2. 必须保留给人的

- **最终决策**：涉及钱、权限、对外承诺、法律效力的操作（如下单、发邮件、审批通过）。
- **边界与例外**：模型不确定时、或触发业务规则（如金额超阈值、敏感操作）时，应交给人判断。
- **责任归属**：凡需“由人负责”的环节，必须在设计上让人参与（审批、确认、接管），而不是事后补救。

### 3. 责任边界在设计上的体现

- 用 **HITL** 在关键节点插入“人参与”：执行前审批、执行后修正、或异常时接管。这样“模型建议、人决策”的边界清晰，责任可追溯。

## 三、全自动系统的三种必然失败：不可判定时的误判、越权与合规、无法兜底

### 1. 不可判定时的误判

- 当问题落在**不可判定区间**（模糊、价值、合规）时，全自动系统只能“猜”。猜错就会误执行：误发邮件、误删数据、误承诺等。
- **缓解**：在这些区间**不自动执行**，而是触发 HITL，由人做最终决定。

### 2. 越权与合规

- 全自动执行可能**越过**业务规定的权限（如未经审批就执行高金额操作），或违反“必须人工确认”的合规要求。
- **缓解**：高风险动作前强制 HITL（审批型）；合规要求写入触发条件，触发即暂停并交给人。

### 3. 无法兜底

- 当 Agent 连续失败、陷入循环或遇到未预料情况时，若没有“人接管”的出口，系统只能卡死或一直错下去，用户也无法介入。
- **缓解**：设计接管型 HITL（如反思输出 stop_type=human_required 时转交给人），让人可以终止、修正或接手后续操作。

### 4. 小结表

| 失败类型      | 表现                     | 设计上的应对                  |
| ------------- | ------------------------ | ----------------------------- |
| **误判**      | 不可判定区间内猜错并执行 | 该区间触发 HITL，由人决策     |
| **越权/合规** | 未经允许执行敏感操作     | 高风险前审批型 HITL、合规触发 |
| **无法兜底**  | 失败或异常时无人可介入   | 接管型 HITL、明确“交给人”出口 |
