# 76. 实战：为 Agent 加入 HITL

Day 75 讲了 HITL 的上下文与信息呈现。本节动手**为 Agent 加入 HITL**：设计“触发 → 暂停 → 呈现信息 → 等待人决策 → 根据决策继续/修正/接管”的流程、**可配置触发条件与三种介入模式的接口**，以及与**现有 Agent 循环、反思节点**的衔接。完整可运行示例见 **`week11/76_code/agent_with_hitl_demo.py`**（审批型）。

## 一、设计“触发 → 暂停 → 呈现信息 → 等待人决策 → 根据决策继续/修正/接管”的流程

### 1. 流程五步

- **触发**：在 Agent 循环中，当“即将执行某工具”或“某步执行后结果异常”或“反思输出需人工”时，满足 HITL 触发条件，进入 HITL 分支。
- **暂停**：不执行该工具（审批型）或暂不继续下一轮（修正/接管型），将控制权交给“等人输入”的逻辑。
- **呈现信息**：按 Day 75 的要求，展示当前意图、待执行动作/参数或待修正结果、风险提示（若适用）。
- **等待人决策**：通过 UI 或命令行等待人输入（如审批：通过/拒绝/修改；修正：提交修正内容；接管：确认接管）。
- **根据决策继续/修正/接管**：审批通过则执行该工具并将结果追加到 messages；拒绝则将拒绝原因写入 ToolMessage，Agent 据此调整或结束。修正型则将修正内容写回后继续；接管型则结束自动循环，由人完成后续。

### 2. 与三种介入模式的对应

- **Approval**：触发在“执行前”，暂停后呈现“将要执行的动作与参数”，人选通过/拒绝/修改；写回后执行或注入拒绝原因。
- **Correction**：触发在“执行后、结果异常时”，呈现“当前结果”供人修改，写回后 Agent 用修正结果继续或重试。
- **Takeover**：触发在“异常或用户请求时”，呈现“当前状态与原因”，人确认接管后结束自动循环（本示例脚本仅实现审批型，修正与接管可在同一框架下扩展）。

## 二、可配置触发条件与三种介入模式的接口（审批通过/拒绝、修正内容、接管确认）

### 1. 可配置触发条件

- **工具级**：为每个工具配置是否 `requires_approval`（或 `requires_hitl`），执行前检查；若为 True 则走审批型 HITL。
- **规则级**：根据参数或业务规则触发（如金额 > N、动作为某敏感列表）；可在“即将执行”的回调里检查规则，满足则触发。
- **反思/异常级**：当 Week 9 反思输出 `stop_type=human_required` 或某步失败且策略为“转人工”时，触发修正型或接管型 HITL。

### 2. 接口形态（本示例为审批型）

- **输入**：当前目标（或意图摘要）、工具名、参数。
- **输出**：人决策 —— `approve`（通过）、`reject` 或 `reject:原因`（拒绝）。脚本中通过 `request_human_approval(goal, tool_name, args)` 实现，内部 `input()` 读用户输入，返回 `"approve"` 或 `"reject:..."`。
- **写回**：通过则调用 `tool_map[name].invoke(args)` 得到结果，追加 ToolMessage；拒绝则追加 ToolMessage 内容为“人工拒绝：原因”，Agent 下一轮会看到该信息并调整回复。

### 3. 修正型与接管型接口（扩展点）

- **修正型**：输入 = 当前结果或待修正文本；输出 = 人提交的修正内容；写回 = 用修正内容替换或注入一条消息，再继续循环。
- **接管型**：输入 = 当前状态与原因；输出 = 人确认“已接管”或“处理结果”；写回 = 可选写回处理结果，并结束 Agent 循环。

## 三、与现有 Agent 循环、反思节点的衔接；可选结合 Week 9 反思的“停止/交给人”分支

### 1. 与 Agent 循环的衔接

- 在 **工具执行前**（或执行后）插入判断：若本步工具在 `TOOLS_REQUIRING_APPROVAL` 中，则先调用 `request_human_approval`，再根据返回值决定是执行工具还是写入拒绝的 ToolMessage。这样不改动“推理 → 工具 → 观察”的主结构，只在工具执行处加一层 HITL 分支。

### 2. 与反思节点的衔接

- Week 9 反思输出 `decision=stop` 且 `stop_type=human_required` 时，可**不直接 return**，而是进入“接管型 HITL”：把当前状态、反思原因呈现给人，等人确认接管或输入处理结果后，再结束或写回。这样“反思认为该交给人”与“真的把人拉进来”打通。

### 3. 脚本实现要点（76_code）

- **`week11/76_code/agent_with_hitl_demo.py`** 中：`TOOLS_REQUIRING_APPROVAL = {"search_order"}`，当 Agent 决定调用 `search_order` 时，先 `request_human_approval(goal, name, args)`，打印意图、动作、参数与风险提示，等待用户输入 `y/n`；`y` 则执行工具并追加 ToolMessage，`n` 则追加“人工拒绝：…”的 ToolMessage，由模型根据拒绝原因给出回复或结束。其他工具（天气、时间）不经过 HITL，直接执行。

### 4. 运行方式

在项目根目录执行：

```bash
python week11/76_code/agent_with_hitl_demo.py
```

输入例如“查一下订单 ORD001 的状态”，在 Agent 决定调用 `search_order` 时会触发审批，根据你输入的 y/n 观察“通过则返回订单信息、拒绝则 Agent 根据拒绝原因回复”。
